# 브랜드 메뉴판 등록 방식 — 브랜드 하나를 어떻게 올리나 (2026-07-28 확정)

> 🔴 **원칙 한 줄: 브랜드 홈페이지가 보여주는 그대로 보여준다.**
> 탭 이름 · 탭 순서 · 탭 안의 진열 순서 · 중복 진열 · 하위 카테고리까지 원본을 지킨다.
>
> 대표 지시(2026-07-28):
> *"우리 입맛대로 카테고리를 설정하면 추후에 데이터 관리가 더 어려울 것 같아서 브랜드별로 탭을 설정하는 게 맞는 것 같아"*
> *"중복되는 부분이 발생, 추천메뉴/치킨 메뉴가 발생하는 건 현재 브랜드에서 그렇게 밀고 있는 거잖아. 업데이트할 때 바뀔 수 있는 거니까"*

## ⛔ 뒤집힌 규칙 — `menu_tab.py` 표준 9개 탭은 **폴백**이다

같은 날 오전에 *"각 브랜드별 탭메뉴 동일하게 적용해"* 로 만든 표준 탭(`치킨/피자/버거/밥·면/…`)은
**원본 카테고리가 없는 브랜드에만** 쓴다. 원본이 들어오면 그 브랜드는 표준 탭을 쓰지 않는다.

표준 탭으로 통일했을 때 실제로 이런 일이 났다 — 되풀이하지 말 것:

| 무엇 | 왜 틀렸나 |
|---|---|
| BBQ `바이젠 500cc` 가 **치킨** 탭 | 원본은 「음료」였다. `_ALIAS` 에 «음료» 키가 없어 못 알아듣고, 마지막 폴백 «치킨집이니 치킨» 이 이겼다 |
| bhc 「사이드」에 피자 5·버거 6·라이스 2 | bhc 홈페이지가 실제로 그렇게 묶어놨다. **원본을 지키면 «오분류» 가 아니다** |
| 스파게티 13건이 **음료** | 이름 규칙 `티\b` 오탐. 원본이 있으면 이름을 볼 일이 없다 |

## 1. 구조 — 셋으로 나뉜다

```
brand_menu_official   메뉴 «사실» 만 — 이름·가격·중량·원산지·알레르기
brand_menu_cat        카테고리 — 이름·경로·순서·상위·숨김
menu_cat_link         메뉴 ↔ 카테고리 N:M + 그 카테고리 안에서의 자리
```

**분류는 `brand_menu_official` 에서 손을 뗐다.** 그 테이블의 `category` 는
원본이 없는 브랜드를 위한 요약·폴백일 뿐이다.

### 왜 나눴나
- **한 메뉴가 여러 카테고리에 걸린다.** bhc 뿌링클은 「치킨」·「BHC시그니처」·「뿌링클유니버스」 세 곳에 있다.
  한 칸에 `치킨 · BHC시그니처 · 뿌링클유니버스` 로 이어붙이고 그걸 다시 쪼개 읽다가 오분류가 났다.
- **순서가 정보다.** `sort_order` 가 없어서 화면이 **비싼 순**(`ORDER BY price DESC`)으로 나갔다.
- **카테고리가 메뉴 행으로 둔갑해 있었다**(BBQ `피자&버거 5,000원`). 카테고리를 따로 들면 대조로 걸러진다.

### 🔴 카테고리 키는 이름이 아니라 **경로**다
bhc 는 「치킨 > 뿌링클」과 「BHC시그니처 > 뿌링클」이 **둘 다** 있다. 이름만으로는 충돌한다.
그래서 `brand_menu_cat.path` (`치킨/뿌링클`)가 식별자이고 `UNIQUE(brand_id, path)` 다.

## 2. 브랜드 하나 = 전용 스크립트 하나

```
scripts/brand_<브랜드>.py   또는   scripts/<브랜드>_api_collect.py
```

⛔ **범용 수집기로 적재하지 않는다.** `brand_menu_list` · `brand_site_collect` · `brand_official_import` ·
`brand_menu_collect` · `brand_list_import` · `app_menu_read` 는 **정찰용**이다.
이것들이 같은 테이블에 마구 쓰면서 **출처 없는 행 113건**과 **문구 쓰레기 101건**이 생겼다
(`새로 나왔어요! 46,000원` · `안주에 제격, 아이들 간식으로 제격 8,500원` · 푸라닭 14개 전부 홍보문구).

### 적재는 공통 뼈대로만

```python
import brand_menu_store as store

c = store.connect(); store.ensure(c)
bid = store.brand_id(c, slug="bhcchicken")

cats = [                                   # 상위를 **먼저**, 그 뒤에 자식
  {"name": "뿌링클유니버스", "ext_id": "74"},
  {"name": "치킨", "parent": "뿌링클유니버스", "ext_id": "75"},   # parent 는 **상위의 경로**
  ...
]
items = [                                  # 홈페이지 나열 순서 그대로
  {"name": "뿌링클", "price": 21000, "weight_raw": ..., "price_source": "official",
   "cats": ["치킨", ("치킨/뿌링클", 2), "BHC시그니처"]},   # (경로, 그 안에서의 자리)
  ...
]
store.replace_brand(c, bid, cats, items, collector="bhc_api_collect")
```

`replace_brand()` 가 대신 지켜주는 것:

- **자기 `brand_id` 밖은 못 건드린다** — 다른 브랜드와 겹칠 수 없다
- **그 브랜드를 통째로 갈아끼운다** — 키가 `(brand_id, name)` 이라 그냥 다시 넣으면 같은 이름만 덮이고
  `새로 나왔어요!` 같은 쓰레기는 **영영 안 지워진다**
- **사람이 확정한 것은 보존한다** — `decided_at` 이 있으면 판매가까지 옛 값을 지킨다.
  확정된 행이 새 수집에 없으면 ⚠️ 로 알린다(수집이 덜 됐다는 신호다)
- `menu_id` · `agreed` · `prev_price` · `price_note` 를 이름으로 물려준다
- **누가 넣었는지 기록한다**(`collector`) — 이상한 값이 보이면 어느 스크립트를 고칠지 바로 나온다
- 사람이 끈 탭(`hidden=1`)은 되살리지 않는다

## 3. 화면은 알아서 따라온다

`gen_preview_html.menu_board()` 가 이 순서로 고른다:

1. `brand_menu_store.board_of()` 에 원본 카테고리가 있으면 → **원본 그대로**(`_board_native`)
2. 없으면 → 기존 표준 탭(`menu_tab`)

**화면 쪽은 브랜드를 추가해도 더 고칠 게 없다.** 수집기가 담기만 하면 그 브랜드부터 원본 탭으로 바뀐다.

- 하위 카테고리가 있으면 탭 아래 칩이 한 겹 더 깔린다 — 맨 앞이 「전체」
- 가격을 아직 못 구한 메뉴는 **이름은 보여주고** 가격 자리에 `가격 확인 중`
  ⚠️ 단 **전용 수집기를 거친 브랜드에만** 그렇게 한다. 범용 수집기가 넣은 2,523행에는
  설명문·카테고리 쓰레기가 섞여 있어 그대로 켜면 58개 브랜드에 한꺼번에 노출된다
- 원가를 낸 메뉴는 **이름 바로 오른쪽에 「원가」 칩**, 판매가는 오른쪽 끝 (★ 는 폐기)

## 4. 수집이 두 단계로 갈린다

| 단계 | 무엇 | 어디서 | 대상 |
|---|---|---|---|
| ① 골격 | **카테고리 + 메뉴명 + 순서** | 브랜드 홈페이지 | 공개 88곳 **전부** (홈페이지 주소가 다 있다) |
| ② 가격 | 판매가 | 홈페이지에 있으면 ①에서 같이 · 없으면 `place_menu_emu.py`(에뮬) | 홈페이지 공개는 15곳뿐 |

**느린 쪽(가격)이 빠른 쪽(골격)을 붙잡지 않게** 나눈 것이다.
지금 «메뉴판 없음» 58곳은 카테고리를 못 얻은 게 아니라 **가격을 못 얻은** 것이다.

## 5. 브랜드 하나 마감 순서

> 🔴 **손으로 쿼리를 짜지 마라.** 아래 네 스크립트가 전부 대신한다 (2026-07-28 신설).
> 브랜드가 달라도 **묻는 것과 하는 일은 늘 같다** — 매번 파이썬을 새로 짜다가 토큰만 태웠다.
>
> ```bash
> python scripts/brand_status.py                     # ① 지금 상태·할 일 (읽기 전용)
> python scripts/brand_menu_import.py <json> --apply # ② 수집 JSON 적재
> python scripts/publish.py --apply                  # ③ 재생성→고아정리→사이트맵→배포→퍼지→확인
> python scripts/brand_delete.py <브랜드> --apply     # ④ 브랜드 삭제(딸린 15개 테이블까지)
> ```
>
> · **전부 미리보기가 기본이다.** `--apply` 를 붙여야만 실제로 움직인다
> · `brand_delete` 는 **원가 낸 메뉴가 있으면 거부**한다 — 사람이 만든 작업물이라 `--force` 를 명시해야 지운다
> · `publish` 는 **한 단계라도 실패하면 즉시 멈춘다** — 생성 실패한 채로 배포하면 사이트가 통째로 404 다
> · `brand_status` 는 **메뉴 수와 가격 수를 둘 다** 본다 — 메뉴 수만 보면 «가격만 채워진 갱신» 을 놓친다

### 옛 방식 (참고 — 이제 `publish.py` 가 한 줄로 한다)

## 5-2. 임포터가 대신 막아주는 것 (2026-07-28 실전에서 하나씩 붙였다)

`brand_menu_import.py` 는 검사만 하지 않는다. **넣기 전에 아래를 자동으로 처리하고 그 사실을 출력한다.**
출력을 눈으로 읽어야 한다 — 조용히 넘어가는 건 하나도 없다.

| 상황 | 어떻게 하나 | 실제 사례 |
|---|---|---|
| **같은 이름에 가격이 여럿** | 두 번째부터 **브랜드 카테고리 이름을 붙여** 구분. 첫 번째는 그대로 둬서 원가 연결이 안 끊긴다 | 피자마루 `페퍼로니 피자` 가 클래식 10,900 / 골드&바이트 15,900 / 퍼스널 4,900 — 키가 `(brand_id,name)` 이라 그냥 넣으면 **UNIQUE 로 죽는다.** 하나만 남기면 나머지 가격이 사라진다 |
| **카테고리가 0개** | 「메뉴」 하나로 묶는다. 탭이 하나면 **탭바가 안 그려지므로** 지어낸 이름이 안 보이고, 순서만 지켜진다 | 60계치킨은 메뉴판이 한 줄로 쭉 이어진다. 카테고리를 안 만들면 표준 탭 폴백으로 떨어져 우리가 「치킨/사이드」를 지어내게 된다 |
| **새 수집에 가격이 없다** | **옛 가격을 지킨다**(`replace_brand`). 「옛 가격을 지킨 행 N개」로 출력 | 맘스터치 골격을 다시 받았더니 가격이 0개였다. 그대로 넣었으면 **129개가 전부 「가격 확인 중」** 이 될 뻔했다 |
| **탭 이름과 같은 메뉴** | **버리지 않고 «확인 필요»로 알린다** | 지코바 「양념치킨」·「소금구이치킨」은 탭 이름이면서 가격·중량이 있는 진짜 메뉴다 |
| **이름에 `/` 가 든 탭** | 최상위 여부는 **`parent` 로만** 판단한다 | 자담치킨 「피자/파스타」 탭이 하위 카테고리로 잘못 잡혔다 |

⛔ **버리는 규칙은 좁게 잡는다.** 넓게 잡아 진짜 메뉴를 죽인 적이 세 번 있다 —
   교촌 `아, 귀한 먹태[홀전용메뉴]`·문베어 맥주 5종(쉼표·길이), 버거킹 긴 세트 이름(길이), 지코바 2종(탭 이름).
   문장은 **끝맺음**(`~니다.`·`~어요!`)으로 판정하고, 길이는 규격(`500ml CAN`)·세트(`+`)가 붙으면 예외다.

## 6. 브랜드별 함정 (실제로 부딪힌 것만)

### bhc — 자체 API (`www.bhc.co.kr/api/v1/web`)
- **순서는 배열 순서가 아니라 `sortSeq`.** 배열대로 쓰면 첫 탭이 「치킨」인데 실제 첫 탭은 **「뿌링클유니버스」** 다
- **하위 카테고리는 `subCateList`** 에 있다
- 🔴 **`/categories/{하위idx}/products` 는 0개를 준다.** 하위별 상품은 **상위 목록**의 각 상품에 붙어 오는
  `cateSortList:[{cateNm, sortKey}]` 로 안다. `sortKey % 10000` 이 그 하위 안에서의 자리다
  (`sortKey` 가 0 인 항목이 몇 개 있어 그때는 나온 순서를 쓴다)
- 판매가 = 본품가 + 옵션(한마리 +1,000 / 순살·콤보·윙 +3,000)

### 피자 — 사이즈가 곧 다른 메뉴다
- `콤비네이션 피자 L` 과 `R` 은 **다른 메뉴**다. 합치면 청년피자 35→20, 59쌀피자 60→43으로 줄어든다
- 사이즈 표기는 **브랜드 말 그대로** — 피자헛 M/L · 파파존스 라지/패밀리 · 반올림 Large/Regular · 도미노 cm
- **「오리지널」은 꼬리표로 뗀다**(2026-07-28). 피자스쿨은 `치즈피자 오리지널`(15,900) / `치즈피자 치즈크러스트`(18,900)
  로 갈리는데 오리지널이 기본이다. ⛔ **「치즈크러스트」는 떼지 않는다** — 떼면 한 메뉴에 둘이 붙어 원가가 부풀려진다
- 피자스쿨 「주요토핑」·피자헛 `rpstDesc` 가 **재료 정본**이다 → `compose_raw`

### 카페 — 앱이 먼저다
- 홈이 **완전 CSR** 인 곳이 많다(설빙은 `urllib` 로 3KB 껍데기만 온다). 크롬으로 파고들지 말고 **앱(APK)** 을 먼저 본다
- 가격이 0개인 게 정상이다 — 스타벅스 321개·메가 224개·빽다방 323개 전부 가격 0으로 들어왔다
- 투썸플레이스는 **IP 차단**을 겪었다. 따로 돌 것

### 그 밖에
- 브랜드 홈페이지에 **가격이 없는 곳이 대부분**이다(49곳 중 공개 15곳). 개수만 보고 성과로 읽지 말 것
- 「0쪽」은 사이트가 막힌 게 아니다 — 헤드리스가 SPA 를 너무 일찍 긁은 것. 브라우저로 열면 그냥 읽힌다
- 목록 페이지를 «가격 줄» 기준으로 자르면 **카테고리 헤더가 통째로 버려진다.** 4,161행 중 295행에만
  원본 카테고리가 남은 이유가 이것이다
