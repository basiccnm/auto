## 2. 가격 구조 — **두 단계다**

상세 페이지 실측 (피양파 15Kg/EA):

| 표기 | 값 | 의미 |
|---|---|---|
| 취소선 | 28,730원 | 정가 |
| **28%** | **20,400원** | **상시 판매가 — 원가 기준으로 쓸 값** |
| 36% | 18,360원 | 쿠폰가 ("최대 할인 상품 쿠폰 적용 시") |

- 36%는 28% 위에 **쿠폰을 한 번 더 얹은** 값이다(할인에 할인). 주말 재고떨이 성격 →
  **원가 기준으로 쓰지 않는다. 28%(상시 판매가)를 쓴다.**
- VAT는 별도 표기됨: `VAT 0원 포함`(면세) / `VAT 2,000원 포함`(과세)

### ✅ 목록에서도 구분된다 (2026-07-24 검색으로 확인)

같은 상품이 **두 줄로** 나오고, 쿠폰 건에만 `쿠폰가`·`쿠폰받기` 텍스트가 붙는다:

```
C461098_1  피양파 (180~230g/개 15Kg/EA)   31,820원  29%  22,590원   ← 상시가
C461098    피양파 (180~230g/개 15Kg/EA)   쿠폰가 쿠폰받기
                                          31,820원  36%  20,330원   ← 쿠폰가
```

**→ `쿠폰가`가 없는 줄만 취하면 상세에 안 들어가고도 상시가를 정확히 뽑는다.**
상시가 쪽 코드에는 `_1` 접미사가 붙는다(같은 상품 두 줄을 구분하려는 앱 내부 규칙으로 보임).

## 3. 상품 1건에서 뽑히는 필드

```
프레시원 조미김가루 (1Kg/EA)     ← 상품명 (브랜드 + 품목 + 용량/단위)
C440360                          ← 상품코드 ★
34,400원 / 36% / 22,000원        ← 정가 / 할인율 / 판매가
VAT 2,000원 포함                 ← 과세 여부 + 세액
원산지 : 국내산                  ← 상세에만
면세 · 상온                      ← 과세구분 · 보관구분
```

**★ 상품코드(`C440360` 형식)가 텍스트로 잡힌다.**
→ 우리 DB 재료와 **1:1 고정 매핑** 가능. 네이버에서 겪던 "어느 상품이 맞나" 문제가 원천 소멸.
→ 이름이 바뀌어도 추적 가능. 재조사 때 검색 안 하고 코드로 바로 감.

## 4. 수집 방법 — UI 덤프가 캡처보다 낫다

```bash
export MSYS_NO_PATHCONV=1          # 없으면 /sdcard/ 를 윈도우 경로로 바꿔버림
ADB="/c/LDPlayer/LDPlayer14/adb.exe"
"$ADB" -s emulator-5554 shell uiautomator dump /sdcard/ui.xml
"$ADB" -s emulator-5554 pull /sdcard/ui.xml ./ui.xml
# text="..." 속성만 뽑으면 끝
```

| 방식 | 1건당 | 250건 | 비고 |
|---|---|---|---|
| 화면캡처 + 이미지 판독 | 4.4초 + 판독 | 40~60분 | 오독 위험, 토큰 많이 씀 |
| **UI 덤프** | **2.2초 / 화면 전체** | **5~8분** | 텍스트 그대로, 오독 0 |

- 덤프 1회 = **화면에 보이는 상품 전부**를 한꺼번에 가져온다 (실측 553개 텍스트 / 308KB)
- 목록은 스크롤하며 덤프만 반복하면 됨
- 실측: **정육 기획전 154건 = 스크롤 24회 / 1분**, 누락 0건

## 5. 검색이 된다 — 이게 정답 경로

목록을 순회할 필요가 없다. **재료명으로 바로 찍는다.**

- 식자재몰 상단 **돋보기**(center 603,78) → 검색창 → 엔터
- 실측: `양파` → **총 81건, 판매량순** 정렬로 나옴
- 1건당 **붙여넣기 → 엔터 → 덤프 ≈ 6초** → 우리 재료 352종이면 **35분 안쪽**

### 🔑 한글 입력 뚫는 법 (이거 없으면 검색 자체가 안 된다)

`adb shell input text "양파"` 는 **실패한다** — ASCII만 되고 한글은
`NullPointerException: Attempt to get length of null array` 를 뱉는다.
`cmd clipboard set-text` 도 이 빌드엔 없다(`No shell command implementation`).
설치된 IME는 `com.android.inputmethod.pinyin` 하나뿐이라 한글 자판도 없다.

**되는 방법 = LDPlayer 창을 앞으로 띄운 뒤 Windows 클립보드에 넣고 붙여넣기.**

```powershell
# 1) LDPlayer(dnplayer) 창을 포그라운드로 — 이걸 안 하면 클립보드가 게스트로 동기화되지 않는다
Add-Type "...SetForegroundWindow..."   # user32.dll
$p = Get-Process dnplayer | ? { $_.MainWindowHandle -ne 0 } | select -First 1
[W]::ShowWindow($p.MainWindowHandle, 9); [W]::SetForegroundWindow($p.MainWindowHandle)
Start-Sleep -Milliseconds 800
Set-Clipboard -Value "양파"
```
```bash
# 2) 검색창 탭 → 붙여넣기(KEYCODE_PASTE=279) → 엔터(66)
"$ADB" -s emulator-5554 shell input tap 400 176
"$ADB" -s emulator-5554 shell input keyevent 279
"$ADB" -s emulator-5554 shell input keyevent 66
```

⚠️ 창을 포그라운드로 안 올리면 **예전 클립보드 값이 그대로 붙는다**(실제로 겪음 —
LDPlayer 설치 명령문이 검색창에 들어갔다). 붙인 뒤 검색창을 잘라 스샷으로 한 번 확인할 것.

## 6. 원산지 — 야채는 건너뛰어도 된다

- 목록에서 **태극기 뱃지 = 국산 / 없으면 수입산**. 단 이건 **이미지라 덤프에 안 잡힌다**
  (`content-desc`에 들어있는 건 상품코드뿐)
- **야채는 거의 국산**이고 수입산은 값이 확 싸다 → **값이 유독 낮은 이상치만** 상세로 확인
- **정육은 반대다.** 수입이 기본이고, **영문 브랜드가 붙으면 수입산**이다
  (`AURORA` 닭다리살, `EXCELBEEF` 소부채살 등 — 대표님 확인).
  → 정육도 상세까지 안 들어가고 **상품명의 브랜드로 1차 판별**할 수 있다.
  애매한 것(한글 브랜드인데 값이 낮은 것 등)만 상세로 확인

## 8. 주요 농산물 시세 (POS 홈 → 꼭 알아야 할 식자재 정보)

**가락도매시장 도매법인 경매가**다. 매일 **02:00 기준** 갱신.

- 주요 농산물 **30종**만 선정
- 토요일 저녁~일요일 새벽·공휴일은 경매가 없어 **최근 7일 내** 자료로 대체
- **등급을 반드시 값과 세트로 저장할 것** — 특(5%) / 상(35%) / 보통(40%) / 하(20%)로
  물량 배분되며, 앱이 보여준 양배추·배추·알배기배추는 전부 "하"였다
- 앱 스스로 "실거래시 참고자료로만" 이라고 명시

**→ 우리 원가에 그대로 쓰면 안 된다.** 대도매 단계 값이라 우리가 살 수 있는 가격이 아니고
30종뿐이라 커버리지도 부족하다. 쓸 데는 **등락률(어제 대비·지난주 대비)** 뿐이다.
게다가 원출처가 가락시장이라 **앱을 긁을 필요 없이 공공데이터에서 직접 받으면 된다.**
