## 1. 화면 구조

```
┌──────┬──────┬──────┬──────┐
│ 메인  │ 메인  │ 가루  │ 야채  │   ← 첫 줄 4칸. 항상 꽉 채운다
└──────┴──────┴──────┴──────┘
        ＋ 집에 있을 만한 것 N가지        ← 접힘. 기본 닫힘
        (야채 → 가루 → 소스 → 상비 순)
📦 세트 구성 표시
2인분에 실제로 들어가는 재료비   6,988원
```

- **첫 줄 4칸** — 메인은 개수와 무관하게 **전부** 보인다(부대찌개는 4칸을 넘긴다).
  남는 자리는 **가루 → 야채 → 소스** 순으로 채운다(사야 할 가능성이 높은 것부터)
- **접힘 안 순서** — 야채 → 가루 → 소스 → **상비**(맨 뒤)
- 🔴 **메인 안에서는 재료비가 큰 것이 앞이다** — 요리의 주인공이 첫 칸에 온다
  (대표 2026-08-03: *"김밥재료세트면 제일 처음에 있어야지"*)
- ⛔ **다른 그룹은 가격순으로 줄 세우지 않는다** — 레시피 순서 그대로.
  *"양파는 1번에 있는데 당근은 8번에 있으면 안됨"*

## 2. 카드 표기 규칙

| 항목 | 규칙 |
|---|---|
| **재료명** | **최대 6글자.** 10글자가 넘어도 6글자에서 자른다. 전체 이름은 `title` 툴팁·복사 버튼에 |
| **사용량** | `90g` · `1개` · `5ml` — DB 값 그대로 |
| **구매 규격** | **위 사용량과 같은 단위 차원**으로 맞춘다 |
| **가격** | 우리가 고른 **쿠팡 상품 가격 그대로** |

### 2-1. 🔴 위아래 단위를 반드시 맞춘다

```
❌  계란   1개  →  15구 900g      «몇 개를 사야 하는지 못 읽는다»
✅  계란   1개  →  15개
❌  참기름 5ml  →  1.8kg          «부피와 무게가 섞였다»
✅  참기름 5ml  →  412ml
```

- `base_unit` 이 **개·마리·세트**면 규격도 그 단위로 (`15개`). 「구」·「입」 같은 말은 쓰지 않는다
- `base_unit` 이 **L** 이거나 사용량이 `ml` 이면 규격도 `ml·L`
- 그 외는 `g·kg`
- 규격에서 **괄호와 「팩」을 뗀다** — `500g 팩`→`500g` · `15구(900g)`→`15개`
- 소수점은 **한 자리까지** — `4.233kg`→`4.2kg`

### 2-2. 🔴 최소 구매 = **우리가 고른 쿠팡 상품 그 자체**

`ingredient_retail`(status=ok · pack_g>0)이 있으면 **그 규격과 그 가격**을 쓴다.
`ingredient_pack` 은 업소용 규격이 섞여 있어 화면이 실제 소매와 어긋났다:

```
참기름  소매 412g 8,890원   ← 실제로 사는 것
        화면 1.8L 24,199원  ← 옛 pack 값. 3배 차이
쌀      소매 4.2kg 16,890원 / 화면 10kg 31,900원
```

**쿠팡 링크로 사는 물건과 화면 숫자가 다르면 그 순간 신뢰가 깨진다.**
단 **개·마리·세트는 예외** — `pack_g` 는 무게라 그대로 쓰면 「계란 0.9개」가 된다.
그때만 `ingredient_pack` 의 개수를 쓰고, 가격은 소매 상품 가격을 쓴다.

## 3. 🥇 메인 재료 판정

**판정 순서 (위에서부터 먼저 이긴다)**

```
① dish_def_ingredient.grp        사람이 지정 — 최우선
② dish_def.main_keys_json        요리별 메인 지정(현재 33개 요리)
③ 자동 판정 = «성격» + «비중»     ← 아래
④ 채소 → 야채
⑤ 분말·가루 / 이름에 가루·전분·분말·믹스 → 가루
⑥ 나머지 → 소스
```

### ③ 자동 판정 — 두 조건을 **모두** 만족해야 메인

**(가) 메인이 될 수 있는 성격인가**

| 포함 | `subcat` 대분류 `축산물`·`수산물` |
| | `subcat` 소분류 `면·떡`·`두부·묵`·`곡물`·`햄·소시지`·`수산가공`·`유제품`·`빵·디저트`·`냉동·간편식`·`절임·김치`·`기타` |
| 제외 | 이름에 **소스·양념·드레싱·시즈닝·파우더·가루·스톡·농축·다시·식초·시럽·올리고당·물엿·케첩·육수** |
| 제외 | 상비 재료 |

**(나) 그 요리에서 돈이 실제로 나가는가** — 재료비 **비중 12% 이상**

- 후보 중 12%를 넘는 게 **하나도 없으면 제일 비싼 것 하나**를 메인으로.
  「메인 없는 요리」가 생기면 첫 줄이 비어 화면이 무너진다
- 🔴 **성격은 맞는데 비중이 작아 탈락한 것은 「부재료」로 간다.** 소스로 보내면 안 된다 —
  비빔밥 쌀·탕수육 계란·설렁탕 소면이 「소스」로 찍혔다(2026-08-03)

### 이 규칙이 고친 것 (2026-08-03)

```
❌ → ✅  간장치킨 참깨 2g(1%)·탕수육 계란(6%) 이 메인이었다
❌ → ✅  김밥재료세트·자반고등어·해물믹스·삶은순대·피자치즈·비엔나소시지·
         버거번·어묵·우유·흰살생선필렛 이 «가공식품»이라 소스로 밀려 있었다
❌ → ✅  메인이 0개인 요리 4개 — 고등어구이·해물찜·물회·피자
```

## 4. 🛒 장보기 선택

- **카드를 눌러 켜고 끈다**(`.ipick.on`). 꺼진 카드는 흐리게
- ⛔ **체크박스를 쓰지 않는다** — 아이콘이 자리를 먹어 재료명이 4~5글자에서 잘렸다
- **기본 켜짐 = 메인·부재료.** 야채·가루·소스·상비는 꺼진 채로 나간다
- 켠 것만 합산해 **「장 보면」 금액**이 실시간으로 바뀐다(`.js-shopsum` 두 곳)
- **복사 버튼 클릭은 선택을 토글하지 않는다** (`e.target.closest('.copy')` 로 먼저 거른다)
- 키보드 `Space`·`Enter` 로도 토글된다
