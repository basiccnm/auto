## 콘텐츠 방향 — "개이득"

- **까기 < 개이득.** 사람은 남의 손해는 구경만 하고, 내 이득은 저장·공유한다. 저장이 알고리즘을 푼다
- **개이득 = 원가 갭이 아니라 "노동 대비"다.**
  - ❌ 족발·보쌈·곱창 — 2만 원 갭이지만 몇 시간 삶는 노동. 아무도 안 함
  - ✅ 음료(스벅 6,100 vs 원가 602)·피자(냉동도우)·볶음밥·떡볶이 — 5~10분, 손 안 감
  - "족발 집에서? ㅋㅋ 3시간 삶다 때려친다 → 근데 이건 5분 개이득"처럼 **노동을 훅으로 쓴다**
- 문구는 정보성 + "너한테 개이득" 톤. 근거는 DB 숫자

## 썸네일·훅 — 조회수 7편 실측 (표준절차 문서 §11 참고)

- 썸네일: **음식 or 큰 숫자를 화면 절반에** + "이득/남는다/아낀다" 단어. 추상 기호(닻) 금지
- 훅: **질문(?) 말고 결론.** 첫 프레임에 바로 터뜨린다
- **LEAD 0.2 고정** — 0.6으로 늘렸다가 배달편만 11회로 죽었다(다른 편 1,400)

## 수익화 — 두 갈래를 같이 굴린다

### A. 제휴 링크 (빠른 현금)
- `naver_offer` 10,584건 = 곧 돈. 재료 페이지에 "이 최저가 사러가기 → 쿠팡" 링크
- "업소용 ○○ 최저가" 검색 트래픽은 **살 마음이 있는** 트래픽이라 전환율 높다
- 정적 사이트에 링크만 붙이면 됨. **트래픽 오기 전에 미리 깔아둬야** 바로 수확된다
- ⚠️ 선행: 쿠팡 파트너스/네이버 제휴 **가입**(대표님이 직접). 가입돼 있는지 확인 필요

### B. 계산기 유료화 (쌓는 돈 = 충성고객)
**메뉴 계산기 = 단순 원가가 아니라 "얼마에 파세요" 자동 산출기**
```
재료 원가(우리 DB) + 배달앱 중개수수료율 + 목표 마진
  → "배달가 ○○원 / 홀가 ○○원에 파세요"
```
- **충성고객 논리**: 신메뉴·재료값 변동 때마다 다시 온다. 가격 정하는 게 습관이 되면 감으로 못 정한다 → 사장님 업무의 일부가 됨
- **유료 지점 = "가격 답을 주는 순간".** 원가는 미끼로 무료 공개, 배달가 산출부터 유료
- 무료는 **한 번 완성까지** 맛보게 한다(0회는 위험 — 써보지도 못한 걸 안 산다)
- 횟수 제한보다 **기능 제한(저장·엑셀·배달가 산출)**이 잘 팔린다
- 구독 추천: 자영업자 대상 "커피 한 잔 값 월 구독(3~5천 원)"이 저항 적다

**계산기 로직 확정 (DB 설계에 반영)**
- 중개수수료율 = **배달앱별 상수** (배민/쿠팡이츠/요기요). 요율은 바뀌면 뉴스로 크게 뜨니 **손으로 갱신**. 자동 수집 불필요. `theme.py` 상수 관리 방식과 동일
- **부가세·카드수수료는 안 넣는다** — 부가세=사장 몫, 카드=배달비 포함. "실제 남는 돈"이 아니라 "가격 정하는 기준"을 준다. 세금까지 넣으면 지역·업종별로 갈려 부정확
- 출력 = **배달가·홀가 두 개**

## ⚠️ 구조상 걸림돌 — 회원/유료화는 아키텍처가 바뀐다

- 지금은 **정적 생성 + Cloudflare 워커**라 서버·DB·인증이 없다
- "하루 N회 제한"·회원가입·결제·저장은 전부 **로그인(서버·인증)이 있어야** 진짜로 잠긴다
  (IP로 세면 폰 데이터·시크릿창으로 뚫리고, 쿠키는 지우면 끝)
- 계산기 유료화 = 큰 결정. **DB 고도화 → 계산기 완성 → (그때) 인증·결제 아키텍처 논의** 순서

## 순서 정리

1. **DB 고도화** (진행 중) — 원가율(`cost_ratio`)이 780%로 깨져 있음. 이거 정확해야 위 전부가 성립
2. 계산기 완성 (메뉴=가격 산출기)
3. 제휴 링크 깔기 → 쇼츠·검색으로 트래픽 유도
4. 트래픽 오면 제휴+애드센스 자동 수확, 계산기 유료화로 단골 확보

**현재 병목은 수익 방식이 아니라 트래픽.** 어떤 방식이든 사람이 와야 돈이 된다.
