# naver — 네이버 검색 API 클라이언트 (시세 산출)

상품을 파는 게 아니라 **시세 지표**를 뽑는 모듈. 그래서 최소주문수량·사업자전용·배송비는 보지 않는다(가격 신호만).

📍 **여기(얼마남아)에서 먼저 만들어 쓰고, 검증되면 `공통모듈\naver\`로 뺀다** (2026-07-20 결정).
뺄 때 `.env`는 두고 가지 말 것 — 공통모듈 원본엔 키를 넣지 않는다.

## 쓰는 법

```python
from naver import market_price

r = market_price("양파 1kg", exclude=["즙", "분말", "장아찌"])
print(r["unit_price"], r["unit"], r["n"])   # g당 원, 'g', 채택 표본수
```

여러 재료:

```python
from naver import market_prices
r = market_prices(["양파 1kg", "참기름 500ml", "후추 100g"])
```

## 설계 (2026-07-20 논의 결과)

1. **검색어에 규격을 넣는다** — `"양파 1kg"` 처럼. 그냥 `"양파"`로 치면 3kg박스·깐양파·양파즙이 뒤섞여 정규화가 안 된다.
2. **응답 title에서 규격을 다시 파싱해 검증**한다. 검색은 유사도 기반이라 요청과 다른 규격이 섞여 온다.
3. **중간값**을 쓴다. 최저가는 대용량·미끼상품 쪽으로, 최고가는 소분·가공품 쪽으로 치우쳐 시세를 대표하지 못한다.
4. 단위는 `g` / `ml` / `개` 로 정규화. 묶음(`500ml x 2`, `3개입`)은 곱해서 총량으로 만든다.

## 키

`config.py`가 이 순서로 찾는다: 환경변수 → `.env` → `naver_config.json`(기존 프로젝트 형식).
`.env.example` 참고. **키는 절대 이 폴더에 커밋하지 않는다.**

- 🔴 **프로젝트마다 앱을 따로 만들 것** — 일일 호출 한도가 앱 단위라, 한 키를 나눠 쓰면 한쪽이 조용히 죽는다.
- 🔴 **이 앱에 '네이버 로그인'을 추가하지 말 것** — 검색 API가 막힌 사례가 있다.

## 한계 (알고 쓸 것)

- 검색 API는 **배송비를 주지 않는다.** 상품가만 나온다.
- `개`·`망`·`단` 같은 개수 단위는 실제 무게를 알 수 없다 — 무게 기준 원가에는 쓸 수 없다.
- 가공품 혼입(양파→양파즙)은 `exclude` 키워드로 막는다. 재료별로 목록을 갖고 있어야 한다.
