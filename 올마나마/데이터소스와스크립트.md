## 3. 쿠팡 — 고를 때 용량이 있는 것만

```bash
python scripts/coupang_search.py <키워드목록.json>     # 검색 (분당 50회 제한)
python scripts/coupang_ingredient.py --only=<이름>     # 재료별 후보 수집
python scripts/retail_pick_sized.py <낱말...>          # 용량 박힌 후보만 보여준다
python scripts/retail_pick_sized.py --set <키> <번호>  # 사람이 고른 것 반영
python scripts/retail_set_from_search.py <키> "<상품명조각>" <용량g> --apply
python scripts/retail_packsize_recover.py --apply      # 잘려 저장된 이름에서 용량 복원
python scripts/retail_packsize_phone.py --brand <브랜드> --limit 6 --apply   # 폰 크롬(최후수단)
```

**고르는 순서** — ①물건 맞나 ②필요량 덮는 최소 규격 ③총지출 최저 ④못 찾으면 비운다

### 🚀 우선순위는 **로켓이 먼저다** — 대표 확정 (2026-07-26 · 원문은 `coupang_ingredient.py:337`)

```
① 로켓 + 가정용     ② 가정용 일반     ③ 로켓 대용량     ④ 나머지
```

> *"콩나물 400g은 일반이 팔고 로켓은 500g만 팔면 **무조건 로켓**"*

- **크기가 조금 달라도 로켓이 이긴다.** 로켓이어야 실제로 집에서 받아볼 수 있고
  배송비가 안 붙어 소매가가 왜곡되지 않는다
- 단 **로켓에 대용량밖에 없으면** 가정용 일반으로 내려간다(최소 장보기 단위가 더 중요)
- **장보기는 «한 번에 내는 돈»이 기준이다** — kg당 단가로 뽑으면 5~10kg 박스가 이긴다.
  정렬 순서: **①로켓 ②이름 일치도 ③총 가격 최저**
- 가정용 = **2kg 이하**(`HOME_MAX_KG`) · kg당 단가가 후보 **중앙값의 2.5배**를 넘으면
  바가지 소포장이라 버린다(치킨무 170g 이 50,529원/kg 으로 잡혔다)
- 프리미엄 라벨(저당·유기농·무항생제·수제…)은 **일반 상품 뒤로** 미룬다
- ⚠️ 판매자로켓(로켓그로스)은 API 의 `isRocket` 에 안 잡히기도 한다 — 사람이 보고 고른다

**`ingredient_retail.json` 의 `cands` 는 이미 이 순서로 정렬돼 저장된다**(`cands.sort`).
⛔ **순서를 다시 매기지 마라.** 사람이 할 일은 **①물건이 맞나** 확인하는 것이다.

### 🚨 「용량 모르는 후보」를 버리면 **로켓이 통째로 사라진다**

`coupang_ingredient.py:170` 에 이미 적혀 있다 —

> 용량을 못 읽어도 **버리지 않는다**. 로켓 상품은 상품명에 용량이 거의 없다
> (`[로켓프레시] 국내산 깐양파 2개입`). 전엔 용량 없으면 탈락시켜서 **로켓 소포장이
> 전부 버려지고** 용량이 적힌 5~10kg 대용량 일반 상품만 후보로 남았다.

**그런데 `retail_pick_sized.py` 가 바로 그 짓을 다시 한다** — 용량이 상품명에 박힌 것만
보여주고 나머지는 「용량 모르는 후보 N개는 뺐다」로 숨긴다.
👉 그 화면만 보고 고르면 **대용량 일반 상품만 고르게 된다.**
용량은 `retail_packsize_phone.py`(폰 크롬)나 상품 옵션에서 나중에 채운다.

### 🔑 `productId`(=`pageKey`) 가 상품이다 — `itemId` 는 그 안의 규격 (2026-08-03 실측)

| 필드 | 정체 | 쓰임 |
|---|---|---|
| **`productId` = `pageKey`** | **상품 ID.** 상품 페이지 하나 | 🔗 **링크는 이걸로 걸린다** |
| `itemId` | **개별 상품 번호** — 같은 상품 안의 용량·규격 선택지 | 화면 옵션 표시용 |
| `vendorItemId` | 판매자 옵션 번호 | 판매자마다 다르다 |

실측(후보 1,094건): **`product_id` 와 URL 의 `pageKey` 가 1,094건 전부 일치**했고,
**한 `product_id` 에 `itemId` 가 2개 이상인 것이 53건**이었다.

> **상품번호가 많아도 결국은 상품 ID로 링크가 걸린다.** (대표 2026-08-03)

#### 🚨 이게 왜 중요한가 — 진간장 실제 사례

`pageKey 7235302196` **한 상품** 안에 개별 상품이 4개 있었다:

| itemId | 가격 | 배송 | 상품명 |
|---|---:|---|---|
| 18369356049 | **3,740원** | **로켓** | 샘표 진간장 금F3 |
| 22350421984 | **6,090원** | **로켓** | 샘표 진간장 금F3 |
| 24148104438 | 13,480원 | 일반 | 샘표진간장(금F3)1.7L jps+1019wP, 1.7L, 1개 |
| 15952475890 | 31,190원 | 일반 | 샘표 진간장 금 F3, 1.7L, 3개 |

로켓 3,740원이 있는데 **상품명에 용량이 없어서** `retail_pick_sized.py` 가 숨겼고,
화면엔 13,480원짜리 하나만 「유일한 용량 후보」로 떴다. **3.6배 차이다.**

👉 **규격·가격을 알고 싶으면 `pageKey` 로 상품 페이지에 들어가라.** 옵션에 다 있다.
   후보 목록의 상품명만 보고 «용량 없음»으로 버리면 로켓 최소단위가 통째로 사라진다.

#### ✅ 한 상품 페이지 안에서 **제일 싼 옵션 = 최소 구매 단위**
같은 페이지의 옵션들은 **같은 물건의 다른 규격**이다. 그러니 그중 제일 싼 것이
「이 물건을 사려면 최소 얼마를 내야 하나」의 답이다. 위 진간장이면 **3,740원**.

⚠️ 단 **최소 금액 ≠ 최소 단가**다. 치킨무 170g 이 50,529원/kg 으로 잡힌 적이 있다(바가지 소포장).
   그래서 kg당 단가가 **후보 중앙값의 2.5배**를 넘으면 버리고, 살아남은 것 중 가장 작은 팩을 고른다.

#### 실제 사고 — 2026-08-03
`데이터소스와스크립트.md` §3 을 **grep 으로 6줄만 보고** 소매를 골랐다.
바로 아랫줄의 「로켓배송 1순위」를 못 봤고, `coupang_ingredient.py` 의 우선순위 주석도 안 읽었다.
결과: **12건 중 로켓 4건** · **로켓 후보가 있는데도 일반을 고른 게 6건**
(시금치·오이·생강·배추·고추장·도넛가루). 게다가 규격도 어겼다 —
이스트 500g×2 = 1kg(집에서 쓰는 양은 5~11g) · 마라소스 3개 묶음 · 배추 6kg 박스.

### 🚫 **끝난 것은 다시 묻지 마라** (2026-08-03 대표 지시 — *"계속 물어본다"*)

> # ⛔ `status='store'` 인 재료는 **사용자한테 묻지 않는다.**
> 이미 사람이 «소매에서 뺀다»고 결정한 것이다. 로켓 후보가 보이든 값이 비었든 **끝난 것**이다.
> 목록에 올리지도, 「이건 어떻게 할까요」라고 되묻지도 않는다.
> 되살릴 이유가 생기면 **대표가 먼저 말한다.**

아래에 해당하면 **이미 처리가 끝난 것**이다. 「소매가 없음」 목록에 올리지도, 물어보지도 않는다.

| 표시 | 뜻 | 예 |
|---|---|---|
| `manual_price=0` + `wholesale_price=0` + **쓰는 메뉴 0개** | 원가에서 뺀 재료 | **물** |
| `ingredient_retail.status='store'` | 매장 전용(소매에서 뺌) | — |
| `coupang_ingredient.NOT_FOOD` 에 걸림 | 먹는 게 아니다 | 테이크아웃 컵·빨대·포장재 |
| 후보를 다 훑고 못 찾음 | 「④못 찾으면 비운다」의 결과 | — |

#### 🥬 반찬으로 나오는 것은 소매에 안 넣는다 (`status='store'`)
기준은 **«집에서 그 요리를 만들 때 그것도 사는가»** 다. 매장에서 딸려 나오는지가 아니다.

| 재료 | 매장 | 집에서 | 판정 |
|---|---|---|---|
| **치킨무** | 치킨에 딸려 나옴 | **사서 곁들인다** | 소매 **있음** — `[로켓프레시] 일품식탁 치킨무 200g` 1,980원 |
| **깍두기** | 국밥 반찬(큰맘할매순대국 7메뉴) | 담그지 않는다 | **`store`** |

⛔ 로켓 후보가 있다는 이유로 반찬을 소매에 넣지 마라. 깍두기는 로켓 6,250원짜리가 있지만
   그건 «김치를 사 먹는 것»이지 «순대국을 끓이는 것»이 아니다.

⚠️ **`data/retail_todo.json` 의 `uses` 숫자는 낡을 수 있다.** 「물 uses=12」로 적혀 있었지만
실제 `menu_ingredients` 에는 **0건**이었다(2026-08-03). **목록 파일 말고 DB 를 보고 판단한다.**

⚠️ `decided_at` 에 `date('now')` 를 쓰면 **SQLite 가 UTC 로 찍는다** — 한국 새벽에 등록하면
전날 날짜가 된다. 「오늘 등록한 것」을 셀 때 하루가 어긋난다.

### 🔴 **50개 받고 → 검수·등록 → 다시 진행** (2026-08-03 대표 지시)
```
50개 수집  →  로켓·최저가·용량 확인  →  DB 등록  →  다음 50개
```
⛔ **한 번에 다 받으려 하지 마라.** 후보만 수백 개 쌓아두고 검수를 안 하면
   뭐가 맞는지 모른 채 파일만 커진다. 실제로 2026-08-03 에 372종 후보를 쌓아놓고
   **로켓인지·최저가인지·용량이 있는지 하나도 확인 안 한** 상태로 있었다.
- 분당 50회가 한도니 **한 묶음 = 50개**가 자연스럽다
- 한 묶음을 등록해야 다음 묶음에서 같은 실수를 안 반복한다

## 4-2. 뚫어놓은 브랜드 API (추측 금지 — 실제로 확인한 것만)

| 브랜드 | 엔드포인트 | 비고 |
|---|---|---|
| **bhc** | `GET https://www.bhc.co.kr/api/v1/web/categories/list`<br>`…/categories/{cateIdx}/products`<br>`…/products/{productCd}` | 6개 → **113개**. 판매가 = 본품가 + 옵션(한마리 +1,000 / 순살·콤보·윙 +3,000) |
| **본아이에프**(본도시락·본죽·본설렁탕·본우리반상·멘지) | `GET https://api.bonif.co.kr/brand/v1/menu?brdCd={코드}&cmdtCateIdx=&orderBy=`<br>`GET https://api.bonif.co.kr/brand/v1/category?brdCd={코드}` | 본도시락 = **BF104**. `subExp` 에 **메뉴 구성**이 들어 있다(재료 근거). ⚠️ 도시락 계열은 하지 않기로 했다 |
| **피자헛** | `GET https://www.pizzahut.co.kr/api/menu/{매장코드}/list/{카테고리}/VISIT`<br>카테고리: `best` · `premium` (매장코드 예: `0996`) | 🔴 **`price`/`hhPrice` 가 홀 매장가**(우리 기준). `memberDlv`=배달가 · `memberPack`=포장가로 따로 온다.<br>`rpstDesc` 에 구성·**중량**이 있다 — *"치즈 무게만 반근(300g)"* · *"안창살 스테이크, 리얼 감자 뇨끼…"* |
| **반올림피자** | `https://www.banolimpizza.com/menu/productPizzaDetail?spOid={피자}&productId=3001` | `spOid` 가 피자 식별자(반올림고구마 1021 · 치즈후라이 1014). **목록 페이지엔 설명이 없고 상세에만 있다.**<br>⚠️ WebFetch 는 링크를 지워 상세 주소를 못 얻는다 → **웹 검색으로 상세 URL 을 찾는 게 빠르다** |

**API 찾는 방법** (네트워크 탭이 안 잡힐 때):
```js
performance.getEntriesByType('resource').map(x=>x.name)
  .filter(u=>/api|json|menu|goods|product/i.test(u))
```
브라우저 콘솔에서 이걸 돌리면 **이미 로드된 XHR** 이 다 나온다. `read_network_requests` 가
«No network requests recorded» 로 비어도 이 방법은 된다(2026-07-27 본도시락에서 확인).

## 6-2. 🔴 «0쪽» 은 사이트가 막힌 게 아니다 (2026-07-27)

`brand_menu_list.py` 가 **0쪽**으로 실패한 브랜드를 **브라우저 도구로 열면 그냥 읽힌다.**
실제로 확인:

| 브랜드 | 수집기 | 브라우저(`preview_start`+`get_page_text`) |
|---|---|---|
| 도미노피자 | 0쪽 | **전 메뉴 + L/M 가격** 다 나옴 |
| 네네치킨 | 0쪽 | **전 메뉴 + 가격** 다 나옴 |
| 처갓집양념치킨 | 0쪽 | 메뉴 구성 설명은 나옴(가격은 공식에 없음) |
| 맘스터치 | 0쪽 | 메뉴는 나옴(**가격을 공개하지 않는다**) |

수집기는 헤드리스 크롬을 **짧게** 띄우고 HTML 을 긁는데, SPA 는 그 시점에 아직 비어 있다.
그러니 **«0쪽 = 못 뚫는 곳» 이 아니다.** 브랜드 하나를 볼 때는 브라우저로 직접 여는 게 맞다.

⚠️ 그리고 수집기가 세는 «메뉴 N개» 는 **가격이 없어도 센다.** 개수만 보고 성과로 읽지 말 것 —
롯데리아 34개는 `본문으로 가기`·`엔제리너스` 같은 네비게이션 글자였고, 설빙 99개는 메뉴명은
맞지만 **가격이 0건**이었다. 적재 가치는 `price IS NOT NULL` 로만 판단한다.

## 6-3. 🔴 가격이 없는 브랜드는 **네이버 검색**으로 (2026-07-27)

브랜드 홈페이지 49곳을 훑은 결과 **가격을 공개하는 곳은 15곳뿐**이다.
와플대학 129메뉴·설빙 100·미스터피자 98을 긁어도 **가격은 0건**이었다.

```bash
python scripts/place_menu_emu.py 홍콩반점0410        # 한 곳
python scripts/place_menu_emu.py --need              # 도장 안 끝난 곳 전부
```

**에뮬레이터(`emulator-5554`) 크롬으로 `m.search.naver.com/search.naver?query=<브랜드>`** 를 연다.
검색 결과의 「플레이스 → 주요 메뉴」에 **메뉴명 + 가격**이 그대로 나온다.
홍콩반점0410 → 짜장면 7,000 · 고추짜장 8,500 · 짬뽕 9,000 … (우리 DB 와 일치 확인)

⛔ **`m.place.naver.com/restaurant/list` 로 바로 가지 마라.** 지도 화면이 뜨고
   매장 목록이 화면에 안 그려져 **탭이 안 먹는다**(노드는 있는데 `bounds="[0,0][0,0]"`).
   2·3번째 매장에 들어가려다 한참 헤맸다. 대표 지적: *"왜 어렵게, 네이버에서 치면 하단에 나오잖아"*

⚠️ 플레이스 가격은 **매장별**이지만 프랜차이즈는 본사 권장가라 대체로 같다
   (대표 확인: *"프랜차이즈는 가격이 틀리면 안돼"*). 검색 결과 값을 그대로 쓴다.
⚠️ PC 쪽(WebFetch·in-app 브라우저)은 네이버 정책으로 막힌다 — **안드로이드 크롬만** 된다.
