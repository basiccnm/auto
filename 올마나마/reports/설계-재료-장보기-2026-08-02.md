## 1. 왜 손대야 하나 — 지금 숫자가 어긋나 있다

탕수육(`dish_tangsuyuk`) 실측:

```
집에서 만들면 재료비   7,023원
장 보면              6,285원   ← 재료비보다 작다. 말이 안 된다
```

「장 보면」이 **메인 2개(고기·계란)만** 계산하고 있다. 라벨은 「메인·부재료」인데 야채 3개·양념 12개가 빠졌다.

**최소 구매 규격으로 17개를 전부 사면 87,564원** — 재료비의 **12.5배**다.

| 묶음 | 개수 | 최소 구매 합계 |
|---|---:|---:|
| 메인 (고기·계란) | 2 | 6,285원 |
| 야채 (양파·당근·오이) | 3 | 6,753원 |
| **양념** | **12** | **74,526원** |

양념에서 터진다. 그리고 **규격 자체가 틀린 게 섞여 있다** —
식용유가 **9kg 34,434원**(업소용)으로 잡혀 있고, **식용유가 두 번**(120ml + 10ml) 들어가 있다.

> 대표: *"집에서 만들면 재료비 7,023원인데 탕수육 장보기를 하면 많이 늘어나겠지"*
> *"최소 장볼 수 있는 양을 우리는 안내를 해줘야지 쿠팡파트너스를 이용하기가 쉬워지겠지"*

## 2. 🔴 축이 둘이다 — 이걸 섞으면 안 된다

| 축 | 값 | 지금 상태 |
|---|---|---|
| **역할** | 메인 / 야채 / 양념 | ✅ 이미 재료 카드에 배지로 붙어 있다 |
| **보유** | 집에 있나 / 사야 하나 | ❌ **없다** |

**역할로 보유를 추정할 수 없다** (대표 지적):
- 계란은 역할이 «메인»이지만 보유로는 상비품이다
- 양파·당근도 일반 가정에 어느 정도 있다
- 반대로 파인애플 통조림은 «양념»이지만 집에 없다

그리고 보유는 **사람마다 다르다.** 우리가 하나로 정하면 누군가에겐 반드시 틀린다.

## 3. 확정된 것

### 3-1. ⛔ 수정 기능 없이 진행 금지

> 대표: *"사용자가 수정을 할수 있는 기능 없이 진행하면 안됨"*

자동 분류는 **기본값일 뿐**이다. 화면에 켜고 끄는 체크가 **함께** 들어가야 반영한다.
계산만 넣고 배포하는 일은 없다.

### 3-2. 🔴 최종 규칙 — 3층 (2026-08-02 대표 확정)

> *"기본적인 소금 후추 설탕 양이 많은거는 있는거야 그러니깐 이건 애초에 빼버리면 되"*
> *"전분가루도 한봉다리 양이 많아서 있을수도 있는거야"*
> *"집에 있을만한것을 표시해두고 없으면 표시해서 추가로 구매할수 있게"*

```
① 안 보임      상비 목록에 있으면 화면·계산에서 아예 뺀다
② 산다         역할이 「메인」이면 기본 켜짐
③ 있을 만한 것  그 외 전부. 기본 꺼짐 — 없으면 켜서 추가 구매
```

**① 상비 목록 (확정)**
```
소금 · 후추 · 설탕 · 식용유 · 간장 · 식초 · 다진마늘 · 물
참기름 · 고춧가루 · 고추장 · 된장
```
전부 «오래 두고 쓰는 것». 이 요리 때문에 사러 가지 않는다.

**예외를 따로 잡지 않는다.** 전분가루·생강·맛술·통조림처럼 한 봉지 사면 오래 가는 건
전부 ③으로 떨어진다 — 「메인이냐 아니냐」 하나로만 가른다.

적용 예 (탕수육 17개):
```
장 보면  5,500원
  [v] 탕수돈육등심 300g  5,500원        ← 메인

  집에 있을 만한 것  [＋ 7가지]           ← 기본 꺼짐
  [ ] 계란 · 양파 · 당근 · 오이 · 전분가루 · 생강 · 맛술 · 파인애플

  (소금·후추·식용유·간장·식초·다진마늘은 아예 안 보임)
```
**17개 → 기본 1개.** 「탕수육은 고기만 사면 된다」가 한눈에 보인다.

⚠️ 메인이 여러 개인 요리(부대찌개 = 햄·소시지·두부·라면사리)는 ②에 여러 개가 남는다. **그게 맞다.**

### 3-2-2. 화면 구조 — 첫 줄 4칸 + 접힘

```
┌────────┬────────┬────────┬────────┐
│ 탕수돈육 │ 전분가루 │ 양파    │ 당근    │  ← 첫 줄 4칸 (항상 꽉 채움)
│  [v]   │  [ ]   │  [ ]   │  [ ]   │
└────────┴────────┴────────┴────────┘
            [＋ 나머지 N가지]              ← 접힘
```

- **첫 줄은 항상 4칸**을 채운다 → 재료가 17개든 6개든 페이지 높이가 안 흔들린다
- **메인은 무조건 보여준다.** 있을 만한 것이어도 뺄 수 없다 — *요리의 정체이기 때문*
  > *"스팸이나 그런것도 왠만하면 집에 있을수도 있어. 그런데 메인은 나와야지. 라면도 매한가지"*
  → 부대찌개는 햄·소시지·두부·라면사리가 다 메인이라 첫 줄을 넘겨도 다 보인다
- **체크는 메인에도 붙는다.** 「보이는 것」과 「금액에 들어가는 것」은 별개다.
  스팸이 집에 있으면 끄면 된다

### 3-2-3. 분류 4가지 · 정렬

역할 태그를 **가루와 소스로 쪼갠다.**
> *"가루류는 더 많이 없을수 있는거라서. 소스류는 다 들어가도 가루류는 다 안들어가잖아"*

```
① 메인   고기 · 해산물 · 두부 · 면
② 야채   양파 · 당근 · 대파 · 오이
③ 가루   전분가루 · 튀김가루 · 부침가루 · 빵가루   ← 없을 확률 높음
④ 소스   간장 · 식초 · 맛술 · 통조림             ← 웬만하면 있음
```

**정렬을 두 가지로 나눈다** (첫 줄과 목록의 목적이 다르다):

| 자리 | 순서 | 이유 |
|---|---|---|
| **첫 줄 4칸** | 메인 → **가루** → 야채 → 소스 | 사야 할 가능성이 높은 것부터 |
| **목록 전체** | 메인 → 야채 → 가루 → 소스 | 장 볼 때 머릿속 순서. 같은 분류끼리 붙인다 |

각 분류 안에서는 **74개 요리 등장 빈도 순**. 페이지를 옮겨도 순서가 안 뒤집힌다.

⛔ **가격순으로 줄 세우지 말 것.**
> *"양파는 1번에 있는데 당근은 8번에 있으면 안됨"*

### 3-2-1. (참고) 폐기된 기준 — 사용량 ÷ 최소 구매량

비율이 낮을수록 「한 번 사면 오래 쓰는 것」이다. **10% 미만을 상비**로 본다.

```
꽃소금    2g / 1kg     =  0.2%   → 500번 쓴다
후춧가루  1g / 100g    =  1.0%
식용유  120ml / 9kg    =  1.3%
양파     80g / 1.5kg   =  5.3%
계란     1개 / 900g    =  6.7%
전분가루 115g / 1kg    = 11.5%   → 사야 한다
탕수돈육 300g / 500g   = 60.0%   → 사야 한다
```

### 3-3. 🔴 등장 빈도는 근거가 못 된다 (실패한 기준)

처음에 「8개 이상 요리에 나오면 상비」를 넣었다가 **생닭이 상비로 잡혔다**.
치킨 요리가 9개라서다. 사용비율은 95%인데도.

```
생닭(치킨용)  요리 9개 · 사용비율 95%  → ✅ 상비  ❌ 명백히 틀림
```

**빈도는 쓰지 않는다. 비율만 쓴다.**

### 3-4. (폐기) 보류 폴백

비율 기준을 안 쓰기로 하면서 **이 규칙도 필요 없어졌다.**
`pack_g` 가 없어도 「메인이냐 아니냐」만 보면 되므로 **소매 규격이 없어도 분류가 된다.**

> 이건 부수 효과가 크다 — `pack_g` 없는 재료가 149종 중 상당수인데,
> 그걸 다 채우지 않아도 화면을 만들 수 있다. 규격은 **금액 표시**에만 필요하다.

## 4. 효과 — 공간도 같이 줄어든다

재료가 많은 페이지가 세로로 길어지는 문제(탕수육 문서 3,504px · 분짜 2,049px)가 함께 풀린다.

```
탕수육 17개
  기본 표시  4개   탕수돈육 · 전분가루 · 계란 · 오이
  접힘      13개   집에 있을 만한 것
```

화면은 대략 이렇게 된다.

```
장 보면  ○○원                    ← 켜진 것만 합산
  [x] 탕수돈육등심 300g   5,500원
  [x] 전분가루   115g   9,400원
  [x] 신선 계란   1개     785원
  [x] 오이       60g   2,466원
  ─────────────────────────
  집에 있을 만한 것 13가지  [＋ 펼치기]   ← 기본 꺼짐
```

**켜진 것만 쿠팡으로 담는다** → 파트너스 흐름이 자연스럽게 이어진다.

## 6. 쿠팡 규격 확인 방법 (같이 정리된 것)

메모리 `coupang-size-is-one-product-key` 에 남겼다. 요지만:

```
pageKey      ← 상품. 이것 하나로 들어간다
itemId       ← 그 안에서 «어느 규격이 선택됐나»
vendorItemId ← 판매자별 아이템
```

- **뿌려지는 게 다를 뿐 결국 상품 키로 들어간다**
- **상품 페이지 한 화면에 규격이 옵션(체크박스)으로 다 있다** — 한 번 들어가면 규격별 가격을 통째로 얻는다
- **제일 싼 것이 최소 구매 단위**
- 검색 API 로는 규격을 알 수 없다 → `PACK_DEV=emulator-5556 python scripts/retail_packsize_phone.py`
- ⚠️ `ingredient_retail.product_id` 가 **247건 전부 비어 있다.** 번호는 파트너스 링크 URL 안에만 있다
