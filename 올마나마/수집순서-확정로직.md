## 🔴 화면 판독 규칙 — 토큰 태우지 마라

2026-07-31 대표 지적: *"공통모듈로 하면 제대로 읽지를 못해 하나하나 스캔해서 봐야하는데
토큰 소비량이 어마어마한데"* — **하나하나 스샷을 비전으로 읽는 것을 금지한다.**

1. **시작 전 반드시 `detect()` 판정부터.** (brand_app_read.py 가 자동으로 한다)
   - `uiauto` (글자 잡힘) → 진행. 메가MGC·컴포즈가 이 길로 100% 나왔다
   - `devtools` (웹뷰) → 화면 긁지 말고 **4a(WEBVIEW_URL)로 돌아가라.** 앱이 웹사이트다
   - `canvas` (글자 0) → **그 자리에서 중단하고 보고.** OCR 시도 금지
2. **스크린샷은 검수용 1~2장만.** 수집을 스샷으로 하지 않는다 — 수집은 uiautomator
   텍스트 노드(공짜)로 하고, 스샷은 «탭을 다 돌았나» 확인할 때만
3. 공통모듈이 **못 읽으면 고치지 말고 증상을 보고**한다:
   «detect 결과 · 화면에 잡힌 글자 수 · 어느 브랜드 어느 화면». 래퍼 수정은 등록 세션이 한다
   — 세션마다 각자 고치면 복사본이 갈라진다
4. `--tops "탭1,탭2"` 수동 지정은 자동 발견이 틀릴 때만. 그때도 탭 이름은
   **화면에 보이는 글자 그대로** 적는다

## 🚨 API 를 찾았어도 **파라미터를 바꾸지 마라** (2026-07-31 실제 차단)

파리바게트에서 `admin-ajax.php?action=pb_get_product_list&cat1=..&cat2=..&per_page=12&paged=1`
을 찾았다. 여기까지는 잘했는데 — **`per_page` 를 12→100 으로 바꿔** 한 번에 받으려다
Wordfence 가 **503 「이 사이트에 대한 액세스가 제한되었습니다」** 로 막았다.

  · 사이트가 **스스로 보내는 요청과 똑같이** 보낸다. 값 하나라도 바꾸면 이상 트래픽이다
  · 한 번에 몰아받지 말고 `paged=1,2,3…` 으로 **그 사이트가 하는 방식대로** 넘긴다
  · 요청 사이에 간격을 둔다(1초 이상)
  · 막히면 **즉시 멈춘다.** 계속 두드리면 IP 가 막혀 잘 되던 것까지 죽는다(2026-07-16 전례)

> 이건 2026-07-16 «엔드포인트 14개 추측 호출 → 방화벽 차단» 과 같은 실수다.
> 그때는 **경로**를 추측했고, 이번엔 **파라미터 값**을 바꿨다. 둘 다 «사이트가 안 하는 짓» 이다.

**차단 뒤에 확인한 것 (2026-07-31)**
- 원래 파라미터(`per_page=12&paged=1`)로 되돌려도 **계속 503** — 한 번 걸리면 그 엔드포인트가 막힌다
- **브라우저로 페이지를 열어도 상품이 0개**로 나온다(페이지 자체 ajax 가 503 을 받는다)
- 일반 페이지(`/`)는 200 — **IP 전체가 막힌 건 아니다**
- 👉 **막히면 그 브랜드를 접고 다음으로 간다.** 시간이 지나면 풀리니 나중에 다시 온다.
  다시 올 때는 **직접 API 를 부르지 말고 브라우저로 카테고리 페이지를 넘기며** 받는다
