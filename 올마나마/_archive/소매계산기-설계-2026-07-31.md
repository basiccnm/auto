# 🛒 최소주문량 구매계산기 (소매) — 설계 확정사항 (2026-07-31)

> 목업을 대표가 보고 확정한 내용의 기록이다. 구현 전 정본.
> 방향 전환: **브랜드별 원가 트랙을 접고, 대표메뉴 소매 계산기로 간다** (2026-07-31 결정).
> 브랜드 페이지는 메뉴판 전용이 되고, menus 374개 DB 는 지우지 않고 화면에서만 내린다(301 봉합).

## 1. 화면 구조 (목업 확정)

```
검색 「냉면」
  → 종류 칩: 함흥냉면 · 칡냉면 · 평양냉면      ← 면 종류가 1단계
  → 그 안에서: 물냉면 / 비빔냉면 토글          ← 조리 갈래가 2단계
제목: 「함흥 물냉면」 (1그릇 g 기준 명시)
인분 토글 1~4 → 최소주문 수량 자동 재계산
숫자 카드 2개: ①1그릇 재료값(고정) ②오늘 장보면(변동)
  + "남는 재료로 N그릇 더" (최소주문이 4인분까지 커버되는 게 셀링포인트)
재료 줄: 필요량 · 쿠팡 최소용량 상품+가격 · 수량 −/＋(0=구매X) · 「집에 있음」 체크
CTA: 남은 N개 재료 쿠팡에서 담기 · 합계
맨 아래: 만드는 법(우리 문장 3~5줄) + 「인기 레시피 N개 참고」 출처 링크
```

## 2. 데이터 파이프라인

```
만개의레시피 인기 레시피 2~3개 → 재료·양 파싱(g 변환표) → 우리 재료 DB 매핑
→ 관리자 화면에서 매칭 확인(자동 후보 2~3개 중 클릭) → 페이지 생성
가격: 소매=쿠팡(보여줌) · 도매=식봄(엔진만, 이 사이트에선 비노출)
```
- 대표메뉴 후보는 **브랜드 메뉴판 7,346줄의 빈도**에서 뽑는다(시그니처 메뉴 자동 배제)
- 조리법은 **우리 문장으로 재작성** + 출처 링크. 본문 복제 금지
- AI 매칭 불필요 — 문자열 사전 + 사람 클릭 확정. 확정된 매칭은 저장·재사용

## 3. 🔴 매칭 규칙 (사고에서 나온 것)

1. **완성품은 후보에서 뒤로 민다** — 「둥지냉면」 사고(2026-07-31): 브랜드 완성품을
   재료로 붙일 뻔했다. 상품명에 `둥지·즉석·컵·밀키트·HMR·간편` 류 신호가 있으면
   자동 매칭 1순위 금지. 재료는 원물/반가공(면사리·봉지육수)으로
2. **매칭 키워드는 메뉴 종류별 레시피에서 따온다** — 같은 「냉면육수」라도
   **함흥냉면(새콤한 회냉면 계열)과 평양냉면(슴슴한 고기·동치미 육수)은 다른 상품**이다.
   «육수» 하나로 검색하면 안 되고, 그 종류의 레시피 재료 표기(예: 「함흥냉면 육수」,
   「동치미 육수」)를 검색 키워드로 그대로 쓴다. 면도 마찬가지(고구마전분/칡/메밀)
3. 소매 고르는 순서는 기존 규칙 그대로: ①물건 맞나 ②필요량 덮는 최소규격 ③총지출 최저 ④못 찾으면 비움

## 4. 쿠팡 파트너스

- 재료 줄 상품명 클릭 = 파트너스 딥링크(`link.coupang.com/re/AFFSDP…`)로 상세페이지 직행
- 클릭 후 24시간 내 구매는 **다른 상품까지 전부** 수익 인정
- «한 번에 담기»는 쿠팡에 공식 다품목 장바구니 링크가 없다 → 버튼 누르면
  남은 재료 링크 목록을 펼쳐 하나씩 여는 방식(수익은 24시간 규칙으로 동일)
- 「가격은 날마다 달라져요」 문구 고정 노출

## 4-2. 참여 기능 (2026-07-31 대표 추가 지시)

- **「이 메뉴 넣어주세요」 요청** — 검색해서 없는 메뉴가 나오면 요청 버튼.
  익명 클릭 가능(부담 없이). 요청 수가 곧 다음에 만들 대표메뉴 순위 = 고객 반응 측정기
- **메뉴별 리뷰·댓글** — ⛔ **익명은 못 단다. 로그인 사용자만.**
  (스팸·광고·경쟁사 방어. 읽기는 누구나)
- 순서: 계산기 완성 → 로그인 부착 → 그 위에 댓글. 「메뉴 요청」은 로그인 없이도 되니 먼저 넣을 수 있다

## 4-3. 관리자 페이지 (admin 8803 확장)

**⛔ 처음부터 CRUD 완비로 만든다 (2026-07-31 대표 지시)** — 입력만 되는 반쪽으로 만들어
두세 번 고치는 일 금지. 모든 목록 화면에 **등록·수정·삭제·새로고침**이 처음부터 들어간다:
메뉴(등록·수정·삭제·공개토글) · 재료 매칭(확정·변경·해제) · 재료(추가·단가수정) ·
요청 목록(처리·삭제). 삭제는 확인창 + 딸린 행까지. 진행 작업은 새로고침으로 상태 확인.

- 메뉴 검색·추가: 「냉면」 입력 → 레시피 파싱 → 재료·양 표시 → 식봄·쿠팡 매칭 후보 2~3개 클릭 확정
- 확정 매칭은 저장·재사용 (사람 확정 우선 원칙 — 자동이 덮어쓰지 않음)
- 고객 요청 메뉴 목록: 요청 수 순위로 정렬 → 위에서부터 만들어준다
- 대표 확인 대기열: 파이프라인이 미리 돌려둔 메뉴를 대표가 훑고 공개 전환
- **가격 업데이트 버튼** (2026-07-31 대표 지시): 쿠팡·식봄 각각. 누르면 **오래된 순**으로
  재료를 돌며 갱신(백그라운드 실행, 쿠팡 분당 50회 제한 준수). 진행률·실패 목록 표시.
  갱신 후 계산기 숫자 자동 반영(재생성)
- **없는 메뉴 자동 등록 플로우** (2026-07-31 대표 지시): 검색창에 메뉴 입력 →
  레시피 파싱·매칭 후보까지 자동 → 대표가 확인(클릭) → **DB 등록·페이지 생성까지 자동.**
  사람 손은 매칭 확인 한 번뿐

## 4-5. 구현하며 확인된 것 (2026-07-31 실제 확인)

- 쿠팡 검색 API `limit` **최대 10** — 20 을 주면 `rCode=400 limit is out of range`
- 🔴 **파트너스 필수 고지 문구**를 페이지에 실어야 한다(API 가 응답마다 알려준다):
  「이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.」
  → `coupang_api.DISCLOSURE` 로 상수화. 계산기 페이지 하단 고정
- ⛔ `import coupang_search` 금지 — 파일 끝 `sys.exit(main())` 때문에 **import 만으로 서버가 죽는다.**
  부작용 없는 공용 핵심을 `scripts/coupang_api.py` 로 분리했다
- 🔴 **용량 배수**: 쿠팡은 `냉면육수, 20개, 310ml` 처럼 개수가 앞에 오기도 한다.
  개수가 엇갈리면(`x3개 … 3개`) **추측하지 않고 비운다**
- 🔴 **단위 불일치는 계산하지 않는다**: 「계란 0.5개 ÷ 1.56kg = 3,120인분」 이 실제로 나왔다.
  무게↔개수를 섞지 않고 화면에 「단위 불일치」 로 표시해 사람이 고치게 한다

## 4-6. 어디까지 만들었나 (2026-07-31 · **여기서 멈춤**)

대표 지시 — *"일단 계산기 부분은 여기까지 해놓고 메뉴를 계속 진행하자"*. 메뉴판이 우선이다.

**돌아가는 것 (전부 눌러서 확인함)**
- `admin_rc.py` → http://127.0.0.1:8803 (`python 올마나마/admin_rc.py`)
- 화면 4개: 대표메뉴 · 후보(빈도 102종) · 고객요청 · 가격갱신
- CRUD 완비 — 메뉴 등록/수정/삭제/공개토글, 재료 등록/수정/삭제, 요청 추가/상태/삭제, 새로고침
- 쿠팡 「찾기」(API 검색) · 「주소 붙여넣기」(딥링크) · 「용량·가격 고치기」(사람이 실제 용량 입력)
- 표 4개: `rc_dish` `rc_ing` `rc_pick` `rc_request` (`scripts/rc_store.py`)

**쿠팡 API 로 확인된 사실**
- 검색 결과는 **안정적이다** — 같은 검색어로 두 번 돌려 완전히 같았다.
  (앞서 «호출마다 바뀐다» 고 적었던 건 내 정렬·출력 차이였다. 틀린 기록이라 지운다)
- **옵션은 각각 행으로 온다** — 같은 `productId` 에 `itemId` 가 다르다.
  예: 면사랑 함흥면사리 `18853272404`=1,250원 / `19920626671`=5,200원
- ⛔ **옵션 상품은 상품명의 용량을 믿으면 안 된다.** 상품명이 옵션마다 똑같이 오기 때문에
  「(2kg)」 이 어느 옵션 것인지 모른다. → 옵션 2개 이상이면 **용량을 비우고** 배지로 알린다.
  같은 상품 안에서 **싼 쪽이 작은 수량**인 건 맞지만 몇 g 인지는 API 가 안 준다
- **로켓프레시는 상품명에 `[로켓프레시]` 로 붙어 온다** — 별도 칸 없음. `isRocket` 과 함께 저장
- 쿠팡 상세 페이지는 **우리가 못 연다**(브라우저 정책 차단 · WebFetch 403). 폰 크롬으로만

**⚠️ 지금 들어있는 냉면 데이터는 «기능 확인용» 이다**
- 가격·상품명은 쿠팡 API 실값이지만 **검증 안 됨**
- **재료 구성(사리 160g·육수 300ml·오이 0.2개·계란 0.5개)은 근거 없음** — 목업에서 지어낸 값
- 레시피 파이프라인을 만든 뒤 **처음부터 다시 채워야 한다.** 그대로 쓰면 안 된다

## 4-7. 원가율은 «나중에 전용 페이지로» (2026-07-31 대표 지시)

⛔ **브랜드 페이지 `<title>` 의 「원가율」 글자를 지우지 마라.**
   대표 지시 — *"빼지마 그거는 원가율 페이지는 다시 추가해서 넣을거야 원가율만 보이게.
   그런데 지금 일단은 필요없으니깐 추후에 넣도록 하자고"*

- 지금 한 것: **업종 페이지 본문에서만** 원가율 문단을 뺐다(메뉴판이 주인공이라서)
- 남겨둔 것: `<title>` 의 `· 원가율 ·` — 나중에 만들 **원가율 전용 페이지**로 이어질 SEO 신호다
- 나중에 할 것: 원가율만 보여주는 페이지를 따로 만든다. 브랜드 페이지에 원가를 다시 섞지 않는다
