# 얼마남아 — 코드탭 레시피 삽입 작업 지시서 (2026-07-19)

## 목적
Gemini로 뽑은 dish 35종 레시피를 dish 페이지에 삽입하되, **원가 계산·SEO·완성사진·내부링크·쿠팡**까지 한 흐름으로 함께 붙인다. 레시피만 덜렁 넣으면 원가가 0으로 뜨거나 SEO를 못 잡으므로, 아래 순서(의존성)를 지킬 것.

## 입력물 / 전제
- **Gemini 레시피 텍스트**: 각 요리가 `[1] 재료(그룹별)` `[2] 만드는 법` `[3] 팁` `[4] 한 줄 소개` `[5] FAQ 3개` 형식. 대표님 검수 완료본. (예: `data/recipes_gemini_2026-07.md`)
- **기존 DB**: `data/eolmanama.db` (dishes, dish_ingredients, ingredients, menus, price_history 등)
- **기존 레시피 데이터**: `data/research/recipes.json` 존재 여부·구조 확인 후 통합할지 대체할지 판단.
- 레시피 텍스트엔 **가격이 없다**(의도적). 모든 금액은 우리 시세 DB에서 계산한다.

---

## 배치 A — 기반: "원가가 나오게" 만들기 (최우선, 이게 안 되면 나머지 무의미)

**A-1. 재료명 매핑 테이블 구축 (핵심)**
- Gemini 재료명 ↔ `ingredients` 테이블 `ingredient_key` 를 연결한다.
  - 예: `생닭 토막육 10호`→`raw_chicken_10`, `찌개용 전지(돼지고기)`→해당 돼지 부위 key, `떡볶이 떡(밀떡)`→떡 key.
- 자동 유사도 매칭을 먼저 돌리고, **매칭 안 된 재료는 조용히 0 처리하지 말고 `unmatched_ingredients.md` 리포트로 출력**한다. → 대표님이 확인해 신규 재료 등록 또는 수동 매핑.
- 매핑이 비면 그 재료 원가가 빠져 전체 원가가 틀어진다. **이 단계 통과가 삽입의 전제.**

**A-2. 재사용 재료 흡유량 로직 (전략정리 6번)**
- 재료명에 `(튀김용)` 등으로 표기된 기름류는 **전량이 아니라 흡유량만** 원가 반영(중량의 약 10~15%, 또는 요리별 계수). 계산 모듈에 규칙 1회 반영 → 전체 자동 적용.
- 삶기·데치기용 물/육수처럼 버려지는 재료도 원가에서 제외 또는 미미 처리.

**A-3. dish 페이지 템플릿 개조 (페이지마다 X, 템플릿 1회)**
- 재료: 지금의 평면 리스트 → **그룹 표시**(주재료 / 튀김옷·양념·소스 / 밑간 / 부재료).
- "집에서 따라 만들기": 기존 짧은 단계 → Gemini `[2] 만드는 법`으로 **교체·확장**.
- `[3] 팁`, `[5] FAQ` 섹션 신설.

---

## 배치 B — 삽입

**B-1. 파서 + 삽입**: Gemini `[1]~[5]` 블록을 분리해 DB/페이지에 넣는다. 재료 그룹·분량을 구조화해 저장(기존 `recipe_steps` 확장 or 신규 컬럼/테이블 판단).

**B-2. 인분 정리 (배율 역전 버그 동시 해결)**: Gemini의 `N인분 기준` 값을 `dishes.serving`에 반영. 원가 vs 프랜차이즈 판매가 비교는 **같은 인분 기준으로 맞추거나 배율 열을 삭제**(김치찌개 ×0.6 역전 방지).

**B-3. 원가 재계산**: 삽입된 재료 분량 × 시세로 dish 원가 갱신.

---

## 배치 C — SEO (삽입과 동시)

- **title**: `[메뉴] 원가, 집에서 만들면 N원? (레시피)` — N은 시세 연동, 갱신 시 자동 업데이트.
- **meta description**: `[4] 한 줄 소개`에 원가를 붙여 `<head>`에.
- **Recipe JSON-LD**: `[1]`재료·`[2]`단계·조리시간·이미지 구조화. **aggregateRating(별점) 절대 넣지 말 것 — 실제 리뷰 없이 넣으면 페널티.**
- **FAQ JSON-LD**: `[5] FAQ`를 FAQPage 스키마로.
- **H2 구조 + 이미지 alt**: 재료/만드는 법/원가/프랜차이즈 비교/팁/FAQ 를 H2로. 완성컷 alt = "○○ 완성 사진".

---

## 배치 D — 사진 · 내부링크 · 수익화

- **D-1 완성 사진**: Unsplash/Pexels API로 요리명 검색 → **라이선스 안전한 1장** 자동 삽입. 출처 표기 + 호출 제한 준수. (외부 웹 이미지 긁기 금지 — 저작권.)
- **D-2 내부 링크 세트**(레시피 하단): "이 메뉴 원가 보기 / 프랜차이즈 가격비교 / 재료 시세". 그리고 **menu 360개 → dish 레시피로 링크**(menu에 레시피 본문 중복 삽입 금지 — scaled content/중복 콘텐츠 회피).
- **D-3 쿠팡 파트너스**: 재료명 → 추적ID 검색링크 버튼. 표시 문구를 버튼 근처 배치.

---

## 주의사항 (반드시)
1. 매핑 안 된 재료는 **리포트로**. 조용히 0 처리 금지. (원가 신뢰 직결)
2. JSON-LD **별점 금지.**
3. menu 360개에 레시피 본문 **중복 삽입 금지** → dish로 링크.
4. 금액은 전부 시세 DB에서. 레시피 텍스트의 표현을 그대로 믿지 말 것.
5. **검증 우선**: 우선 **후라이드치킨 1개**로 배치 A~C를 끝까지 돌려 페이지·원가·SEO 확인 후 나머지 확장.
