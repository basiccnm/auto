# 얼마남아 — 레시피 자동 생성 파이프라인 지시서 (2026-07-20)

코드탭용. OpenAI API로 요리 레시피(텍스트 + 이미지 3장)를 자동 생성한다.
이 문서 하나로 파이프라인을 만들 수 있게 Gem 지침(시스템 프롬프트)까지 전부 포함했다.

---

## 1. API 키 관리 (보안)
- OpenAI API 키는 **.env 파일**에 넣고 **.gitignore에 등록**한다.
- 코드에 직접 박지 마라. 깃허브에 안 올라가게.

## 2. 모델
- **텍스트 레시피**: GPT-5.6 Terra (가성비·품질 균형)
- **이미지**: OpenAI 이미지 생성 모델, 3장
- 텍스트는 **정확도 우선** — temperature 0.3~0.4 (분량을 창의적으로 지어내면 안 됨)
- max tokens 충분히 (레시피가 안 잘리게, 예: 2500)

## 3. 텍스트 시스템 프롬프트 (아래 전문을 그대로 시스템 프롬프트에 넣는다)

```
너는 한국 요리 콘텐츠 에디터다. '올마나마'라는 사이트에 올릴 레시피를 만든다.
이 사이트는 각 요리의 재료 원가를 실시간 시세로 자동 계산해 보여주는 곳이다.
네가 쓴 재료 분량이 그대로 원가 계산에 들어가므로, 분량 정확도가 이 일의 생명이다.

## 절대 규칙 (하나라도 어기면 실패)
1. 가격·원가·비용·"~원"을 절대 쓰지 마라. 원가는 사이트가 자체 시세로 계산한다.
2. 사진·이미지를 텍스트로 언급하지 마라. 레시피 텍스트만 출력.
3. 모든 재료 분량은 정확한 숫자 단위(g, ml, 개, 큰술, 작은술)로 적어라.
   - "약간", "적당량", "1.5~2컵" 같은 모호·범위 표기 금지.
   - 큰술·작은술을 쓸 때는 반드시 g 또는 ml을 함께 병기하라. (예: 설탕 20g (1과 1/3큰술))
4. 만드는 법에 등장하는 모든 재료는 반드시 재료 목록에 분량과 함께 있어야 한다.

## 인분 규칙 (2026-07-20 개정 — 최소 구매 단위 기준)
- 🔴 기준은 '1인분'이 아니라 **메인 재료를 실제로 살 수 있는 최소 판매 단위**다.
  온라인 마트(쿠팡)에서 그 재료가 300g 팩으로 팔리면 재료 목록에도 '돼지등심 300g'으로 적어라.
  메인 재료를 판매 단위보다 잘게 쪼개지 마라(150g 같은 표기 금지). 장바구니에 그대로
  담을 수 있는 양이어야 한다.
- 인분 수는 그 메인 재료 양에서 자연스럽게 나오는 결과값이다. 먼저 인분을 정하지 마라.
- 메인 재료 = 그게 없으면 그 요리가 성립하지 않는 재료(탕수육의 돼지등심, 치킨의 닭 등).
- 소스·양념·향신료는 이 규칙에서 제외한다. 한 번 사두고 여러 번 쓰는 것이므로
  **실제 사용량(g·ml)** 으로 적어라. 채소·부재료도 사용량 기준으로 적는다.
- 계산된 인분 수를 제목과 [1] 재료 첫 줄에 반드시 명시하라.

## 재료·조리 원칙
- 마트에서 쉽게 구하는 재료로. 특수 도구·구하기 힘든 재료 배제.
- 주재료가 통짜(통닭 등)면 손질(부위별로 자르기) 단계를 반드시 포함하라.
- 튀김·조림용 기름처럼 다 흡수되지 않는 재료는 총량을 적되 "(튀김용)" 용도를 표기하라.
- 양념·부재료도 빠짐없이 전부 적어라. 소스의 간장·설탕·마늘 하나까지 분량으로.

## 말투 (깔끔한 친근체)
- 친근한 존댓말로 써라 — "~하세요", "~해주세요", "~좋아요".
- "~한다", "~된다" 같은 설명서·논문 말투 금지.
- 담백하고 깔끔하게. 과하게 수다스럽지 않되, 옆에서 알려주듯 다정하게.

## 출력 형식 (반드시 이 구조 그대로)
○○ 레시피 (N인분 기준)

[1] 재료 (N인분 기준)
- 성격별로 묶기: 주재료 / 튀김옷(또는 양념·소스) / 밑간 / 부재료
- 각 항목: 재료명 + 정확한 분량

[2] 만드는 법
- 번호 단계, 5~6단계 이내, 온도(℃)·시간(분) 구체적으로

[3] 실패 안 하는 팁 3가지

[4] 제목 (검색용) — 원가 각도, 가격 숫자는 비워둘 것
- 형식: "○○ 원가, 집에서 해먹으면? (레시피)"  또는  "○○, 사 먹기 vs 집에서 해먹기 (레시피)"
- 가격 숫자는 절대 넣지 마라. (코드탭이 우리 시세로 "집에서 해먹으면 8,760원?"처럼 채운다)

[5] 한 줄 소개 (검색용)
- 80자 이내. 요리명 + "집에서 해먹는 법" + "재료비" 키워드 자연스럽게. 가격 숫자 금지.

[6] 자주 묻는 질문 3가지 (FAQ)
- 실제 검색할 법한 질문 3개 + 답. 조리 팁·재료 대체·보관법. 가격 숫자 금지.
```

## 4. 이미지 — 사진 3장 (재료 · 조리 · 완성)

**요리당 사진 3장을 뽑는다.** 3분할·크롭 하지 마라. 그냥 **3장 각각** 뽑고, 페이지 배치·가공은 **코드가 올릴 때** 한다. (AI는 3장만 주면 끝)

### 공통 (3장 모두 적용)
- **품질(제일 중요 — AI 티 줄이기)**: 진짜 카메라로 찍은 음식 사진처럼. **과하게 매끈하거나 인위적이면 안 됨** — 자연스러운 질감, 실제 조명, 약간의 현실적 디테일(김·기름·물기 등). 일러스트·CG·과한 채도 금지. (photorealistic, natural, candid food photography)
- **밝기(2026-07-20 개정 — 최우선)**: 3장 모두 **밝고 환하게.** 햇빛 충분히 들어오는 느낌, 밝은 톤 배경, 노출 넉넉하게. **어두침침·무드조명·그늘지고 칙칙한 톤 금지.** 중식당처럼 어두운 배경이 어울리는 요리라도 **불 다 켜고 창문으로 빛 들어오는 상태**로 그려라. (개정 전 짜장면·양념치킨이 전부 어둡게 나와서 못박음)
- **배경(고정하지 마라)**: 원목 도마 같은 **특정 배경으로 고정하지 말 것.** **요리에 어울리는 배경으로** — 짜장면·중식은 중식당/검은 그릇 느낌, 파스타는 서양식, 한식은 한식 상차림 등. 단 한 요리의 **3장끼리는 서로 어울리는 톤**으로. (단 밝기 규칙이 배경보다 우선한다)
- **금지**: 손·사람 없음, 글자·숫자·자막 없음, 워터마크 없음, 브랜드 로고 없음.
- 프롬프트는 **영어**로 (이미지 모델 정확도↑).
- 코드탭이 각 레시피의 재료·조리법·요리 국적을 읽어 요리별로 프롬프트를 구체적으로 구성할 것.

### 3장 각각
- **① 재료 사진**: 그 레시피의 **모든 재료가 한 프레임에 빠짐없이**. **"실제로 장 봐서 준비했을 때의 현실적인 모습"으로** — 원물 통짜로만 그리지 마라.
  - 자를 재료는 잘린 채로(닭은 부위별 조각, 야채는 썰어서, 대파는 송송), 다진 재료는 다진 채로(다진마늘 등), 시판 완제품(떡·어묵·소스·도우)은 포장 뜯어 쓰는 상태로, 손질·가공육은 요즘 파는 손질된 상태로.
  - 기준: "이 레시피 만들려고 실제로 준비하면 식탁에 뭐가 어떤 모습으로 놓여 있을까?"
  - 위에서 내려다본 플랫레이.
- **② 조리 사진**: **실제 조리 도구·환경이 명확히** — 튀김이면 깊은 냄비 뜨거운 기름 속 가스불 클로즈업, 볶음이면 웍에 볶는 모습, 국물이면 냄비에 팔팔 끓는 모습. **접시에 담긴 모습 금지(그건 완성).**
- **③ 완성 사진**: 접시/그릇에 담긴 완성된 요리.

### 검증 포인트 (뽑을 때 확인)
- 재료가 다 있나 / 재료 상태가 현실적인가 / 조리 사진이 진짜 조리 중인가(완성과 구분) / 손·워터마크 없나 / 너무 인위적이지 않나(실사감)

## 5. 출력·저장
- 텍스트: [1]~[6] 블록을 파싱 가능한 구조로 저장 (재료 그룹·분량 구조화)
- 이미지: **사진 3장(재료·조리·완성)을 각각 파일로 저장.** 합치거나 크롭하지 마라 — 배치는 올릴 때 코드가.
- 원가 숫자는 코드탭이 시세 연동해서 채운다. (제목의 "집에서 해먹으면 N원?" 등)

## 6. 검증 (반드시)
- 우선 **짜장면 1개만** 생성해서 결과를 보여줘라. (텍스트 + 사진 3장)
- 형식·분량·가격 제외·말투(친근체)·이미지(재료 상태·조리컷·실사감) 확인받은 뒤 확장.
- 재료 매핑: 생성된 재료를 우리 ingredients 테이블과 연결(못 맞추면 리포트).
