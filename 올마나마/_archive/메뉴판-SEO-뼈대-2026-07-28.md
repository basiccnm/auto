> 근거는 **네이버 검색광고 키워드도구 실측**(`python scripts/naver_keyword.py`)과
> **구글 서치콘솔 28일치**(노출 99 · 클릭 4 · 평균순위 7.9위)다.

## 2. 규칙 — 페이지마다 이 형식으로

### 브랜드 페이지 (`brand_*.html`) ← 제일 중요
```
title  {브랜드} 메뉴 가격표 · 원가율 · 올마나마
h1     {브랜드} 메뉴 가격표
desc   {브랜드} 전메뉴 가격 {최저}~{최고}원 과 재료비 원가율을 한 번에.
       메뉴 N개의 판매가 대비 재료비가 몇 %인지, 집에서 만들면 얼마인지 공개합니다.
```
`메뉴` · `가격` 두 단어가 제목에 다 들어가야 "브랜드메뉴"와 "브랜드가격"을 같이 먹는다.

### 메뉴 페이지 (`menu_*.html`)
```
title  {브랜드} {메뉴} 가격 · 원가율 · 올마나마
h1     {메뉴} 가격 · 원가율
```
`원가`만 넣으면 월 10회짜리 말에 걸린다. **가격이 먼저다.**

### 카테고리 페이지 (`cat_*.html`)
```
title  {카테고리} 브랜드별 메뉴 가격 · 원가율 · 올마나마
```

---

## 3. 구조 — 지금 빠져 있는 것

브랜드 페이지에 **h2 가 하나도 없었다**(2026-07-28 확인). 구글이 문단 구조를 못 읽는다.

- [x] `h1` = 브랜드명 + **메뉴 가격표**  (전엔 브랜드명만)
- [x] `h2` = `원가를 낸 메뉴 N` · `전체 메뉴판 N개`
- [ ] `h3` = 메뉴판 탭마다 (치킨 / 사이드 / 음료 …) ← **아직**
- [ ] JSON-LD ← **아직.** 브랜드 페이지에 구조화 데이터가 하나도 없다

### 메뉴판은 접지 마라
`<details>` 안에 넣으면 색인이 약해진다. 지금은 탭으로 나뉘어 있고 **HTML 에는 전부 들어 있어서 괜찮다** —
탭 전환을 JS 로만 하고, 서버 응답에서 메뉴를 빼지 말 것.

### JSON-LD (넣을 것)
```json
{ "@context":"https://schema.org", "@type":"ItemList",
  "name":"{브랜드} 메뉴 가격표",
  "itemListElement":[
    {"@type":"ListItem","position":1,
     "item":{"@type":"MenuItem","name":"뿌링클",
             "offers":{"@type":"Offer","price":21000,"priceCurrency":"KRW"}}}
  ]}
```
가격이 검색결과에 직접 뜰 수 있다. 메뉴 페이지엔 이미 Recipe JSON-LD 가 있으니 형식은 그걸 참고.

## 4. 하지 말 것

- **제목에서 `가격`·`메뉴` 를 빼고 `원가`만 남기지 마라.** 그게 지금까지의 실수다.
- 브랜드명을 임의로 줄이지 마라. `bhc치킨` 처럼 사람들이 치는 그대로 둔다.
- 메뉴판을 이미지로 만들지 마라. 텍스트여야 걸린다.
- 가격을 지우지 마라. **가격이 있는 게 우리 무기다.**

## 순위 페이지 (`ranking.html`)

- **역할: 내부 순환.** 브랜드·메뉴 페이지로 보내는 허브다. 검색 1등을 노리지 않는다.
- title `프랜차이즈 메뉴 원가율·마진율 순위` — `마진율`(1,780)만 곁가지로 먹는다
- 여기에 힘을 더 쓰지 말 것. 같은 시간에 **재료 페이지 326장**을 손보는 게 몇 배 낫다
  (계란가격 16,320 · 감자가격 3,060)

## 정보 페이지 (`info_*.html`)

지금 8편이 전부 `○○ 원가` 형식인데, 그 말은 월 10~50이다.
그런데 **서치콘솔에서 실제로 클릭이 붙은 건 정보글이다**(`설빙 원가` 4위, `처갓집 후라이드` 2위).
즉 형식이 문제지 글 자체는 먹힌다.

### 앞으로 정보글 제목은 이렇게

```
✕  뿌링클 21,000원, 재료비는 얼마일까        ← '뿌링클원가' 월 10
○  뿌링클 가격 인상? 재료비로 따져봤습니다      ← '치킨가격'·'치킨할인' 쪽으로 붙는다
○  치킨 할인쿠폰 받고도 손해인 경우            ← '치킨할인' 1,600
○  가성비 치킨 브랜드, 재료비로 줄 세우면       ← '가성비치킨' 690
```

**규칙: 제목에 `원가`만 쓰지 마라. 사람들이 치는 말(가격·할인·가성비·추천)을 하나 이상 넣는다.**

### 글 하나당 노리는 검색어를 정하고 쓴다
1. `python scripts/naver_keyword.py 후보1 후보2 …` 로 먼저 검색량을 본다
2. 월 500 이상인 말이 없으면 **그 주제로 글을 쓰지 않는다**
3. 정한 말을 title · h1 · 첫 문단에 그대로 넣는다

## 우선순위 (시간 대비 효과)

1. **재료 페이지 326장** — 계란·감자·양파… 합치면 제일 크다  ← 제목 반영 완료
2. **브랜드 메뉴판 49장** — BHC메뉴 9,370 급           ← 제목·h2·h3·JSON-LD 완료
3. **정보글** — 검색되는 말로 새로 쓰기                  ← 앞으로
4. 순위·계산기 — 내부 순환용. 검색은 기대하지 않는다

## 결론 — 지역은 페이지, 품목은 그 안의 소제목

- **시·도 17개 + 「그 외(택배배송)」 1개 = 18장.** 광역시 하나에 월 1,000쯤이라 합계 5천~1만.
- **시·군·구 247개는 만들지 마라.** 검색량 0에 가깝고, 내용 비슷한 페이지 대량 생성은
  저품질로 잡힌다. 애드센스 심사 중이라 특히 위험하다.
- **지역 × 품목으로 곱하지 마라.** `부산정육도매` 10명이다. 136장을 만들어도 소득이 없다.
- 품목은 **한 페이지 안에서 h2 로 나눈다** — 정육 / 채소 / 수산 / 계란 / 냉동.
  페이지를 쪼개지 않아야 "부산 식자재마트"로 들어온 사람이 정육까지 같이 본다.
- **품목 단독 페이지도 만들 필요 없다.** 재료 페이지가 이미 먹고 있다 —
  `계란 가격` 16,320 vs `계란도매` 840. 20배 차이다.

## 지역 페이지에 넣을 것 (로그인 없이 가능한 범위)

가격이 지역별로 안 갈려도 검색은 잡힌다. **업체 목록이 지역마다 다르면 내용이 갈라진다.**

- 그 지역에 배송하는 업체 목록 — 업체명 · 주문마감 시각 · 배송 요일 · 취급 상품 수
- 전국 물류업체(`is_logistics_vendor`) / 지역업체 구분
- 「그 외(택배배송)」 — 전국 어디서나 받는 경로
- 재료 가격표 — **"전국 기준"이라고 반드시 밝힌다**

🔴 로그인 세션까지 가서 지역별 가격을 갈라내는 건 SEO 관점에선 **불필요하다.**
   세션 유지가 깨지면 수집이 통째로 멈춘다. 얻는 것보다 잃는 게 크다.

🔴 **"쿠팡"·"로켓배송"은 제목·설명·도메인에 쓰지 않는다.** 파트너스 약관상 상표 사용 제한이다.
   본문에서 사실 서술("조사한 상품은 모두 로켓배송입니다")은 괜찮다.

## 왜 순위를 버리나

`원가율순위` 10 · `치킨원가율순위` 10 · `프랜차이즈원가` 10.
**우리 콘텐츠를 설명하는 말은 전부 월 10명이다.** 반면 `식자재마트`는 54,090,
광역시별로도 1,000씩 나온다. 같은 자리에 식자재마트를 놓는 게 100배 낫다.

순위 데이터 자체는 지우지 말고 **브랜드·메뉴 페이지 안의 섹션**으로 남긴다 — 내부 순환에는 쓸모가 있다.
