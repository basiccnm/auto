# 원가계산기 설계 — 2026-07-25 확정

> 대표 판단: **이게 지금 하는 것 중 제일 빠르게 반응 올 수 있는 아이템.**
> 애드센스(트래픽 쌓여야 푼돈)보다 빠른 현금. 소매는 쿠팡 제휴로 자동 수익.
> 순서: **제휴(쿠팡)로 현금 → 트래픽(SEO) → 계산기 유료화로 구독 자산.**

---

## 0. 한눈에

계산기는 **2개**(소매·도매). 도매 위에 **플랜(베이직·프리미엄)**으로 기능이 열린다.

```
소매 계산기   재료 몇 개 선택 → 100g당 가격          일반인 미끼 · 쿠팡가 · 무료
도매 계산기   재료 몇 개 선택 → 100g당 가격 (맛보기)   사장님 유입 · 우리 DB · 회원
──────────── 여기까진 "얼마쯤" 조회 ────────────
메뉴(베이직)  초정밀: 1g 단위 + 양념 별도 + 템플릿 저장           ← 여기부터 진짜 도구
배달(프리미엄) 메뉴원가 + 배달앱 수수료 + 마진율 → "얼마에 파세요"  ← 제일 값나감
```

**소매·도매는 조회(맛보기), 메뉴부터가 초정밀 도구.** 여기가 돈 내는 지점.

---

## 1. 접근·과금

| 층 | 접근 | 과금 |
|---|---|---|
| 소매 | 비회원, 쿠키/IP 하루 20회 | 무료(미끼). 쿠팡 공개가라 유출 무관 |
| 도매 조회 | 카카오 회원 | 건당 10원 (맛보기, 우리 DB라 아껴서) |
| 메뉴(베이직) | 회원 | 건당 100원 |
| 배달(프리미엄) | 회원 | 기능별 추가 과금 (반찬·배달 등) |

- **회원가입은 무료.** 카카오 로그인(REST 키 `.env`/워커시크릿에 준비됨).
- **충전제** — 무료 구간 없이 충전잔액에서 건당 차감. 1만원 단위 충전(PG 소액결제 수수료 절감).
- **구독 vs 1회작업** 사용자가 선택 — 가끔=건당, 헤비=월정액.
- **기능마다 단가**(기능ID→price 테이블). 기능 추가돼도 과금이 자동으로 따라옴.
- 소매는 서버 없이 프론트 쿠키 카운트. 도매·메뉴는 카카오 로그인 뒤 서버가 값 지급.

---

## 2. 메뉴 계산기 (베이직) — 초정밀

- **1g 단위** 투입 (100g 어림 아님).
- **양념 별도** — 재료와 따로. 소량이지만 종류 많음.
- **템플릿 여러 개 저장** — "우리집 국밥 베이스" 저장→재사용.
  ★ 이게 충성 만드는 핵심. 한 번 만들면 신메뉴·재료값 변동마다 다시 옴 = 사장님 업무의 일부.
- **한식 반찬 수식** — 반찬 기본 30~40g 기준(직접 수정 가능). 백반·국밥은 반찬이 원가의 큰 부분.

---

## 3. 배달 계산기 (프리미엄) — 가격 결정

```
재료원가(초정밀) + 포장용기 + 배달앱 중개수수료 + 목표마진
────────────────────────────────────────────
= "배달가 ○○원 / 홀가 ○○원에 파세요"  (자동 산출·등록)
```

- **배달앱 수수료** = 배민·쿠팡이츠·요기요 요율. **상수로 관리**(theme.py 상수처럼). 뉴스 뜨면 손으로 갱신. 자동수집 불필요(안 바뀌다 가끔 크게 바뀜, 바뀌면 뉴스로 앎).
- **부가세·카드수수료는 안 넣음** — 부가세=사장 몫, 카드=배달비 포함. "실제 남는 돈"이 아니라 "가격 정하는 기준"을 주는 도구. 세금 넣으면 지역·업종별로 갈려 부정확·클레임.
- **포장용기** = 배달 원가의 필수 항목. 식봄 포장 카테고리(`_포장카테고리.json` 28잎)에서.

## 4. 가격 표기 규칙 (전 계산기 공통)

- **가공·소스는 최저~최고 범위 + 중앙값(대표값).**
  - 브랜드·용량 많아 최저가 하나로 못 잡음.
  - 범위 = 보여주기용(정확성 방어 — 하나로 안 박으니 틀릴 일 없음).
  - 대표값 = **중앙값(median)**. 인기순은 광고 우려로 안 씀(현재 광고 없지만 안전하게). 중앙값이 미끼최저·소포장튐·광고 다 무시하고 "보통 사는 값".
- **⚠️ 최소 주문단위 명시 (전 계산기).**
  - "삼겹 100g 640원" 보여줘도 실제론 10kg 박스로만 팜. 명시 없으면 원가가 현실과 어긋남.
  - `ingredient_price.pack_kg`에 규격 이미 저장돼 있음(미트박스·식봄 수집 때).
- **메뉴부터: 재료 선택 → 실제 제품·주문단위 안내.** "이 재료 10kg 박스 / 5kg / 1kg" 보여주고, 1g으로 넣되 원가는 실제 살 수 있는 단위 기준.
- **면책 문구** — "표시 가격은 조사 시점 최저가 기준. 지역·용량·시기·거래처 따라 실제가 다름. 참고용." (시세 페이지에 이미 적용)

## 5. 데이터 토대 (왜 남이 못 베끼나)

- 재료 ~700종 **원산지·등급·형태·규격별 실판매가, 매일 갱신** — `ingredient_price` 표.
- 소스: **식봄(foodspring)이 활어 빼고 거의 전부** — 육·수산·채소·소스·장류·면·냉동·반찬·베이킹·포장. 미트박스(육류)·식자재왕몰·쿠팡(소매)은 서브.
- 이 수집 인프라가 해자. 남이 따라오려면 다 다시 뚫어야 함.
- 계산기가 값나가는 이유 = 이 DB가 정확·최신이라서. 그래서 지금 DB 작업이 계산기의 연료.

## 6. 두 갈래 사용자 (깔때기)

```
소매(구경) → 도매(회원가입) → 메뉴(베이직) → 배달(프리미엄)
 일반인        사장님 확보       원가          진짜 돈
  ↓쿠팡 제휴
 재료·밀키트 구매 수수료(빠른 현금)
```

- **일반인** = 레시피 + 소매가 + **쿠팡 재료/대체밀키트 버튼** → 제휴 수수료.
  - 대체 밀키트: 정확히 그 브랜드 아니어도 "비슷하게 집에서, 냉동으로". 프랜차이즈도 빈자리 없이.
  - 멘트: "이거 하나면 빠르게 해먹을 수 있음."
- **사장님** = 도매·메뉴·배달 계산기 (충전/구독).

## 7. 만들기 전 남은 것

- 카카오: 로그인 사용설정 ON·redirect_uri 등록 완료. REST 키 `.env` 저장됨. OpenID/웹훅 불필요.
- 워커: 지금 **정적 자산 전용**(main 스크립트 없음). 로그인 콜백 받으려면 워커에 스크립트 추가 + REST 키를 **워커 시크릿**으로.
- redirect: `/auth/kakao/callback` (확정).
- 목업: `_mockups/calc.html` (그람수·원산지 선택·반찬 35g 골격). 로컬 8809로 인터랙티브 확인.
- 결제(PG): 충전제 → 카카오페이/토스페이먼츠. 1만원 단위 충전.
