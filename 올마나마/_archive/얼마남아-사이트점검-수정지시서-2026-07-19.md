# 올마나마(olmanama.com) 전체 점검 — 수정사항 지시서

점검일: 2026-07-19 (홈/요리사전/요리상세/메뉴상세/원가율순위/카테고리/브랜드/시세 전 화면 + eolmanama.db 대조)
목적: 트래픽 유입 + 체류시간(내부 회유 동선) 극대화. 기존 Pending 배치(전략정리 9번)와 합쳐 코드탭에 한 번에 지시할 수 있게 정리.

---

## 우선순위 요약

- **A급 (신뢰를 깨는 데이터 버그 — 최우선)**: 배율 ×0.6 역전, 족발 재료 1줄 문제, 레시피-재료표 불일치, 인분 기준 뒤죽박죽
- **B급 (체류시간 — dead-end 제거·내부링크)**: 순위 클릭 불가, 페이지 하단 막다른 길, 전역 네비 부재, 재료↔요리 역링크
- **C급 (디테일)**: 로고, 정렬, 광고 영역 등

## A급 — 데이터·로직 버그 (사이트 신뢰도 직결)

### A-1. 배율 역전 버그 (김치찌개 ×0.6) — 치명적
- `dish_kimchi-jjigae`: 집밥 재료비 **15,948원(4인분)** vs 프랜차이즈 판매가 **10,000원(1인분)** → 배율 **×0.6**으로 표시.
- 인분 수가 다른 걸 그대로 나눠서 "집에서 만들면 프랜차이즈보다 비싸다"로 보임. 사이트 논리가 통째로 무너져 보이는 부분.
- **수정**: 1인분 환산 후 비교하거나, Pending대로 **배율 열 자체를 삭제** (dish 페이지 + menu 페이지 공통). 하단의 "4그릇 40,000원 vs 4인분 15,948원 = 24,052원 절약" 문장 방식이 정확하니 이걸 표준으로.

### A-2. 재료 언더카운트 (족발 등 극단값)
- 족발: 재료가 "족발 생육 700g, 4,550원" **한 줄뿐**. 조리 단계에는 된장·간장·설탕·향신료가 나오는데 재료표엔 없음 → 배율 ×6.4~×9.0으로 과장돼 신뢰 하락.
- DB에서 원가율 하위권 메뉴도 같은 의심: 에머이 야채볶음 재료비 480원(원가율 5.3%), 포메인 칠리볶음밥 1,149원(7.4%), 홍대개미 닭목살덮밥 903원 등.
- **수정**: ① 원가율 하위 10~15개 메뉴 재료 구성 일괄 점검. ② 공통 규칙으로 "양념·부재료" 1줄(메뉴 성격별 500~1,500원) 추가하거나 "기본 양념 제외" 라벨 명시. 전략정리 6번(흡유량 로직)과 같이 **로직으로 한 번에** 처리.

### A-3. 레시피 단계 ↔ 재료표 불일치 (같은 페이지 안에서 모순)
- `dish_kimchi-jjigae`: 재료표는 삼겹살 400g·두부인데, 만들기 단계는 "앞다리살 150g, 당면·푸주, 대파·양파". 김치도 재료표 800g vs 단계 200g.
- 원인: 단계 텍스트가 프랜차이즈 메뉴(백채김치찌개) 기준 recipe_steps를 그대로 붙여서.
- **수정**: dish 페이지 단계는 dish 재료표 기준으로 재작성. → **어차피 ChatGPT 레시피 배치 생성(전략 3-4)으로 교체 예정이므로, 그때 dish 재료표와 분량을 맞춰 생성하는 걸 규칙에 포함**하면 한 번에 해결.

### A-4. 인분 기준 뒤죽박죽 (요리사전 카드)
- 카드에 김치찌개 15,948원(실제 4인분), 떡볶이 9,592원(1인분), 족발 4,550원(반 마리)이 기준 표기 없이 나란히 → 김치찌개가 미친 듯이 비싸 보이고 족발이 이상하게 싸 보임.
- DB `dishes.serving`은 김치찌개가 '1인분'인데 페이지는 4인분×4배 재료로 렌더 — **serving 값과 렌더 배수 로직이 어긋나 있음. 어디서 4배를 곱하는지 확인 필요.**
- **수정**: ① 카드에 기준 표기("4인분", "한 마리", "1줄") 추가. ② 가능하면 "1인분 환산가" 병기 또는 환산 정렬. ③ DB serving 값 정리.

## B급 — 체류시간·내부 동선 (dead-end 제거)

현재 구조는 "들어온 페이지에서 끝"이다. 모든 페이지가 `공유하기 → 면책 → footer`로 끝나서, 꼬아놓은 네비가 "미로"가 아니라 "막다른 골목"으로 작동 중. 꼬기는 콘텐츠 안 링크로 하고, 나가는 길목마다 다음 볼거리를 깔아야 함.

### B-1. 원가율 순위 페이지 — 행 클릭 불가 (가장 아까운 페이지)
- 1~10위 행이 링크가 아님. 360개 목록을 보고도 아무 데도 못 감.
- **수정**: 각 행 → 해당 menu 페이지 링크. + 카테고리 필터 칩(치킨/피자/…) 추가하면 페이지 넘기며 체류 늘어남.

### B-2. 페이지 하단 "다음 볼거리" 블록 (전 페이지 공통)
- dish/menu/brand 페이지 하단에 3종 세트:
  - "이 요리 다른 브랜드는?" (같은 dish의 menu 목록)
  - "원가율 TOP 5" (ranking 미리보기)
  - "오늘 재료 시세 보기" (prices 링크)
- 이게 전략정리 3-2 내부링크 세트의 사이트 버전. 레시피 유입이 시작되기 전에 뼈대를 먼저 깔아두는 것.

### B-3. menu 페이지 "집에서 직접 만들면 재료비 9,150원" 카드 → dish 페이지 링크
- 지금 클릭 안 됨. 교촌오리지날(menu) → 간장치킨(dish) → 재료 시세 → 쿠팡으로 이어지는 **회유 동선의 핵심 고리**라 반드시 링크.

### B-4. 전역 네비게이션
- 헤더에 로고+공유+다크모드뿐. dish 페이지에서 시세/순위로 갈 방법이 없음.
- **수정**: 헤더에 4개 텍스트 링크(요리 · 브랜드 · 시세 · 순위) 또는 모바일 하단 고정 탭. "꼬기"는 본문 링크로, 기본 출구는 명확하게 — 길을 못 찾으면 머무는 게 아니라 나감.

### B-5. 재료 시세 → 요리 역링크
- prices의 재료 행 클릭 시 "이 재료가 들어가는 요리/메뉴" 목록 표시(또는 펼침). 시세 보러 온 사람을 요리→쿠팡으로 끌어들이는 두 번째 고리.

### B-6. menu 페이지에 쿠팡 블록 없음
- dish 페이지엔 쿠팡 검색창+복사 버튼이 있는데 menu 페이지엔 복사 버튼만 있음. 360개 menu 페이지가 수익화에서 빠져 있는 셈.
- **수정**: menu 페이지 재료 아코디언 아래에 dish와 동일한 쿠팡 블록 + (Pending대로) 재료행에 추적ID 검색링크 버튼.
- 쿠팡 파트너스 문구는 이미 하단에 있음 — 버튼 근처로도 한 줄 이동 배치 권장(공정위 표시 위치).

### B-7. 시세 페이지 "0 오름 / 0 내림 / 0 보합" 문제
- 첫 화면 제일 위에 0/0/0이 크게 노출 — "매일 갱신"이라는데 아무것도 안 움직여 보임(고정단가 247종이 섞여서).
- **수정**: 변동 집계는 자동갱신 362종만 대상으로 하고, 변동 0인 날은 "오늘은 큰 변동 없음 · 최근 변동: ○○ +3.2%" 식으로 최근 변동 재료를 보여줌. 전략정리 2번(1층/2층 구조 라벨)도 이 페이지에 반영: 고정단가엔 "참고가 · 월 갱신" 라벨.

## C급 — 디자인·디테일

1. **cat 페이지 브랜드 로고 누락**: 치킨 카테고리 10개 브랜드 전부 닭다리 이모지. brand 페이지엔 로고 있음 → cat 페이지에도 logo_url 렌더. (DB상 로고 없는 브랜드 20/87곳 → fetch_logos 재실행 대상)
2. **cat 페이지 미리보기 부족**: 브랜드명+메뉴 개수만 있음 → 대표 메뉴 1개와 원가율 미리보기 추가하면 클릭률↑.
3. **홈 원가율 TOP 사이드카드**: 3개→5개, 각 항목 menu 페이지로 클릭 가능하게.
4. **홈 "실시간 재료 가격 07.18 대비" 카드**: 내용 없이 버튼만 있음 → 오른 재료 TOP3 미리보기 표시.
5. **요리사전 정렬/검색**: 정렬 칩(재료비순/가나다/판매처 많은 순). 현재 카테고리 칩은 좋음.
6. **menu 페이지 "재료 N가지 자세히 보기" 아코디언**: 기본 펼침 고려 — 접혀 있으면 체류 짧아지고, 펼쳐져 있어야 복사→쿠팡 동선이 보임.
7. **brand 페이지 하단**: "같은 카테고리 다른 브랜드" 블록 (B-2와 동일 패턴).
8. **광고 영역**: 광고 미노출 시 빈 영역 접기(기존 Pending 유지).
9. **(SEO, 레시피 붙일 때) Recipe 구조화 데이터(JSON-LD)**: dish 페이지에 레시피 스키마 추가하면 구글 레시피 리치결과 노출 가능 — ChatGPT 레시피 삽입 구조 만들 때 같이.

## 기존 Pending(전략정리 9번) 반영 현황 — 이번 점검으로 확인

| 항목 | 상태 |
|---|---|
| 메뉴명 크게/프랜차이즈명 작게 | ✅ 반영됨 (menu 페이지 확인) |
| "요리 35종 전부 비교" 버튼 삭제 | ✅ 안 보임 (반영된 듯) |
| 원가율 순위 10개 페이지네이션 | ✅ 반영됨 (1/36) |
| 가격비교 참고용 문구 | ✅ 있음 |
| "배율" 열 삭제 | ❌ dish/menu 페이지에 아직 있음 → A-1과 함께 처리 |
| 재료 버튼 쿠팡 추적ID 링크 | ❌ 검색창+복사만 있음 → B-6 |
| 시세 갱신시각·기준일 표기 | ✅ 있음 (매일 오전 7시, 기준일) |
| 광고 빈 영역 접기 | 확인 불가(광고 미노출 상태) → 유지 |
| 필터 칩 5분류 | 시세 페이지 칩 있음 (축산/농산/수산/가공/시판) ✅ |

## 코드탭 배치 지시 순서 (제안)

1. **배치 1 (데이터 버그)**: A-1 배율 삭제/환산 → A-4 인분 기준 표기+serving 로직 → A-2 언더카운트 점검 스크립트(하위 15개 리포트만 먼저 뽑기)
2. **배치 2 (내부링크)**: B-1 순위 링크 → B-3 menu→dish 링크 → B-2 하단 다음볼거리 블록 → B-4 헤더 네비
3. **배치 3 (수익·시세)**: B-6 쿠팡 블록/추적ID → B-7 시세 변동 집계 → C-1 로고 → C-3~6
4. **배치 4 (레시피)**: ChatGPT 레시피 생성(재료표 분량 연동 규칙 포함) → dish 페이지 텍스트 삽입 구조 + Recipe JSON-LD → A-3 자동 해결

※ A-2 재료 보정과 흡유량 로직(전략 6번)은 같은 계산 모듈이므로 한 배치로 묶는 게 효율적.
