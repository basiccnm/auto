# 얼마남아(olmanama) — 레시피·이미지·원가·시세 전략 정리

작성일: 2026-07-19
용도: 이 세션에서 확정한 얼마남아 관련 결정 전부. 새 창에서 이 문서 읽고 이어가면 됨.
(학교/에듀싱크 건은 완전 별개 — 에듀싱크 폴더의 핸드오프 문서 참조)

---

## 0. 큰 그림 (왜 이걸 하나)

얼마남아는 원가율·재료시세·프랜차이즈 가격비교가 **메인 콘텐츠(진짜 데이터)**인 사이트다.
당장 애드센스/애드핏/쿠팡파트너스로 수익을 내는 게 목표.
이번 세션의 핵심은 **레시피를 유입 미끼로 붙여서 검색 트래픽을 끌어오고, 그걸 원가·시세·쿠팡으로 흘려보내는 구조**를 확정한 것.

---

## 1. 돼지고기 원가 계산 — "지육 ÷ 수율" 공식 폐기 (확정)

- **틀린 공식:** 부위단가 = 지육시세 ÷ 부위 수율.
  → 한 마리(지육) 값 전체를 한 부위에 다 뒤집어씌워서 가격이 폭등한다.
  (삼겹살 5,500 ÷ 0.16 ≈ 34,400원/kg = 비현실적. 항정살은 92만원/kg 같은 헛소리.)
- **결정:** 이 공식 완전 폐기. **부위별 실제 시장가**로 간다.
- 지육 시세는 "지육 시세 보러 오는 사람 잡는 콘텐츠"로만 따로 둔다. 레시피 원가 계산엔 안 쓴다.

---

## 2. 재료시세표 — 2층 구조 (확정)

매일 손으로 262종을 갈아끼우는 건 불가능. 그래서 **데이터 성격대로 두 층**으로 나눈다.

### 1층 — 매일 자동 갱신 (공공 API 있는 것만)
- 소고기 부위(한우 등 촘촘), 돼지 삼겹살·목살, 농산물 등.
- 소스: 축평원 / KAMIS 오픈API. 코드탭이 크론으로 자동 수집.
- "매일 갱신 시세표" 콘셉트는 이 층이 지탱한다.

### 2층 — 참고가 (공공데이터 없는 것)
- 돼지 특수부위(앞다리·뒷다리·항정살·갈매기살·가브리살 등), 수입육.
- **"참고가 · 월 갱신 기준" 라벨 필수.** 매일 갱신하는 척하면 안 됨.
- 숫자는 쿠팡 실판매가 또는 웹서칭 기준(국산 부위별). "국산 기준" 등 기준 명시.
- 결정: 이 특수부위들은 **빼지 말고 "참고가"로 남긴다** (검색 유입 위해).

### 팩트
- 소고기는 공공데이터가 촘촘하지만 **돼지 특수부위는 공공데이터에 없음 = 어쩔 수 없는 부분.**

## 3. 레시피 전략

### 3-1. 왜 레시피를 넣나 (핵심 논리)
- **레시피 = 검색 유입 미끼.** "후라이드 치킨 레시피/만드는 법" 검색량이 "원가" 검색량보다 훨씬 크다.
- 동선: 레시피 검색 유입 → 원가 확인 → 재료 시세 → 프랜차이즈 가격비교 → **쿠팡에서 재료 구매**.
- 원가·시세만으론 검색량이 적어 사람이 안 온다. 레시피가 사람을 끌어오는 미끼.
- 대표님 "체류시간 끌기 / 네비게이션 꼬기" 전략과도 일치.

### 3-2. 내부 링크 (미끼를 돈으로 바꾸는 장치 — 필수)
각 레시피 하단에 통일된 링크 세트:
- "이 메뉴 원가율 보기 →" (원가 페이지)
- "○○ 프랜차이즈 가격비교 →" (가격비교 페이지)
- "재료 시세 보기 →" (시세 페이지)
→ 이게 없으면 레시피만 보고 그냥 나간다.

### 3-3. 차별화 — 제목을 "원가/가성비" 각도로
- 만개의레시피·백종원이랑 "레시피" 정면승부는 힘들다. 우리 무기는 **원가**.
- 제목 공식: **"[메뉴] 원가, 집에서 만들면 얼마? (레시피)"** 각도.
- 예:
  - "후라이드 치킨 원가, 집에서 만들면 얼마? (레시피 + 재료값)"
  - "양념치킨, 사 먹기 vs 집에서 만들기 원가 비교"
  - "떡볶이 1인분 원가, 얼마나 남을까? (간단 레시피)"

### 3-4. 레시피 소스 — 자체 생성
- 공공 레시피 API는 별로: 식약처 COOKRCP01(빈약), 농정원(적고 오래됨).
- **만개의레시피 사이트 긁기 = 저작권 위반. 절대 금지.**
- (참고: KADX에 만개의레시피 데이터셋 있으나 상업 재배포 라이선스 미확인 — 쓰려면 조건 확인 필요.)
- **결론: Gemini/ChatGPT로 자체 생성.** 우리 원가 데이터와 연결해 "우리 콘텐츠"로 만든다.

### 3-5. 레시피는 반드시 "텍스트"로 (SEO 생명줄 — 가장 중요)
- 만드는 법을 **이미지로 넣으면 구글이 글자를 못 읽어서 "레시피 검색"에 안 걸린다** → 유입 전략이 통째로 죽는다.
- **제목만 텍스트도 부족.** 본문(만드는 법)이 텍스트여야 순위가 올라간다. (제목만 있으면 5페이지에 묻힘 = 유입 0)
- 페이지에 원가·시세 글이 많아도, 그건 "원가" 검색용이지 "레시피" 검색용이 아니다. 만드는 법 글이 따로 텍스트로 있어야 레시피 검색을 잡는다.
- **원칙: 텍스트(만드는 법) + 이미지(완성 사진) 둘 다.** 구글은 텍스트를 읽고, 사람은 이미지를 본다. 하나도 안 버림.
- 레시피 카드(글 박힌 이미지)는 **쓰레드·인스타 홍보용으로만.** 사이트 안에는 텍스트.
- 삽입 노동 걱정 X: ChatGPT 레시피 텍스트를 **코드탭이 자동 파싱해서 페이지에 꽂는다.** 대표님은 사진만 얹으면 됨.

## 4. 이미지

### 4-1. AI 이미지 — 손 안 나오게
- AI는 손을 제일 못 그린다(손가락 6개 등). 과정 사진에 손 나오면 어색해짐.
- **해법: 손 안 나오는 구도로 생성.** ① 재료 위에서 내려다본 플랫레이 ② 튀김냄비 클로즈업 ③ 완성 접시.
- (후라이드 치킨 테스트 결과: 손 없음·스타일 통일·실사 느낌 잘 나옴 → 이 방식 검증됨.)

### 4-2. 워터마크
- **Gemini 앱** = 눈에 보이는 워터마크 박힘 (문제).
- **ChatGPT** = 눈에 보이는 워터마크 없음(메타데이터 표식만) → 웹에 바로 쓰기 깔끔.
- **Gemini API(유료)** = 대체로 보이는 워터마크 없음(미확인, 쓰려면 실제 확인 필요).

### 4-3. 완성 사진은 무료 스톡 API도 가능
- Unsplash / Pexels API로 "양념치킨" 등 검색 → 자동으로 받아 페이지에 삽입 가능.
- 장점: 공짜, 워터마크 없음, 진짜 사진(AI보다 먹음직스럽고 신뢰↑), 자동화(퍼나르기 X).
- 조건: 사진작가 출처 표기 + 호출 제한 준수 (코드탭이 규칙 맞춰 구현).
- **한계:** 한 요리의 과정 사진 세트(같은 스타일 4~5장)는 API로 못 맞춤.
  → 과정 사진은 히어로 레시피 몇 개만 직접(대표님이 실제 요리 가능), 나머지는 완성 사진 1장.

## 5. 대량 생성 판단

- 얼마남아는 원가·시세 데이터가 메인 → **대량 레시피 OK.** (순수 블로그였던 방구석약국과 다름. scaled-content 위험 낮음.)
- **단 3가지 조건:**
  1. 원가와 연결해 "우리 것"으로 만든다 (generic AI 레시피 아님).
  2. 이미지는 전부 말고 선별 (이미지가 진짜 병목).
  3. 원가 함정은 로직으로 한 번에 처리 (아래 6번).
- ChatGPT Go로 30개씩 배치 생성 가능. **한 번에 왕창 dump보다** 원가 연결 + 꾸준히.
- 우선 소수(첫 배치)로 애드센스 통과·반응 확인 후 확장 (검증 우선 원칙).

## 6. 원가 계산 함정 (코드탭 로직에 반드시 반영)

- **튀김기름 등 "재사용 재료"는 전량 원가 아님.** 실제 흡수되는 흡유량(보통 10~15%)만 반영하거나 별도 처리.
  (식용유 1.5L를 통째로 원가에 넣으면 후라이드 치킨 원가가 2만원대로 폭등.)
- 이 규칙을 계산 로직에 한 번 넣으면 레시피가 100개든 1,000개든 자동 적용됨.
- 지육 나누기 함정과 같은 맥락 — 원가는 이런 함정이 계속 나오니 로직으로 방어.

## 7. 쿠팡 파트너스 — 표시 의무 (법적)

- 쿠팡 링크가 들어가는 페이지엔 **"이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다"** 문구 의무 (공정위 표시광고법).
- 재료·쿠팡 버튼 근처에 배치.
- 애드센스 "광고" 라벨과는 별개(둘 다 필요).
- (참고: 쿠팡 API는 15만원 실적 전까지 없음 → 지금은 검색 링크(추적ID)로 진행.)

## 9. Pending 얼마남아 UI 수정 배치 (코드탭에 한 번에 지시)

- 메뉴명 크게 / 프랜차이즈명 작게
- 카테고리 일관성 (핫도그 = 명랑핫도그만, 피자 = 기본 종류, 보쌈 = 족발 제외 등)
- "요리 35종 전부 비교" 버튼 삭제 → 원가율/재료로 대체
- 원가율 순위 10개 페이지네이션
- 프랜차이즈 가격비교: 참고용 문구 추가, "배율" 열 삭제, "판매가" 표기
  (※ 탭은 유지 — 체류시간 전략)
- 재료 버튼에 쿠팡 파트너스 검색 링크(추적ID) 삽입
- 재료 표 여백 + PC 가운데 정렬, 광고 미노출 시 빈 영역 접기, 시세 갱신시각·기준일 표기, 필터 칩 5분류

## 10. ChatGPT 레시피 생성 프롬프트 (검증됨 — 후라이드 치킨 테스트 성공)

```
너는 한국 요리 콘텐츠 에디터야. 원가·재료 정보를 다루는 사이트에 올릴 레시피를 만든다.

"[메뉴명]"을 집에서 쉽게 따라 할 수 있는 간단 레시피로 만들어줘.
- 특별한 도구나 구하기 어려운 재료는 빼고, 마트에서 쉽게 구하는 재료로.
- 단계는 최대한 적게, 복잡한 과정은 생략해서 초보도 부담 없이 하게.

아래 형식으로 작성해줘.

[1] 재료 (2인분 기준)
- 모든 재료를 정확한 분량(g, ml, 개, 큰술)으로. 원가 계산에 쓸 거라 분량이 정확해야 해.
- 재료를 [주재료 / 튀김옷(또는 양념) / 밑간·부재료]로 구분해줘.

[2] 만드는 법
- 단계별 번호로, 되도록 5~6단계 안으로 간단하게.
- 각 단계 1~2문장, 요리 초보도 따라 할 수 있게.
- 온도·시간을 구체적으로.

[3] 실패 안 하는 팁 3가지

※ 가격·원가는 절대 쓰지 마. 그건 우리 사이트 자체 시세로 계산할 거라, 네가 추정해서 넣으면 안 돼.

그리고 이 레시피에 어울리는 실사 느낌 이미지 3장을 생성해줘. 조건:
- 손·사람이 절대 나오면 안 됨.
- ① 손질된 재료를 위에서 내려다본 플랫레이 ② 조리 중 클로즈업 ③ 접시에 담은 완성컷
- 3장 모두 같은 배경(밝은 나무 도마/식탁)과 따뜻한 조명으로 스타일 통일.
- 일러스트 말고 사진처럼.
```

프롬프트 주의: 가격은 일부러 빼게 함(ChatGPT가 원가 추정하면 틀린 숫자를 자신있게 뱉음 → 원가는 우리 시세로 계산). 무료 tier는 이미지를 하나씩 줄 수 있음.
