## 1-2. 🥇 우선순위가 바뀌었다 (2026-07-31 저녁)

대표 결정 — *"일단은 원가 생각하지 말고 메뉴판을 생각하자. 메뉴판이 SEO랑 우리 트래픽에
분수령이야 … 원가는 지금 검색량 얼마 되지도 않아"*

**① 메뉴판 가격 채우기 → ② 검색량 큰 브랜드 늘리기 → ③ 그다음 원가**

- 게이트 B(원가 감사 60건)는 **뒤로 미룬다.** `menu_audit.py` 는 만들어뒀으니 나중에 돌리면 된다
- 브랜드를 켜고 끄는 기준은 **월 검색량**. 가맹점 수가 아니다
  (2026-07-31: 검색량 낮은 15곳 삭제 · 검색량 높은 12곳 수집 지시)
- ⛔ 「원가를 못 낸다」 는 이유로 브랜드를 내려두지 않는다 — 메뉴판만으로 페이지 값어치가 있다

## 2. 완성의 정의 — 게이트 3개

- **게이트 A (메뉴판):** 93곳 전부 골격 있음 + 가격 채움률 90%↑.
  못 채운 곳은 「가격 확인 중」으로 정리돼 있으면 통과 — **가격 0은 실패가 아니다. 지어내는 것만 실패다.**
- **게이트 B (원가):** 감사 60건 전부 «조사 완료(반영 또는 근거불충분으로 유지)» 처리.
  `python scripts/menu_audit.py` 가 0건이 되거나, 남은 건마다 사유가 적혀 있으면 통과.
- **게이트 C (배포):** `publish.py --apply` 가 라이브 확인까지 ✅.

계산기는 이 DB(menus·menu_ingredients·ingredients)를 **읽기만** 하고,
로그인은 그 위에 붙는다. 그래서 게이트 전에 구조 동결.

## 3. 🔄 역할 분담이 바뀌었다 (2026-07-31 저녁)

**수집기 세션을 없앴다.** 대표 지시 — *"데이터 수집기 없애고 너가 수집해서 1개씩 진행할꺼야.
그게 정확하고 빠를거 같아. 한번에 하면 백그라운드에서 실수가 너무 많이 나면 어짜피 다시해야해"*

```
한 세션이 전부 한다 — 브랜드 **한 곳씩**
   수집 → brand_menu_import.py --apply → 눈으로 확인 → 다음 브랜드
   마무리로 publish.py --apply --menu-only
```
- ⛔ **여러 브랜드를 한꺼번에 몰아치지 않는다.** 오매칭·쓰레기 적재가 생기면 되돌리는 게 더 비싸다
- 수집 방법·순서: `수집순서-확정로직.md` / 가격은 `가격수집-4단계순서-2026-07-31.md`
- 원가 조사는 뒤로 미뤘다(§1-2)

## 4. 🔥 토큰 규칙 — 수집은 «필요할 때만»

1. **수집 트리거는 셋뿐.** ①이 문서 G1~G3/G5 에 있는 브랜드 ②JSON↔DB 차이가
   `brand_status.py` 에 뜬 브랜드 ③대표가 이름 집어 지시한 브랜드. **그 외 재수집 금지.**
2. **순서 지키면 화면스캔까지 갈 일이 거의 없다.** 가격의 87%가 웹에서 나왔다.
   앱 화면 판독은 `detect()` 판정 후 uiauto 일 때만. **스샷 하나하나 비전 판독 금지.**
3. **스크립트를 새로 짜지 않는다.** 서랍에 97개 있다(`수집순서-확정로직.md` §스크립트 서랍).
   범용 5종: `brand_status` / `brand_menu_import` / `publish` / `brand_board_reset` / `menu_audit`.
4. **막히면 30분 안에 보고하고 다음 브랜드로.** 한 브랜드에 매달려 태우지 않는다.
   보고 형식: «브랜드 · 시도한 단계(1~5) · 막힌 증상 한 줄».
5. **공통모듈(`app_menu_reader.py` 등)은 복사해 쓰되 직접 고치지 않는다** — 증상만 보고.

## 5. 원가 검증 파이프라인 (2026-07-31 신설 — G4 처리 방법)

```
python scripts/menu_audit.py --md        # ← 의심 메뉴 자동 감사 → 조사 목록 MD 생성
   R1 원가율 낮음(업종별 기준: 일반12·피자8·카페6% 미만)
   R2 재료 2개 이하   R3 메뉴명 재료가 목록에 없음 (시래기국에 시래기 없음 류)
        ↓
조사 세션: 목록의 메뉴마다 웹서칭 (검색어: "브랜드 메뉴명 구성" / "메뉴명 레시피 1인분")
        → 빠진 재료·양(g)·근거URL 을 목록 칸에 채움. 근거 없으면 «근거불충분» 이라 쓰고 넘어감
        ↓
등록 세션: 채워진 칸 확인 → menu_ingredients 반영 → compute_line_costs → publish
        ↓
python scripts/menu_audit.py             # 다시 돌려 0건 확인 (게이트 B)
```
실제 사고가 근거다: 시래기국에 시래기 없음 · 빙수에 피자치즈 · 지코바 소금구이 —
전부 원가율이 낮거나 이름-재료가 어긋나 있었다. 이제 우연이 아니라 규칙으로 잡는다.
