```

├─ [버튼] categories.html ── 카테고리 13 → cat_{slug} → 브랜드 87 → menu_{id}  ← 매장 원가율(도매)

python scripts/gen_schema.py         # ★ 스키마 바꿨으면
python scripts/build_dist.py         # ★ _preview → _dist (검수용 _* 제외)

python scripts/healthcheck.py        # 🔴 48종 전수점검 — 반드시
```

### 🔴 지켜야 할 5가지 (전부 실제로 터진 것)
1. **계산은 한 곳에서만** — 도매 라인가격은 `compute_line_costs.py`가 `menu_ingredients.wholesale_cost`에 저장하고 렌더러는 **읽기만**. 화면에서 다시 계산하면 반올림 2회로 표 합계와 헤드라인이 어긋난다.
2. **상수는 한 곳에서만** — 배포 주소는 `scripts/site_config.py`가 `wrangler.toml`의 `SITE_ORIGIN`을 읽는다. 4곳에 박았다가 canonical 488개가 없는 도메인을 가리킨 적 있다.
3. **커서 재사용 금지** — 루프 안에서 또 쿼리하면 `.fetchall()` 필수 (prices.html 47종→2종 사고).
4. **"누가 쓰는가"를 DB 안에서만 찾지 말 것** — dish 레시피는 `gen_dishes.py`의 **하드코딩 DISHES 리스트**에 있다. DB만 보고 재료를 지웠다가 요리사전 35개가 죽었다.
5. **`schema.sql`은 자동생성** — `python scripts/gen_schema.py`. 손으로 관리하다 dish 4테이블 + 원가 컬럼 11개가 빠진 채였다(그대로 D1 시딩했으면 요리사전·매장원가가 죽었다).

1. **"카테고리는 브랜드잖아"** — 홈의 `[카테고리]` 버튼을 누르면 브랜드 목록이 나온다. 이름≠내용.
   → **"브랜드별 찾기"**로 바꿔야 함.
2. **"메뉴별 원가사전이 안 보인다"** — dish 축(짜장면·김치찌개로 찾기)이 3번째 버튼에 묻힘.
   일반인에겐 "짜장면 원가"가 브랜드보다 먼저 떠오르는 **더 직관적 입구**인데 순서가 거꾸로.
   → dish 축을 위로, 더 크게.
3. **"복잡하다"** — 메뉴 상세에 카드가 3겹(요약 pcard → `<details>` 설명 → 재료구성).
   막대(pcard)는 개선됐으나 층이 여전히 많음.
