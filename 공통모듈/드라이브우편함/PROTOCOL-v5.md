주제: 통신 프로토콜 v5 — watcher 상시 감시 + 깨움 신호

# PROTOCOL v5 (정본)

v1·v2·v3·v4 전부 폐기. **이 문서만 정본.**
v4에서 보강: ①watcher 상시 감시 프로세스 ②깨움 신호(WAKE.md + 알림)

## 0. 전제 (바뀌지 않음)
- 웹 Claude는 한 턴 안에서는 여러 번 도구를 부를 수 있으나, 턴이 끝나면 멈춘다.
  사용자가 말을 걸어야 다시 깨어난다.
- 코드탭도 20분 타임아웃에 걸려 끊긴다. 자체 재기동 불가.
- **따라서 상시 살아있는 주체는 watcher 스크립트뿐이다.**
- 목표: "끊기지 않게"가 아니라 **"끊겨도 놓치지 않게 + 깨워야 할 때 알려주게"**

## 1. 3주체 역할

| 주체 | 살아있는 시간 | 하는 일 |
|---|---|---|
| watcher.mjs | **상시** (백그라운드) | 폴더 감시, 알림 발송, 정형 작업 자동 실행 |
| 코드탭 | 호출될 때만 | 판단이 필요한 구현, 렌더, 디버깅 |
| 웹 Claude | 사용자가 부를 때만 | 전략 판단, 기획서 작성, 회신 |

watcher는 **판단하지 않는다.** 감지·알림·정형 실행만.

## 2. watcher.mjs 스펙 (코드탭이 구현)

위치: 프로젝트 루트. 실행: `node watcher.mjs`
윈도우 작업 스케줄러에 등록 → PC 부팅 시 자동 시작.

**30초마다 반복:**

1. 통신 폴더(G:\내 드라이브\sajangpick\) 스캔
2. 새 `회신NN.md` 발견 → PENDING.md에 추가 + WAKE.md에 `CODE_NEEDED` 기록 + 알림
3. `요청NN.md`이 20분 넘게 회신 없음 → WAKE.md에 `WEB_NEEDED` 기록 + 알림
4. 회신 안에 `AUTO_RENDER: 001` 지시자가 있으면 → 렌더 직접 실행 (판단 불필요한 정형 작업)
5. WATCHER_HEARTBEAT.md 갱신 (watcher 자신의 생존 표시)

**알림 2채널:**
- 데스크톱: 윈도우 토스트 (node-notifier 또는 PowerShell BurntToast)
- 폰: 텔레그램 봇 API (`https://api.telegram.org/bot<TOKEN>/sendMessage`)
  → 봇 토큰·chat_id는 사용자에게 요청 (요청NN으로 올릴 것, 비용 없음)

알림 문구는 **누굴 깨워야 하는지만** 짧게:

    [사장픽] 웹 확인 필요 — 요청03 20분 경과
    [사장픽] 코드탭 확인 필요 — 회신03 도착

## 3. WAKE.md — 깨움 신호판 (watcher가 갱신)

    UPDATED: 2026-07-22 12:34
    WEB_NEEDED: 03          ← 웹이 답해야 할 요청 번호 (없으면 -)
    CODE_NEEDED: -          ← 코드탭이 처리해야 할 회신 번호 (없으면 -)
    WATCHER_ALIVE: yes

사용자는 이 파일 한 줄만 보면 누굴 깨울지 안다.
처리되면 watcher가 자동으로 `-` 로 되돌린다.

## 4. 파일명 — 완전 고정. 슬러그 금지. (v4에서 유지)

    요청00.md ~ 요청09.md      ← 코드탭 → 웹
    회신00.md ~ 회신09.md      ← 웹 → 코드탭

- 주제는 **파일 안 첫 줄**에 쓴다. 파일명에는 절대 넣지 않는다.
- 요청NN의 답은 반드시 회신NN.
- 이 형식 외의 파일명은 통신으로 인정하지 않는다.
- 번호는 00~09 순환. 활성 파일 최대 20개.
  같은 번호 재사용 전에 이전 쌍을 archive/로 이동 (`요청04_20260722.md`).

## 5. 고정 파일 목록

| 파일 | 쓰는 쪽 | 용도 |
|---|---|---|
| WAKE.md | watcher | 깨움 신호 |
| PENDING.md | watcher | 코드탭이 처리할 대기 목록 |
| WATCHER_HEARTBEAT.md | watcher | watcher 생존 표시 |
| INDEX.md | 코드탭 | 통신 현황 (NEXT_REQ, LAST_HANDLED_REPLY, OPEN) |
| STATE.md | 코드탭 | 작업 상태 + HEARTBEAT |
| WORKLOG.md | 코드탭 | 작업 기록 (append only) |
| COMMLOG.md | 코드탭 | 통신 기록만 |
| DATA.md | 사용자/코드탭 | 업로드 성과 |

## 6. 재개 절차

**코드탭이 재개될 때:**
1. PENDING.md 읽기 → 밀린 회신 전부 순서대로 처리
2. INDEX.md·COMMLOG.md·STATE.md 갱신
3. 처리 완료분은 PENDING.md에서 제거

**웹이 깨어날 때:**
1. WAKE.md → 누가 뭘 기다리는지
2. INDEX.md → 통신 현황
3. STATE.md HEARTBEAT → 코드탭 생사
4. OPEN 번호에 회신 작성

## 7. 판단 라우팅 — 사용자에게 묻는 것은 셋뿐
1. 배포·업로드 승인
2. 돈이 드는 일
3. 사업·법적 정체성 판단

그 외 **모든** 판단은 요청NN으로 웹에 보낸다.
기술 선택, 대본 수정, 규격 변경, 우선순위 — 전부 웹이 결정한다.

## 8. 자율 진행 규칙
- 대본이 규격(20~30초) 초과 → 장면 수 줄여 자동 축약, WORKLOG 기록
- 제품 이미지 없음 → 텍스트·색배경 렌더 (#F97316 / #1A1A1A / 흰 배경)
- 렌더 실패 → 3회 재시도, 실패 시 다음 기획서로 넘어감
- inbox 비면 → 대기 전환, STATE.md 갱신 후 정지
- 라이브러리·경로·빌드 등 순수 기술 이슈 → 직접 해결. 질문 금지.
- **회신이 20분 내 안 오면 → 자율 판단해 진행. 멈추지 않는다.**
