## 2. 데이터 보안 (Data safety) 답안

⚠ 실제 코드·DB 기준으로 뽑았습니다. **틀리게 신고하면 나중에 앱이 내려갑니다.**

### 수집하는 것

| 항목 | 어디에 | 목적 | 필수? |
|---|---|---|---|
| 아이디 · 비밀번호(해시) | `accounts` / `auth_methods` | 계정 | 필수 |
| 휴대폰 번호 | `accounts.phone` | 비밀번호 찾기 | 필수 |
| 이메일 (소셜 로그인 시) | `accounts.email` | 계정 | 선택 |
| 보호자 이름(표시명) | `accounts.display_name` | 서식·화면 표시 | 선택 |
| 자녀 별명 · 학년 · 반 · 출생연도 | `children` | 학교 정보 연결·미션 배정 | 필수 |
| 자녀가 다니는 학교 | `children.school_id` | 급식·시간표 | 필수 |
| **자녀가 올린 사진** | R2 `RECORDS` 버킷 | 부모 확인 · 기록 보관 | 선택 |
| 커뮤니티 글 | `community_posts` | 같은 반 학부모 대화 | 선택 |
| 푸시 구독 정보 | `push_subscriptions` | 알림 | 선택 |
| 결제 내역(금액·기간) | `payments` | 이용권 | 결제 시 |

- 광고 식별자(현재 광고 없음)

### 처리 방식

- 사용자가 삭제 요청 가능: **예** (탈퇴 시 3개월 유예 후 삭제)

## 4. 🔴 타깃 연령층 — 먼저 정할 것

자녀 앱은 **초등학생이 직접** 씁니다. 신고 방법이 둘로 갈립니다.

**A안 — 「만 13세 이상 + 아동」 혼합 (Families 정책 적용)**
- 아동용 앱으로 분류됩니다. 광고 SDK 제한, 아동 데이터 처리 고지, 부모 동의 명시 필요
- 우리는 광고가 없고 부모 동의(`consent_at`)를 이미 받고 있어 **맞추기 어렵지 않습니다**
- 대신 심사가 깐깐하고 Families 정책 위반 시 즉시 내려갑니다

**B안 — 「만 13세 이상(보호자용)」**
- 자녀 폰은 「보호자가 설정해 준 기기」라는 논리
- 심사는 가볍지만, 실제로 아동이 쓰는 게 드러나면 **나중에 문제가 됩니다**

→ 제 의견은 **A안**입니다. 실제로 아이가 쓰는 앱이고, 광고가 없어서 Families 요건 대부분을
  이미 만족합니다. 숨기고 가다 내려가는 게 제일 나쁩니다.
