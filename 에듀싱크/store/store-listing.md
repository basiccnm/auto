⚠ 실제 코드·DB 기준으로 뽑았습니다. **틀리게 신고하면 나중에 앱이 내려갑니다.**

### 수집하는 것

| 항목 | 어디에 | 목적 | 필수? |
|---|---|---|---|
| 아이디 · 비밀번호(해시) | `accounts` / `auth_methods` | 계정 | 필수 |
| 휴대폰 번호 | `accounts.phone` | 비밀번호 찾기 | 필수 |
| 이메일 (소셜 로그인 시) | `accounts.email` | 계정 | 선택 |

## 4. 타깃 연령층 — ✅ **혼합(부모 + 자녀) 확정** (대표님 2026-08-13)

**아동 «전용»이 아니다.** 주 사용자는 부모이고, 아이는 **부모가 열어준 문으로만** 들어온다.
그래서 대상 연령에 **성인과 아동을 함께** 신고한다(mixed audience).

콘솔에서 고를 때 이렇게 답한다.
- 대상 연령층: **만 13세 이상 + 만 13세 미만 함께 선택**
- 「주로 아동을 대상으로 하나요」 → **아니오** (부모용 앱이고 자녀 기능이 딸려 있다)
- Families 정책은 적용된다 — 아동이 쓰는 화면이 있기 때문. **부모 동의는 면제 사유가 아니라 요구 사항**이다

### 우리가 이미 만족하는 것 (심사에서 이대로 설명하면 된다)

| 요건 | 우리 상태 | 근거 |
|---|---|---|
| 광고 SDK 제한 | **광고 없음** | 앱에 광고 코드 자체가 없다 |
| 부모 동의 확보 | **받고 있음** | 자녀 등록 시 `children.consent_at` 기록 |
| 아동이 결제에 닿지 않을 것 | **닿지 않음** | 자녀 토큰은 `#pay` 접근 불가 → 아이 홈으로 튕김 |
| 아동이 UGC 에 닿지 않을 것 | **닿지 않음** | 학부모 커뮤니티는 자녀 토큰 접근 불가 |
| 아동 화면에 실제 화폐 없음 | **별(★)만** | 아이 상점은 별을 쓴다. 돈이 나오지 않는다 |
| 아동 단독 사용 불가 | **부모 발급 6자리 코드 필요** | 코드 없이는 자녀 앱이 아무것도 못 한다 |

기술 근거: `app/www/app.js` 의 `CHILD_SCREENS` 화이트리스트 —
자녀 토큰은 목록에 없는 화면으로 가면 `#game`(아이 홈)으로 되돌려진다.

### 아동 기준으로 추가로 챙길 것
- [ ] 개인정보처리방침에 **아동 개인정보 항목**을 따로 구획해 적기
      (수집 항목 · 부모 동의 방법 · 부모의 열람/삭제 요구 방법)
- [ ] 데이터 보안 양식에서 **아동 데이터 수집**을 숨기지 말 것 —
      자녀 별명·학년·반·출생연도·사진은 **수집한다고 그대로** 신고
- [ ] 자녀 실명은 **기기에만** 저장한다는 점을 정책 문서에도 한 줄 명시
