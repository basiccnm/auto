## 1. 부모 앱 디자인 — 시안 D 확정

| 바뀐 것 | 왜 |
|---|---|
| 시안 A·B·C(텍스트 목록형) **폐기** | 「읽는 화면」이라 기존과 차이가 없었다. 사장님: 「보는 화면」이어야 한다 |
| 시안 ①원색 폐기, **D 확정** | 토스풍 중립. 흰 바탕 + 연회색 보조 + **파랑 하나** |
| 종류별 색(급식 주황·시간표 파랑…) **전면 폐기** | 색으로 뜻을 나누면 상태색(빨강·초록)과 충돌한다. 아이콘·글자가 뜻을 진다 |
| 빨강은 **「부모가 지금 눌러야 할 것」 전용** | 벨·대화 뱃지까지 빨강이면 진짜 급한 게 안 보인다 → 뱃지는 파랑으로 내림 |
| 챙길것 배너 빨강 → **중립 배경 + 점 하나** | 같은 이유. 빨강은 미션 확인 대기에만 |

**칠하는 색 ≠ 그 색으로 쓰는 글씨** — 점·뱃지 면은 쨍해도 되지만 같은 값으로 12~13px 글씨를
쓰면 연회색 위에서 4.5:1 아래로 떨어진다(감사에서 4건 적발). 그래서 `--todo-ink` 같은
**-ink 짝**을 따로 둔다. 다크는 바탕이 어두워 둘이 같은 값이어도 통과한다.

## 2. 테마 6종 → 2종

- 조약돌·안개·모래·흑연·심야·재 → **밝게 / 어둡게**
- **옛 키를 지우지 않고 새 두 벌에 매달아 뒀다**(style.css 선택자에 함께 나열).

  여러 화면이 번호로 참조 중이라 이름을 지우면 그 화면들이 무너진다.

## 3. 하단 탭바 부활 (7/24 폐지 → 8/2 복원)

- **홈 / 일정 / 미션 / 서랍 / 내정보** 5칸. 가운데 ＋ 원은 뺐다(부팅 중 그것만 3~5초 떠 있었다)
- 서식·설정은 **내정보 안으로**, 일정(달력)은 **탭으로 승격**
- `#calendar` 는 학교 화면의 일정 탭을 그대로 연다 — **달력을 두 벌 만들지 않는다**
- ⚠ 탭바가 돌아오면서 **일정 탭의 ＋ FAB 가 탭바 밑에 깔렸다**(bottom 고정값이 탭바를 몰랐다).
  같은 함정이 또 있을 수 있다 — `position:fixed; bottom:` 은 전부 `--tabbar-h` 를 더해야 한다

## 4. 홈 = 「보는 화면」

- 오늘 큰 카드 3장(급식 / 하교·방과후 / 내일 준비물) → **가로 캐러셀 한 자리**
- **미션 도장판이 홈의 주인공** — 진행률 + 도장 3칸 + 확인 대기 줄
- 격자는 5개로 축소, 라벨은 **2~4자 명사**(알림/방과후/체험학습/학교정보/커뮤니티)
- 급식 없는 날(주말·공휴일·방학)은 **캐러셀에서 급식 카드를 통째로 뺀다**
  - ⚠ 이때 저녁 자동 스냅 인덱스를 고정값(2)으로 두면 어긋난다 → 실제 인덱스로 계산
- 저녁(19시~) 미체크 준비물 → 상단 **단일 슬롯**(챙길것 > D-day). 둘을 겹치면 800px를 넘었다

## 5. 자녀 앱 테마 2종 (파스텔 / 퀘스트)

- 원색안 폐기. **파스텔**(전학년) / **퀘스트**(차콜 + 금별) 둘
- 퀘스트는 **색 스킨이 아니라 별도 정체성** — 「오늘의 퀘스트」·「도전」·「클리어!」,
  도장판이 격자가 아니라 **「별의 길」 곡선 경로 지도**
- 용어 사전 `KID_WORDS` — 퀘스트=**별**, 파스텔=**도장**. 화면마다 삼항을 심으면 빠뜨린다
- 포인트 색은 테마별 3종 중 아이가 고른다. **파랑 계열 없음**(부모 앱과 갈리게)
- **자녀 화면에는 빨강을 쓰지 않는다** — 「보냈어요!」는 경고가 아니라 안내다

## 6. 급식 평가 미션 — 네 번 뒤집힌 결정 ⚠

이 기능은 이 세션에서 **네 번 설계가 바뀌었다.** 되돌리지 않도록 이유를 남긴다.

| 판 | 무엇 | 왜 뒤집혔나 |
|---|---|---|
| 1판 | 이모지 3단 + 선택 칩, **부모 대화로 자동 전송** | — |
| 2판 | 역할 분리(말=기존 대화채널 / 평가값=새 API) | 말을 만드는 주체가 서버·앱 둘이라 진실이 둘이었다 |
| 3판 | **부모 전송 폐기.** NPC 미션 + 별5 + 맛있는 순 정렬 | 사장님: 이건 부모와 이야기할 게 아니다. **부모 앞에서 말하는 게 아니라 혼자 고르는 것이라 「오롯한 자기 의지」가 남는다** |
| 4판 | **별5 + 제일 맛있던 것 하나.** 탭 두 번 | 어른 기준이었다. 메뉴가 위아래로 두 번 나오고, 다섯 개를 순서 매기는 건 여덟 살에게 숙제다. 3~5등은 대충 찍어서 데이터도 지저분해진다 |

**지금 확정:** 아이는 **별 5개 + 제일 맛있던 것 하나**만 고른다. 즉시판정(사진·기다림 없음).
자녀 화면에 통계·리포트는 **없다** — 아이한테 지난달 취향은 관심 밖이다.

### 데이터 설계 (리포트의 재료)
- `meal_ratings`(하루 1회 UNIQUE, stars 1~5) + `meal_rating_items`(dish_raw / dish_key / dish_cat / rank)
- **원문(dish_raw)을 절대 버리지 않는다.** 합치는 사전은 쌓인 식단표를 실제로 훑어야 좋아진다.
  그때 원문에서 다시 계산하려면 원문이 살아 있어야 한다. 지레짐작으로 묶으면 **잘못 묶인
  데이터가 쌓여 되돌리기 더 어려워진다**
- **종류(dish_cat)를 같이 쌓는 이유** ← 이게 핵심이다.
  급식은 주 5일 × 5품 = 25품인데 **반복되는 건 밥·김치 정도**고 메인 반찬은 거의 안 겹친다.
  개별 메뉴 순위만으로는 한 주에 표본이 안 된다. 종류(볶음·국물·튀김·나물·김치·주식)로 묶어야
  **「볶음을 좋아하고 나물을 싫어한다」가 한 주 만에 나온다**
- 분류는 **이름 끝 규칙**. 「볶음밥」이 볶음으로 새지 않게 **주식을 먼저 본다**(순서 중요)
- 개별 메뉴 순위는 **2회 이상 나온 것만** 리포트에 올린다. 표본 수를 항상 병기한다 —
  안 그러면 한 번짜리를 부모가 사실로 믿는다. 주식(밥)은 매일 나와 고정이라 순위에서 뺀다

### 부모는 월 1회 리포트로
매일 들여다보게 만들 필요가 없다. 로드맵의 **블록3 「1년 돌아보기 리포트」가 첫 유료 실험
후보**인데, 급식 리포트가 **그 축소판이자 첫 조각**이다. 「매달 뭔가 나온다」를 미리 증명한다.

## 7. 자녀폰 연결 구멍 2건 (수정 완료)

- **미연결 + 아직 안 찍은 사진 미션** → 부모 홈·미션에 경고 한 줄 + 연결하기

## 8. 정리 3단계 (기능 미완 잔재 처리)

| 단계 | 무엇 | 왜 |
|---|---|---|
| 1 | 아이의 「봤어요」를 서버까지 | 로컬 변수만 바꿔서 **부모 앱엔 영원히 「보냄」**으로 남았다 |
| 2 | 급식 평가 역할 분리 | (3판에서 폐기됨 — 부모 전송 자체가 사라짐) |
| 3 | `addStars()` 호출 | 서버가 별을 `star_ledger` 로 집계하는데 안 적어서, 앱이 +1 해놓고 새로고침하면 되돌아갔다 |

**⚠ 어제 보고한 「같은 말이 두 번 뜬다」는 오진이었다.** `loadLife()` 가 `STUB.notices` 를
통째로 교체하므로 겹쳐 남지 않는다. 진짜 문제는 `.catch(()=>{})` 로 실패를 삼킨 것이었다.

## 9. 일일 퀘스트 3개 — 「DB가 쌓이는 미션」의 완성형

급식 평가가 잘 돌자 **같은 틀로 둘을 더** 만들었다. 셋 다 «고르기만 → 즉시 별 → 한 달 뒤 리포트»다.

| 미션 | 재료를 어디서 | 왜 이것인가 |
|---|---|---|
| 오늘 급식 평가 | 이미 받는 식단표 | 맞고 틀림이 없다. 아이가 손해 볼 수 없는 질문 |
| 오늘 누구랑 놀았어? | 아이가 직접 입력(칩으로 재사용) | **부모가 제일 모르는 것.** 애들은 이런 걸 말하지 않는다 |
| 오늘 제일 재밌었던 건? | 이미 받는 시간표 | 성적표는 «잘하는 것»을 알려준다. 이건 «재밌어하는 것» |

**친구 이름은 실명으로 받는다.** 한때 「개인정보」라며 «몇 명이랑 놀았어»로 바꾸자고 했는데
**틀린 판단이었다.** DB 절대규칙 1은 *우리 이용자*의 이름을 기록·일정에 넣지 말라는 것이고,
아이가 말하는 친구 이름은 **이름 석 자뿐** — 성별도 연락처도 학교도 없다.
그리고 «몇 명»은 이 기능의 값어치를 통째로 없앤다. 되돌리지 말 것.

**표본이 작은 건 정상이다.** 한 반 30명, 같은 성별이면 15명. 과목은 주 단위로 반복된다.
그래서 리포트는 **횟수를 같이 보여준다** — 「3번 중 2번」이 「67%」보다 정직하다.
개별 급식 메뉴만 예외다(한 주에 거의 안 겹친다) → 그래서 **종류(볶음·국·튀김…)를 같이 쌓는다.**

**⚠ 랜덤 풀에 넣으면 안 된다.** 175개 풀에 섞으면 며칠에 한 번 나와서 데이터가 영영 안 쌓인다.
그래서 이 셋은 **풀 밖의 고정 미션**이다.

## 10. 미션 화면 두 탭 — RPG 구조

일일 퀘스트(즉시 정산)와 의뢰(검수 후 보상)가 한 줄에 섞여 있으면 아이가
**«왜 어떤 건 바로 별이 나오고 어떤 건 기다리나»** 를 읽을 수 없다. 그래서 탭을 갈랐다.

- 퀘스트 테마: 「일일 퀘스트」 / 「의뢰」 · 파스텔 테마: 「오늘 기록」 / 「오늘 할 일」
- 일일 퀘스트 개수는 **오늘 나올 수 있는 것만** 센다 — 주말엔 시간표가 비어 과목 미션이 없고,
  급식 없는 날도 있다. 없는 것을 분모에 넣으면 영영 못 채우는 0/3이 된다
- **의뢰는 전부 부모 확인형으로 바꿨다.** 「다 했어요」 한마디로 별이 나오면 부모가 낄 자리가 없다.
  사진 미션은 원래부터 이 길이었고, 이제 셋이 같은 길로 모인다.
  안 봐도 **다음날 아침 8시 자동 승인**이라 아이는 손해 보지 않는다
  - ⚠ `claim()` 에서 별을 주지 않는다. `approve()`/크론이 준다. 양쪽에서 주면 두 배가 나가고
    별 원장(`star_ledger`)은 되돌리기 어렵다
  - 사진 없는 의뢰인데 부모 화면에 **빈 사진틀**이 뜨던 것도 같이 고쳤다

## 11. 자녀 화면 대화바 임시 제거

화면 맨 아래 고정이라 준비물·오늘하루를 가렸다. **기능은 안 지웠다** —
`chatDock()`·`chatSend()`·messages API 그대로고, `childview` 끝에 한 줄만 되살리면 돌아온다.
부모 홈 대화바는 그대로(그쪽은 가리는 것이 없다).

같은 자리에서 **「연구 직원이 쓰는 화면 같다」**는 지적이 나왔다 — 질문 카드가 세로로
줄줄이 서 있어서 설문지처럼 읽힌다는 것. **지금 손대지 않는다.** 「오늘 카드 덱」 개편과
같이 풀어야 두 번 안 고친다(`docs\제안-보류.md`).
