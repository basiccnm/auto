# 에듀싱크 — 전체 로드맵 & DB 마스터 설계

작성: 2026-07-19 (v3: 이용권 구조 코드 조사 반영 — passes 신설 취소, 기존 구조 확장 확정) | 성격: 12년 서비스의 뼈대 문서. **데이터 설계는 이 문서가 단일 기준.**
관계: 전략은 `우리아이-뒷바라지AI-전략.md`, 블록1 구현은 `블록1-지시서-v3.md`. 이 문서는 그 사이의 "전체 지도".

## 0. 4대 원칙 (모든 블록에 적용)

1. **설계는 전체를 미리, 구현은 블록으로.** DB 스키마·형식은 지금 확정, 테이블 생성은 각 블록 시점에.
2. **저장 형식 = 미래 AI 입력 형식.** 블록1이 저장하는 모양 그대로 블록3 리포트·블록4 AI가 읽는다.
3. **각 블록은 출시하는 날 처음 공개.** 미리 보여주면 앵커링(유료화 반발) + 모방 시간 벌어줌.
4. **검증 후 확장.** 블록마다 검증 지표를 정해두고, 반응 확인 후 다음 블록 착수.

## 0.5 실사로 확인된 기존 자산 (2026-07-19 UI 검수)

기존 앱에 이미 있음: 소셜 로그인(카카오/구글, 이름·이메일 미수집), 이용권 구조(D-N 기간제, 1주일 체험), 잠금→자녀등록 전환 퍼널, 자녀 스위처(헤더 배지), 시간표 크라우드소싱 수정(반 공유/개인 구분), 교시 개인일정(최대 4행), admin(유료 회원·결제 관리 탭), 커뮤니티. **PG는 미부착.** 마이페이지는 기능 플래그로 꺼져 있음 → 블록1에서 켜서 자녀기록의 집으로.

## 2. 블록별 분류 (포함/제외/데이터/조건/지표)

### 블록 1 — 자녀기록 (제작 중, 상세는 지시서 v3)
- **포함:** 마이페이지 활성화(자녀기록의 집), 자녀 프로필(이름·출생연도·보호자 동의), 기록 업로드(6종 수동 분류)·타임라인·검색, **방과후·활동 별도 페이지**(주간 뷰, 유효기간), 시간표 하단 요약줄, 기간권 한도 로직, 광고 배치 규칙, 방침 개정+보호 안내 페이지, 정비(문구 통일·홈페이지 주소·배지 버그)
- **제외:** OCR(→1.5), PG 실연동(별도 트랙, 전환일 전), 알림·공유(→미정), AI(→2·4), PC 전용 레이아웃(→블록3 시점 검토)
- **데이터:** children 확장 + identifiers / records / activity_schedules 신설
- **검증 지표:** 자녀 등록률, 업로드 발생률, 방과후 등록률, 2주 재방문, **전환일 이후 기간권 결제 전환율**

### 블록 1.5 — 성적 구조화
- OCR 자동분류(수동→추천), 성적 숫자 추출 → grades. **이용권 사용자 한정으로 제공해 OCR 원가를 매출에 연동.**
- 선행: 블록1 업로드 실사용 확인 + API 원가 계산. 지표: 분류 정확도, 성적표 업로드 비중.

### 블록 2 — 공용 발달 AI (온램프)
- 공용 지식 DB만 사용(개인 데이터 접근 없음, 격벽). AI 행동규율 5개. **무료 월 N회 + 이용권 무제한** — 출시 첫날부터 이 구조로(무료로 다 풀지 않음 = 앵커링 방지).
- 선행: 지식 DB 소스 확정, 사용량 제한 설계. 지표: 사용률, 재사용률, 세션 원가.

### 블록 3 — 1년 돌아보기 리포트
- 1년치 기록 기반 정산 리포트. 이용권 상위 티어 or 단품 후보. PC 반응형 확장 검토 시점.
- 선행: 1년치 코호트, 부모 본인인증. 지표: 열람률, 상위 티어 전환율 ← 블록4 가격의 근거.

### 블록 4 — 개인 대화 AI + 기억 (해자·프리미엄)
- 자녀별 전용 AI(해당 child_id만), memories 축적, 연령별 페르소나, 리셋. **자녀별 과금**(가격 사다리가 아이 나이 기준이므로) + 둘째부터 다자녀 할인.
- 선행: 데이터 성숙 1~2년, 본인인증, 결제 고도화(자동결제 검토 시점). 지표: 구독 전환·유지율.

### 상시 트랙
보안·개인정보 / 마케팅(각 블록 출시 공지, 블로그) / 검증(지표 측정)

## 3. 유료화 사다리 (v2 — 기간권 모델)

- **모델: 자동결제 아닌 "기간권" 단건 결제.** 기존 이용권(D-N) 구조 재사용. 만료 D-3 연장 알림으로 갱신 유도. 자동결제는 수요 확인 후(블록4 시점 검토).
- 사다리: 무료(급식 일부·기록 20건·발달 AI N회) → **기간권 3,500원/월**(전 기능+광고 제거+기록 무제한) → 블록3 상위 티어 → 블록4 자녀별 프리미엄(초등<중등<고등, 다자녀 할인).
- 광고: 무료 사용자에게 애드센스(공개 정보 화면만, **자녀 데이터 화면은 광고 청정 구역**), 이용권 활성 시 제거. "광고 제거"가 기간권 첫 혜택.
- **자녀 수 정책: 무료 1명 → 이용권 3명 (자녀 등록=학교 열람 해제이므로 어뷰징 방지 상한. 4명 이상 실다자녀는 고객센터 수동 예외). 인원별 추가 과금 없음 — 기록·보관은 가족 단위 하나로, 자녀별 과금은 블록4 개인 AI부터.**
- **가격 원칙: ①스탠다드 3,500원은 고정 — 기능이 추가돼도 인상하지 않고 내용물만 두꺼워짐 ②질적으로 다른 가치(블록4 개인 AI)만 새 상품(프리미엄)으로 — 기존 가격 인상이 아니라 상위 옵션 추가 ③프리미엄은 스탠다드 포함형 단일가 (사다리: 무료→스탠다드→프리미엄 3층만 보이게).**

## 4. DB 마스터 설계

### 4.1 두 창고와 절대 규칙
- 자녀별 개인 DB(child_id 기준) / 공용 지식 DB(개인정보 없음)
- 절대 규칙: ①이름은 identifiers에만 ②공용 AI는 개인 DB 접근 불가 ③개인 AI는 해당 child_id만 ④광고/분석은 개인 DB 접근 불가

### 4.2 테이블 목록 (생성 시점)

**■ 블록1 (확정 — 지시서 v3):** children(기존 확장: +birth_year, +consent_at) · identifiers(신설) · records(신설, school_year 정수 코드: 초1=1…고3=12, 유치원 0 예약) · activity_schedules(신설). 신규 테이블은 sync_to_d1 재적재 제외.
**■ 블록1.5:** grades — record_id(FK, 원본 근거), child_id, subject, score_type(점수|등급|성취도), value, school_year, semester. 성적 숫자는 반드시 원본 이미지에 연결(환각 방지의 바닥).
**■ 블록2:** knowledge_base — age_band, topic, content, source(근거 필수). 공용 AI 대화는 세션 단위·익명, 영구 저장 안 함.
**■ 블록3:** reports — child_id, period(학년도), content_ref, generated_at.
**■ 블록4:** memories(관찰|대화요약, source_ref) · chat_state(리셋 시 기본 삭제 대상은 이 테이블만).
**■ 이용권 — passes 신설 취소, 기존 구조 확장으로 확정 (2026-07-19 코드 조사 후 결정):** 만료일은 children.trial_expires_at(의미: 이용권 만료일 — rename 안 하고 주석으로 명시, add-only 원칙), 결제 이력은 기존 payments, 연장은 기존 이어붙이기 로직, 무료 개방 플래그는 기존 BETA_FREE_ALL 재활용(전환일 기준으로 전환). 가격표 PAY_MATRIX는 자녀 수 차원 제거 후 단일가: 1개월 3,500 / 3개월 9,500 / 6개월 16,800 / 12개월 29,400 (초기값, 전환율 보고 조정 — 기간권이라 다음 구매분부터 변경 가능). 블록4 자녀별 과금은 그 시점에 children 컬럼 추가로 대응.
**■ 결제 고도화 시점:** guardians(본인인증 최소 정보)만 신설 예정.

### 4.3 공통 규칙
1. 개인 DB 전 테이블 child_id 포함, owner_token(+소셜 계정)→child_id 검증 필수
2. 시기 축 통일: school_year(정수 코드) + semester(1|2)
3. 삭제 연쇄: 자녀 삭제 = 전 테이블 + 스토리지 원본 즉시 파기 (기존 personal_schedule 계열 포함)
4. 마이그레이션 add-only, 기존 컬럼 의미 변경 금지

## 5. 미결 사항

1. **PG 선정·심사** (토스페이먼츠/포트원 계열 후보) — 유료 전환일 전 부착 데드라인. 수수료·심사 조건 확인 필요
2. 기간권 가격 구성(1개월 외 3개월 할인권 등) — 전환율 보고
3. 블록2 지식 DB 소스 선정
4. 블록4 리셋 범위(기억 포함 여부), 자동결제 전환 시점
5. 사업자 표시 값(대표자·주소·고객센터·통신판매업 신고번호) — 사장님 제공 필요, 유료 전환 전 필수
6. 프리미엄(블록4) 과금 세부 — 자녀별 과금 유력하나 설계는 블록3 전환율 실측 후
7. "다중 학교 열람권" 별도 상품 후보 — 학원 원장·강사 등 여러 학교 일정을 봐야 하는 직업군 수요. 지금 안 만들고 수요 신호 보고 판단
