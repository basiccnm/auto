### 신규 라우트
| 경로 | 하는 일 |
|---|---|
| `GET /records` | 타임라인(자녀·종류·검색) |
| `POST /records/upload` | 다중 업로드 |

전부 `needsLogin` 대상으로 등록 — 자녀 사진이라 반드시 로그인 뒤.

### 브라우저 리사이즈
원본 긴 변 2000px/JPEG 0.85 + 썸네일 480px/0.7을 **같은 canvas에서** 뽑아 함께 전송.
Workers엔 이미지 처리가 없어 **업로드 시점의 브라우저가 유일한 기회**다.
`imageOrientation:'from-image'`를 빼면 아이폰 세로 사진이 눕는다.
**EXIF가 canvas를 거치며 통째로 사라진다** — 위치정보 제거가 공짜로 딸려온다. 부작용이 아니라 기능이므로 방침에 명시해야 한다.

### 쓰기 순서 R2 → D1 (삭제와 같은 방향)
D1을 먼저 쓰면 타임라인에 **영영 안 지워지는 깨진 칸**이 남는다. R2 성공 후 D1이 실패하면 **방금 올린 객체를 즉시 보상 삭제**한다.
다중 업로드는 **장별 독립** — 3장 중 2번째가 실패해도 1·3은 저장한다. 전부 롤백하면 사용자가 사진을 처음부터 다시 골라야 한다.

### 이미지 서빙 보안
URL을 일부러 **연번**(`/records/2/img`)으로 잡았다. UUID를 URL에 넣으면 "URL을 아는 사람 = 권한자"라는 잘못된 모델이 생긴다. 실제 방어는 매 요청 SQL(`owner_token → child_id → record`)이고, 권한 없음은 **403이 아니라 404**로 답해 존재 여부까지 숨긴다.
`Cache-Control: private` — 개인 사진이 공용 캐시·CDN에 남지 않게.

### R2 키 구조
```
rec/{child_id}/{uuid}     원본
rec/{child_id}/{uuid}_t   썸네일 (컬럼 없음, 원본 키에서 파생)
```
`child_id` 접두사 덕에 고아가 생겨도 `list({prefix:'rec/17/'})`로 자녀 단위 청소가 된다.
