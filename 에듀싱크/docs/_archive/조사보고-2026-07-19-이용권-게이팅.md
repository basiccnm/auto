## 1. 이용권/체험(D-N) — 어디까지 구현돼 있나

**결론: 기간권 뼈대는 이미 다 있다. `passes` 신규 테이블 불필요.**

| 요소 | 상태 | 위치 |
|---|---|---|
| 이용권 만료일 | ✅ `children.trial_expires_at` (자녀 행에 직접) | — |
| 1주일 체험 | ✅ `TRIAL_DAYS=7`, 등록 시 자동 부여 | index.js:94, 749 |
| 재체험 차단 | ✅ `free_trials` 테이블 (계정당 1회) | index.js:707, 759 |
| 결제 기록 | ✅ `payments` 테이블 | index.js:1359 |
| 기간 이어붙이기 | ✅ **이미 구현** — 기존 만료일부터 연장 | index.js:1350-1357 |
| 가격표 | ✅ `PAY_MATRIX` (1·3·6·12개월 × 자녀 1~3명) | index.js:1326 |
| D-N 표시 | ✅ admin pill (이용중 D-n / 곧 만료 / 만료 / 테스트 / 무기한) | admin_templates.js:20-38 |
| CS 수동 조정 | ✅ ±일 조정 API | index.js:1787 |
| **PG 연동** | ❌ **더미** — `/pay`가 DB만 쓰고 끝 | index.js:1333 |

**핵심 발견 — `PAY_MATRIX`가 이미 자녀 수별 가격표였다:**
```js
const PAY_MATRIX = { 1: [0, 3500, 4000, 4500], 3: [...], 6: [...], 12: [...] };
//                        1명   2명   3명
```
1개월 1명이 **이미 3,500원** — v3 가격과 일치.

### ✅ 결정 (승인됨)
- **passes 신설 취소.** 기존 구조 확장.
- `trial_expires_at`은 **rename 없이 주석으로 의미 명시**(= 이용권 만료일). add-only 원칙 준수.
- **`PAY_MATRIX` 단일가화** (자녀 수 차원 제거):
  `1개월 3,500 / 3개월 9,500 / 6개월 16,800 / 12개월 29,400` (상수, 초기값)
- 블록4 자녀별 과금은 그 시점에 `children` 컬럼 추가로 대응.

> **기각한 대안**: 로드맵 v2의 `passes` 신설안. 만료일·연장·D-N·CS조정이 전부 `trial_expires_at` 기준으로 이미 동작 중이라, 새 테이블은 **두 개의 진실**을 만든다. 기존 로직 전면 재작성이 필요해 8/15 일정에 무리.

## 2. 비로그인인데 자녀 배지가 뜨는 원인

**siblings 쿼리가 `owner_token` 쿠키만 본다. 계정(로그인)을 안 본다.**
```js
// index.js:417-425
ownerToken ? db.prepare("... FROM children WHERE owner_token = ?").bind(ownerToken).all()
           : Promise.resolve({ results: [] })
// templates.js:1772
${(siblings && siblings.length) ? childSwitcher(siblings, child, school.slug) : ...}
```

**경위**: 로그인 게이팅을 넣을 때 `paid`만 고치고 배지는 놓쳤다.
```js
// index.js:481 — 여기는 account를 봄
const paid = !!paidChild && (paidChild.is_test || !!account);
```
→ 잠금은 걸리는데 **배지는 그대로 노출**. 공용 PC에서 남의 자녀 별명이 보인다.

### ✅ 결정 (승인됨)
`siblings`를 템플릿에 넘길 때 **`account` 없으면 빈 배열**로. `is_test`는 QA 예외 유지.

## 3. 테스트 자녀 등록 직후 '만료' 표시 원인

**`statePill()`이 테스트 자녀를 계산에서 제외한다.**
```js
// admin_templates.js:22-30
function statePill(kids) {
  const real = (kids || []).filter((c) => !c.is_test);   // ← 테스트 자녀 제거
  if (!real.length) return { text: "테스트" };
  let min = Infinity;
  for (const c of real) { ... }                          // ← 테스트 자녀는 안 봄
  if (min < 0) return { text: "만료" };
```
게다가 **테스트 자녀는 `trial_expires_at` 없이 INSERT된다** (index.js:1925 — 컬럼 자체가 빠짐).

→ 그 owner_token에 **예전 실제 자녀(만료됨)가 남아 있으면**, 테스트 자녀를 아무리 추가해도 그룹 pill은 만료된 자녀 기준으로 **'만료'**를 표시. 행을 펼치면 개별 자녀는 `childPill()`로 '테스트'(보라)로 정상 표시되어 **그룹 pill ↔ 자녀 pill이 어긋나 보인다.**

### ✅ 결정 (승인됨)
- 그룹 pill이 **실제 게이팅 상태와 일치**하도록 수정.
- **테스트 자녀만 있으면 '테스트'** 표시.
- **테스트 자녀 INSERT에 `trial_expires_at` 누락도 채운다.**
- 세부 구현은 코드탭 판단.

## 5. 🔴 BETA_FREE_ALL — 플래그가 한도만 관장하고 게이팅은 관장하지 않는다

### 발견
`BETA_FREE_ALL` 사용처는 **딱 2곳, 둘 다 자녀 수 한도**다:
```js
// index.js:103 — 자녀 최대 수
return (BETA_FREE_ALL || isPaid) ? MAX_CHILDREN : FREE_MAX_CHILDREN;
// index.js:705 — 무료 1명 제한 스킵
if (existingToken && !isSubscriber(request) && !BETA_FREE_ALL) { ... }
```
**콘텐츠 잠금(급식·일정·시간표)은 이 플래그를 보지 않는다:**
```js
// index.js:472, 481
const valid = (c) => c.school_id === school.id && (c.is_test || (c.trial_expires_at && c.trial_expires_at > nowIso));
const paid  = !!paidChild && (paidChild.is_test || !!account);
```

### ⚠️ 결과 — 지금 구멍이 있다
무료 개방 기간인데도 **자녀 등록 7일 뒤 콘텐츠가 다시 잠긴다.** `trial_expires_at` 만료로 `valid()`가 false가 되기 때문.
→ **"배포~개학일 전면 무료 개방"이 실제로는 1주일만 열리는 상태.**

### ✅ 결정 (2026-07-19 승인 — 정본은 지시서 v4 1-3절)

- **Q1 = A.** 개방 기간에는 체험 만료를 무시하고 **전원 전체 개방.**
  근거: PG도 없는데 잠그면 마찰만 남는다.
- **Q2 = A-2.** 전환일에 **전원 체험 7일 일괄 재부여**(연착륙).
  근거: 개학 첫 주가 가치 최고 체감기 → 그 주를 쓰게 한 뒤 잠근다.
  **`free_trials`의 계정당 1회 차단은 이 일괄 재부여에 한해 무시.** 이후 신규 가입자는 기존 규칙(등록 시 7일) 그대로.
- **플래그 통합 승인** — ①자녀 수 한도 ②콘텐츠 게이팅 ③기록 20건 한도 셋 모두 관장.
- **개명 승인** — `BETA_FREE_ALL` → **`FREE_OPEN_UNTIL`**(날짜 설정값).

#### 구현 시 주의 (코드탭 메모)
1. 전환일 일괄 재부여는 **1회성 배치**다. 매 요청마다 갱신되면 영원히 안 잠긴다 — 실행 여부를 기록할 것.
2. 재부여 대상은 **`is_test = 0`인 실제 자녀**만.
3. `FREE_OPEN_UNTIL`이 날짜값이 되면 `valid()`가 **매 요청 날짜 비교**를 하게 된다. 전환일 이후 첫 접속 시 배치가 돌도록 훅을 걸지, 크론(이미 매분 실행 중)에서 처리할지 결정 필요 — **크론 쪽을 권장**(접속이 없어도 시점이 지켜짐).

### 원 제안 (참고)
```js
const valid = (c) => c.school_id === school.id &&
  (c.is_test || BETA_FREE_ALL || (c.trial_expires_at && c.trial_expires_at > nowIso));
```
플래그가 **①자녀 한도 ②콘텐츠 게이팅 ③기록 20건 한도(신규)** 셋을 모두 관장하게 통일.
전환일에 플래그 하나만 내리면 세 가지가 동시에 정상화된다.

**이름 변경도 제안**: `BETA_FREE_ALL` → `FREE_OPEN_UNTIL`(날짜 설정값).
v3 1-3 "유료 전환일 = 가장 빠른 2학기 개학일, 코드에 하드코딩 금지·설정값으로"에 부합. 상수라 add-only 원칙과 무관.

## 7. 자녀 상한 3명 확정 경위

문서(5명) ↔ 코드(3명) 충돌을 보고 → **코드가 맞고 문서가 틀림**으로 결정.

- 헤더 자녀 스위처가 **2×2 그리드, 최대 3명** 구조로 이미 구현됨 (templates.js:825) → 그대로 유지, 재작업 없음
- **인원별 추가 과금(자녀2 +500원 · 자녀3 +1,000원) 폐지** → 단일 기간권 3,500원에 자녀 3명 포함
- 등록 폼·구독 안내 문구 전면 교체 → **"이용권 하나로 자녀 3명까지"** (지시서 6절 문구 통일 목록에 포함)
- 4명 이상 실다자녀는 **고객센터 수동 예외**
