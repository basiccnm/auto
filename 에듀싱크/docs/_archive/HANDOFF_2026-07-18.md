## 🔴→🟢 D1 용량 초과 장애 & Workers Paid 전환 (2026-07-18)
- **사고**: 전국 학사일정 적재(2.19M행)로 D1이 **668MB** → 무료 한도 **500MB/DB** 초과 → 모든 **쓰기 거부**(`D1_ERROR: Exceeded maximum DB size`). 로그인·가입·결제·의견이 Error 1101. 읽기(페이지 조회)는 정상이라 겉보기엔 멀쩡했음.
- **진단 확정**: `wrangler d1 info` 668MB / 로그 에러메시지 / `d1 list`로 **DB가 프로젝트별 분리**됨 확인(academy-site-db·eolmanama-b2b·eduthink-db 별개 — 다른 프로젝트가 채운 게 아님). 용량의 대부분이 academic_schedules, 그중 **grade_flags(코드에서 안 읽는 죽은 JSON) = 301MB**.
- **해결**: **Workers Paid($5/월) 전환**(대시보드 Workers & Pages → 사용량 옆 업그레이드). 반영에 ~2분 걸림. 전환 후 no-op UPDATE + 실제 `POST /feedback` 쓰기 end-to-end 성공 확인 → 정상. **이제 "유료 플랜" 가정이 실제로 참.** 하루 요청 한도도 상향.
- **D1 한도**: 무료 500MB/DB·하루요청 10만 → 유료(사용자 확인) **1GB/DB**. (10GB 아님 — 정정)
- **grade_flags 정리(301MB)**: 지금은 미실행(1GB 안 여유 있음 + UPDATE로는 파일 즉시 안 줄어듦). **개학 때 급식 전국 적재하며 grade_flags 없이 재적재**로 헤드룸 확보 예정. → [[meals-timetables-bulk-load-decision]]에도 반영.

- **급식** = 개학 후 전국 일괄 pre-fill(방학이라 지금은 희박, 30일에 4일치). 유치원 제외.
- **시간표** = 일괄 ETL 안 함. 요일 고정 1회 세팅 구조가 이미 완성(아래 참조). "실시간으로 안 받고 고정 평일 한 번 지정하면 끝".

지금(방학) 실측 → 2학기 시간표는 NEIS에 아직 없음(1학기는 정상 100행+), 급식도 희박. 그래서 급식 일괄은 개학(8월 말~9월 초)에 실행.

**⚠️ 시간표는 일괄 ETL 대상 아님(2026-07-18 사용자 확정):** 시간표는 "실시간 수집"이 아니라 **요일 고정 = 한 번 세팅하면 끝**. 현재 `ensureTimetable`(index.js:356)이 이미 그 구조 — 학교·학년·반·학기당 1회만 받고(있으면 skip), 요일별 대표과목으로 축약, **갱신 크론 없음**(학기 바뀔 때만 재수집). NEIS에 없으면 빈 격자 직접 입력 + 반 단위 공개 오버라이드(`timetable_overrides`)로 채움 — 완성된 설계. **따라서 시간표에는 실시간/갱신 크론/수만 콜 걱정 불필요.** 반별 대량 pre-fetch도 하지 않음(반 열거 부담) — 각 반이 처음 볼 때 1회 세팅되는 현행 유지가 기본.

**개학 후 실제 일괄 대상 = 급식뿐:**
- **급식** = `ensureMeals`(mealServiceDietInfo, 학교당 1콜·30일 창). 전국 ~1.2만 콜 → meals.
- **레이트리밋 최우선** — NEIS 키·IP 차단 = 온디맨드까지 죽는 실사업 리스크(글로벌 CLAUDE.md 축평원 사고). 지역별 순차·초당 소수·실패 재시도.
- **급식 갱신 크론 필요** — 급식은 30일 창이라 부어넣고 끝이 아님. `rollSchedulesRefresh`(학사일정 롤링) 방식을 meals로 확장(sync_state에 meals_synced_at 추가). ← 이건 급식만. 시간표는 해당 없음.
