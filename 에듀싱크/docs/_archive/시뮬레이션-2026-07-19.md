## ✅ 통과

### 1. 로그인 없이 기록 진입 불가
`/records` → **302** `/login` · `POST /records/upload` → **302**
`needsLogin`에 `/records*`·`/activities*` 등록 완료.

### 2. 보호자 동의 없이 자녀 등록 불가
동의 체크 없이 직접 POST → **"보호자 동의가 필요해요"** 안내로 차단.
프론트 `required`만이 아니라 **서버에서도 검사**한다.

### 3. 자녀 2명 → 타임라인 자녀별 분리
자녀 24(초3)·25(초5) 등록 → 각자 기록 업로드 → **각 타임라인에 자기 것만** 노출. 스위처 정상.

### 4. 이름이 identifiers에만 존재
```
identifiers 행: 1
children.nickname에 실명: 0
records.title에 실명: 0
```
**로드맵 절대규칙 ① 준수 확인.**

### 5. 다중 업로드 + 시기 자동 추정
3장 동시 업로드 → `{"ok":true,"saved":3}`. 시기 미지정 시 **7월 → 1학기** 자동, 학년은 자녀 프로필(초3) 기준.
제목 자동 생성: **"초3 1학기 상장"** ×3 (같은 배치는 제목이 같은 게 의도된 동작).

### 8. 방과후 등록 → 주간 뷰 + 요약줄
수학학원(월·수 16~18시) · 축구교실(토 9~11시) · 피아노(금) · 일요논술(일) 등록.
**시간축 자동 확장 9~22시** + 안내 문구. 시간표 탭 하단 **"오늘의 방과후: 일요논술 10:00~12:00"**.
유효기간(8/22) 지나면 자동 미표시 — 로직 확인.

### 9. personal_schedule 회귀 없음
행수 0 유지(원래 0). 기존 개인일정 구조 미변경.

### 10. 타 계정 접근 차단
| 시도 | 결과 |
|---|---|
| 타 계정이 남의 기록 이미지 | **404** (403 아님 — 존재 자체를 숨김) |
| 타 계정이 남의 기록 삭제 | `not_found` |
| 타 계정이 남의 자녀에 업로드 | `forbidden` |
| 타 계정 타임라인 | 200이지만 **자기 것만** 노출 |

### 11. 자녀 삭제 → 전체 파기
```
삭제 전: 기록 1 · 실명 1 · 일정 0
삭제 후: 자녀 0 · 기록 0 · 실명 0 · 일정 0
```
`deleteChildCascade` 단일 경로. R2는 원본+파생(`_t`) 함께 삭제.

### 12. 광고 청정 구역
`recordsPage` · `activitiesPage` · `mypagePage` · `purgeAllPage` · `childrenManagePage` — **전부 광고 호출 0건**(소스 grep).

### 14. 이미지 공개 URL 접근 불가
`Public access via the r2.dev URL is disabled` — R2 버킷 비공개 확인.
접근은 워커가 매 요청 `owner_token → child_id → record` 검증 후 스트리밍.

### 15. 기존 기능 회귀 없음

## ⚠️ 부분 확인 — 환경 제약

### 6. 무료 21건째 잠금
**측정 불가.** 현재 자녀 학교(서울숭미초)의 개학일이 **2026-08-20**이라 무료 개방 기간이고, 한도가 **1,000건**으로 뜬다(화면 표시 `4/무제한`). 20건 한도는 개방 종료 후에만 걸린다.
- 코드 경로는 확인: `maxRecordsFor(isPaid, freeOpen)` → 개방/유료면 1000, 아니면 20
- 초과 시 **업로드만 잠기고 열람·삭제는 유지**되는 분기도 코드상 확인
- 🔵 **개학일 이후 또는 별도 테스트 학교로 재확인 필요**

### 13. 4MB 초과 거부
**측정 불가.** 3MB 넘는 multipart를 보내면 wrangler dev가 `Your worker restarted mid-request` / 503으로 죽는다. **로컬 dev 서버의 한계**이지 앱 코드 문제가 아니다(같은 루프를 타는 **MIME 거부는 정상 동작** 확인: `{"ok":false,"skipped":1}`).
- **10장 초과 거부는 확인**: `{"ok":false,"error":"too_many","max":10}`
- 실사용에선 브라우저가 2000px/0.85로 줄여 보내므로 대개 1MB 미만이라 4MB는 드문 경계
- 🔵 **배포 후 실서버에서 재확인 필요**
