## 8. 반응형 유동 확장 전환 (원칙1 재확인)

기존: `.wrap` + 내부 div가 전부 `max-width:468px` 고정 → 데스크톱에서도 468px 좁은 기둥만 중앙에 뜨고 양옆은 빈 회색.
변경: 화면 폭에 따라 컨테이너가 유동 확장되도록 전환.

- **컨테이너 유동화**: `.wrap` = `width:100%` + 브레이크포인트 상한 — 모바일 480px / 태블릿(≥768px) 720px / 데스크톱(≥1024px) 960px. 내부 페이지 div 15곳의 `max-width:468px` → `max-width:100%`로 바꿔 wrap 폭 상속
- **글자 clamp화**: 헤딩·본문 9종(13.5·14·14.5·16·16.5·17·18·22·27px)을 `clamp(원본px, 유동vw식, 상한px)`으로 전환. 모바일에선 원본 크기 유지(축소 없음), 큰 화면에서만 상한까지 성장. 미세 라벨(≤13px)은 버튼·칩 넘침 위험으로 고정 유지
- **표 콘텐츠**: 시간표/스탯그리드가 `1fr` 컬럼이라 컨테이너 확장 시 칸이 자동으로 커짐(데스크톱 시간표 그리드 300→900px)

**3개 폭 실측 재검증**(Browser pane 측정 + 실제 Chrome 스크린샷 + 버튼 실클릭):
| 폭 | 컨테이너 | 가로 넘침 | 시간표 그리드 | h1 |
|---|---|---|---|---|
| 360px | 360px(꽉 참) | 없음 | 300px | 27px(원본 유지) |
| 768px | 720px(확장) | 없음 | 660px | 33px(상한) |
| 1920px | 960px(상한, 무한정 X) | 없음 | 900px | 33px(상한) |
- 넓은 화면 급식/시간표 탭 실클릭 정상, 레이아웃 깨짐·넘침 없음

## 9. 네이티브 confirm() → 커스텀 모달 전수 교체

이유: 브라우저 네이티브 다이얼로그가 디자인 톤과 안 맞고, 자동화 QA 도구(스크린샷·클릭)를 완전히 멈추게 함.

- **재사용 헬퍼**: `layout()`(사용자화면)·`adminLayout()`(관리자)에 커스텀 확인 모달을 1회씩 주입. 전역 API 통일:
  - 폼 제출: `onsubmit="return uiConfirm(event, '메시지', '확인버튼라벨')"` (기본 제출 막고 모달 확인 시 폼 submit)
  - 콜백: `uiConfirmCb('메시지', function(){...}, '라벨')`
  - 취소/ESC/배경클릭으로 닫힘, 메시지는 `white-space:pre-line`으로 줄바꿈 지원
- **교체한 곳(총 10)**:
  - 사용자화면 6: 시간표 수정모드 토글(시작/완료)·시간표 초기화·자녀 삭제·커뮤니티 신고·결제 확인·알림 해제
  - 관리자 4: 배너 삭제·데이터 원복·테스트자녀 삭제·환불
- **검증**: 소스에 실제 `confirm()` 호출 0건(주석만). 실브라우저에서 시간표 수정 버튼 클릭 → 모달 flex 표시·"확인" 시 편집모드 진입·모달 닫힘 확인. 자녀삭제 폼 → 제출 가로채기(즉시제출 안 됨)·모달 메시지 줄바꿈 정상. **자동화 클릭이 더 이상 멈추지 않음**(네이티브 confirm 프리징 해소)

## 9. 미해결/보류

- **배포(`wrangler deploy`) 아직 안 함** — 위 코드 변경사항은 전부 로컬 파일에만 존재. 사용자가 "로컬로 가겠다"고 해서 배포 보류 중
- 관리자(`/admin`) 페이지 실클릭 QA는 이번 세션에서 스킵(Basic Auth라 자동화 도구가 자격증명 URL 주입을 안전정책상 차단)
- 자동화 브라우저 도구의 `confirm()` 네이티브 다이얼로그 처리 한계(시간표수정·결제하기 버튼) — 앱 버그 아님, 툴 제약
