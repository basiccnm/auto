스크립트에 **workers.dev를 받으면 아예 거부**하는 가드를 넣었습니다.

# 5. 🔴 실행 중 발견 — wrangler가 조용히 아무것도 안 합니다

**②단계가 통째로 안 돌았는데 스크립트는 성공처럼 다음으로 넘어갔습니다.**
자녀·기록은 지워졌는데 `users` 14 · `accounts` 3 · `payments` 2가 그대로 남아 있어 발견했습니다.

원인: 토큰 21개짜리 `IN` 목록이 여러 DELETE에 반복되며 `--command` 문자열이 길어지자
**wrangler가 에러도 없이 빈 출력만 내고 끝났습니다.** 드라이런의 카운트 SELECT도 같은 이유로
한 번 비어 있었습니다(그건 바로 알아차렸습니다).

**조치 2가지:**
- **한 문장씩 보냅니다.** 여러 DELETE를 한 `--command`에 묶지 않습니다
- **성공 판정을 문구가 아니라 응답의 `"success": true`로** 봅니다.
  단문/다문에 따라 wrangler 출력 문구가 달라서, 문구로 재면 **멀쩡한 실행을 실패로 읽습니다**
  (실제로 per-table 재실행 때 전부 "실패"로 찍혔는데 알고 보니 다 성공한 상태였습니다)

수정 후 스크립트를 **두 번 더 통째로 재실행**해 ②·③이 각 문장별로 `OK`를 찍는 것과
**멱등**(다시 돌려도 결과가 같음)을 확인했습니다.

# 7. 스크립트 최종형 — `scripts/qa_cleanup_2026-07-24.sh`

```bash
bash scripts/qa_cleanup_2026-07-24.sh <base_url> <admin_pw> <local|remote> [--apply]
```

지켜지는 것:
- **기본이 드라이런.** `--apply` 없으면 세기만 함
- **와일드카드 금지.** 21개 토큰 명시 (운영 DB 패턴 삭제는 오폭이 조용히 남)
- **자녀는 반드시 admin 연쇄** → `deleteChildCascade`가 R2 먼저. SQL로 지우면 사진이 영구 잔류
- **`records`는 ③ 잔재 청소에서 제외** — R2가 딸려 있어 SQL 삭제 금지
- **workers.dev 거부 가드**
- **문장별 실행 + `success` 기반 판정**

`payments` 삭제 줄에 경고를 박아뒀습니다 —
**실사용자 결제가 생긴 뒤에는 그대로 쓰지 말 것**(이번엔 베타 전 더미 2건이라 가능했던 예외).
