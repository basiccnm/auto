# 우리아이학교정보 관리자 페이지 — 기능·백엔드 지시서

> **대상:** Claude Design (관리자 화면 디자인·구조 확정용)
> **작성:** 2026-07-18 / **작업 폴더:** `workers/site-renderer` (Cloudflare Worker, 서버 렌더링)
> **배포:** https://eduthink-site-renderer.dndmotor1.workers.dev/admin
> **성격:** 대표 1인 전용 운영 도구(Basic Auth). 소비자 화면과 달리 **정보 밀도·조작 효율 우선**의 대시보드형.
> 이 문서는 "각 페이지가 무슨 데이터를 보여주고 무슨 조작을 하는지"를 백엔드 기준으로 확정한 것. 디자인은 이 기능을 담아내면 된다.

---

## 0. 공통 규칙 (모든 페이지)

### 0.1 인증·진입
- `/admin/*` 전체 **Basic Auth**(고정 비밀번호). 아이디/비번 아무 칸에나 비번 입력 시 통과.
- 상단 고정: 서비스명 + 7개 탭 네비게이션. 현재 탭 강조.

### 0.2 네비게이션 (탭 7개)
| 탭 | 경로 | 한 줄 역할 |
|---|---|---|
| 모니터링 | `/admin` | 적재 현황·갱신일·오류 로그 대시보드 |
| 배너 관리 | `/admin/banners` | 광고 7슬롯 등록·수정·게시토글 |
| 데이터 보정 | `/admin/correct` | 학교 검색 → 급식·학사일정 수동 수정·원복 |
| **유료 회원** | `/admin/members` | **부모(회원) 단위 관리 — 자녀·결제·이용기간** |
| 결제 관리 | `/admin/payments` | 결제 내역·환불·수정·삭제 |
| 오류 신고 | `/admin/reports` | 사용자의 학교정보 오류 제보 처리 |
| 베타 의견 | `/admin/feedback` | 서비스 전반 의견 처리 |

### 0.3 공통 컴포넌트 (재사용)
1. **상태 pill** — 색으로 상태 표현: 정상(초록)/주의(노랑)/위험·환불(빨강)/테스트(보라)/비활성(회색).
2. **학교 이름 검색 자동완성** — 입력창에 학교명 일부 → 드롭다운 목록(학교명 · 지역 · 학교급) → 선택. **관리자는 학교 코드/번호를 모르므로 이름으로만 찾는다.** (데이터 보정·테스트자녀 등록 공용) · API: `GET /admin/school-search?q=`
3. **확인 다이얼로그** — 삭제·환불 등 파괴적 동작 전 커스텀 confirm(네이티브 confirm 금지 — QA 자동화 도구가 멈춤).
4. **상세 모달(팝업)** — 목록 행 클릭 시 상세를 모달로. 회원·결제에서 사용.
5. **스크롤 목록** — 수천 행 목록은 통짜 나열 금지. 고정 높이 + 내부 스크롤 + 상단에 이름 필터.

### 0.4 ⚠️ 기술 주의 (현재 구현 버그의 원인 — 재설계 시 반드시 반영)
- 공통 스크립트(모달 열기·학교검색 헬퍼)는 **각 페이지 스크립트보다 먼저** 로드/정의돼야 한다. 현재는 공통 스크립트가 body 끝에 있어 페이지 스크립트가 먼저 실행되며 `함수 미정의` 에러 → "자세히" 모달이 안 열리는 버그가 있음. → 공통 스크립트를 head 또는 body 상단에 두거나, 페이지 초기화를 `DOMContentLoaded` 이후로 미룰 것.

### 0.5 톤·반응형
- 데스크톱 우선(대표가 PC에서 운영). 단 표는 가로 스크롤 컨테이너로 감싸 좁은 화면에서도 깨지지 않게.
- 절제된 관리자 톤: 파랑 계열 강조색 1개 + 중립 회색 + 상태색(초록/노랑/빨강). 과한 장식 금지, 정보 위계·정렬 우선.

## 1. 모니터링 (`/admin`)

**목적:** 전국 데이터가 얼마나 채워졌는지, 최근 갱신·오류 상황을 한눈에.

**A. 적재 현황 카드 (상단 요약)**
- 전체 학교 수 / 초·중·고 각 학교 수 / 학사일정 적재 학교 수 / 학교 상세정보 학교 수.
- 출처: `schools`(전체·학교급별 COUNT), `academic_schedules`(DISTINCT school_id), `school_details`(COUNT).

**B. ETL 진행 상황**
- 최근 배치 1건: job_name, 완료/전체, 상태(running/done/failed), 시작·종료 시각. 출처: `etl_runs` 최신 1행.

**C. 학교별 최근 갱신일** — *스크롤 목록 + 이름 필터*
- 컬럼: 학교명 · 학교급 · 급식 갱신일 · 시간표 갱신일 · 학사일정 갱신일. 없으면 "없음" pill.
- 출처: `schools` + 각 데이터 테이블의 `MAX(last_synced_at)`. (현재 최근 100개교 표시)
- 상단에 학교명 필터 입력(클라이언트 즉시 거르기).

**D. 최근 API 실패 로그**
- 컬럼: 발생시각 · 소스 · 대상 학교 · 오류 메시지. 출처: `etl_error_log` 최근 30건.

## 2. 유료 회원 (`/admin/members`) — **부모(회원) 중심** ★핵심 재설계

> **개념:** 회원의 단위는 **부모 1명 = `owner_token` 1개**다(전화·이름 미수집이라 브라우저 토큰이 계정 키). 소셜 로그인을 한 부모는 `users`에 계정(provider·닉네임)이 연결된다. 자녀는 그 부모에 속한다.
> **"테스트 자녀 등록"은 이 페이지의 주인공이 아니다** — QA 보조 도구로 하단에 작게 두거나 개발도구로 분리.

### 2.1 회원 목록 — **부모 1명 = 1행**
| 컬럼 | 내용 | 출처 |
|---|---|---|
| 대표 | 소셜 닉네임(있으면) / 없으면 대표 자녀 별명 + 제공자 뱃지(카카오/구글/네이버) | `users.nickname`,`users.provider` / `children.nickname` |
| 자녀 수 | n명 | `children` COUNT by owner_token |
| 학교 | 대표 학교명 "외 N" | `children`→`schools.name` |
| 이용 상태 | 최근 만료 기준 pill (이용중 D-n / 곧 만료 / 만료 / 테스트) | `children.trial_expires_at`, `is_test` |
| 결제 | 유효 결제 있음/없음 뱃지 | `payments` by owner_token |

- 정렬: 최근 활동/가입 순. 상단에 이름·닉네임 검색.
- **행(또는 "자세히" 버튼) 클릭 → 상세 모달**(아래 2.2).

### 2.2 회원 상세 모달 — **그 부모의 모든 것** ★
행을 누르면 팝업으로, **이 부모에 딸린 자녀 전체 + 결제 내역 전체 + 계정 정보**가 한 번에 보여야 한다.

**(1) 계정/부모 정보**
- 소셜 제공자·닉네임, 가입일, 최근 로그인. 브라우저 토큰(앞 8자). 알림 신청 여부. 무료체험 사용 여부.
- 출처: `users`(provider·nickname·created_at·last_login_at), `notif_settings.enabled`, `free_trials.first_used_at`.

**(2) 자녀 목록** (이 부모의 모든 자녀)
- 각 자녀: 별명 · 학교 · 학년·반 · 이용 만료(또는 테스트) · 커뮤니티 닉네임.
- 자녀별 액션: **수정**(별명·학년·반) · **삭제** · **화면 보기↗**(실제 학교 상세를 이 자녀로 열기).
- 출처: `children`(+`schools.name`,`slug`). 수정 API `POST /admin/members/:id/edit`, 삭제 `POST /admin/members/:id/delete`.

**(3) 결제 내역** (이 부모의 모든 결제)
- 각 결제: 결제일 · 금액 · 기간·자녀수 · 수단 · 자동구독 여부 · 상태(결제완료/환불) · 이용 만료일.
- 출처: `payments WHERE owner_token = ?`. (결제 관리 페이지와 동일 데이터의 부모별 뷰)

**(4) 부모 단위 액션**
- **이용기간 ±일 조정**(CS 연장·단축) → 이 부모의 (테스트 아닌) 모든 자녀 `trial_expires_at` 일괄 조정. API `POST /admin/members/adjust`.
- **회원 전체 삭제** → 이 부모(owner_token)의 모든 자녀 삭제. API `POST /admin/members/token-delete`. (계정 `users`·결제 기록 보존 여부는 정책 확인 필요 — 기본은 자녀만 삭제)

### 2.3 유료 가입자 모드 토글 (개발/QA 보조)
- 이 브라우저를 "유료 가입자"로 on/off (결제 미구현 상태에서 유료 화면 확인용). 작게 유지.

### 2.4 테스트 자녀 등록 (개발/QA 보조 — 주인공 아님)
- 학교(**이름 검색**)·학년·반·별명 → 결제 없이 잠금 해제된 자녀 생성(is_test=1). API `POST /admin/members/add-test-child`.
- 위치: 페이지 하단 또는 "개발 도구" 접힘 영역으로. 회원 목록이 화면 상단 주인공.

## 3. 결제 관리 (`/admin/payments`)

**목적:** 결제 내역 조회·정산·CS(환불·정정).

> **이름 표시 규칙:** 결제자 이름은 `payer_name`(실제 PG 연동 시 결제사가 주는 이름) 우선 → 없으면 소셜 **계정 닉네임** → 그것도 없으면 **토큰 앞 8자**. 지금은 베타(더미 결제)라 payer_name이 비어 있어 닉네임/토큰으로 표시됨. **`payer_name` 컬럼은 이미 추가돼 있음**(PG 연동 대비).

### 3.1 목록 — 결제 1건 = 1행
| 컬럼 | 출처 |
|---|---|
| 결제일 | `payments.created_at` |
| 이름 | `payer_name` → 계정 닉네임(`users`) → 토큰 |
| 금액 | `amount` |
| 기간·자녀 | `months`·`child_count` |
| 수단 | `method`(카드/휴대폰/가상계좌) + 자동구독 |
| 상태 | `status`(결제완료/환불됨) pill |

- 상단: 이름/토큰 검색, 유효 합계 금액.
- 행 클릭 → 상세 모달.

### 3.2 결제 상세 모달
- 결제자 이름(payer_name / 계정 닉네임 / "미확보(PG 연동 후)"), 결제일, 금액, 기간·자녀, 수단, 토큰.
- **이 결제가 어느 부모/자녀의 것인지 연결 표시**(owner_token → 회원 상세로 이동 링크가 있으면 좋음).
- 액션: **수정**(결제자 이름·금액 정정) `POST /admin/payments/:id/edit` · **환불** `POST /admin/payments/:id/refund`(상태만 환불됨으로) · **삭제** `POST /admin/payments/:id/delete`.

> 참고: 실결제(PG)는 베타 이후. 현재 `/pay`는 더미 + `PAYMENTS_DISABLED=true`. 지금 화면은 더미 결제 기록 관리용이며, PG 연동 시 payer_name 자동 채움 + 영수증/승인번호 등 컬럼 추가 예정.

## 4. 데이터 보정 (`/admin/correct`)

**목적:** NEIS 원본이 비었거나 틀렸을 때 관리자가 급식·학사일정을 직접 수정. 이력 남기고 원복 가능.

- **학교 찾기: 이름 검색 자동완성**(코드/슬러그 직접입력 폐지). 선택 시 그 학교의 보정 화면.
- **급식 보정**(최근 20건): 날짜·구분·메뉴 → 메뉴 텍스트 수정 저장. API `POST /admin/correct/meals/:id`.
- **학사일정 보정**(최근 20건): 날짜·행사명 → 행사명 수정 저장. API `POST /admin/correct/schedules/:id`.
- **수정 이력**(최근 30건): 시각·학교·대상 필드·원본값·수정값 + **원복** 버튼. 출처 `admin_edit_log`. 원복 API `POST /admin/correct/undo`.
- 안내: NEIS 재적재 시 수동 수정이 덮어써질 수 있음(이력으로 추적).

## 5. 배너 관리 (`/admin/banners`)

**목적:** 광고 7슬롯(1·2 애드센스 / 3 쿠팡 / 4·5 하우스 / 6·7 B2B 학원) 관리. 출처 `banners`.

- **목록**: 슬롯 · 종류 · 광고주 · 노출지역 · 기간 · 결제여부 · 상태(게시중/숨김) + 액션(게시토글·수정·삭제).
- **등록/수정 폼**: 슬롯(1~7) · 종류 · 코드 스니펫(애드센스/쿠팡) · 이미지/링크 URL(하우스/B2B) · 대체텍스트 · 광고주명 · 노출지역 교육청코드(비우면 전체) · 기간(시작~종료) · 결제완료 체크.
- API: 등록 `POST /admin/banners`, 게시토글 `/:id/toggle`, 수정 `/:id/edit`, 삭제 `/:id/delete`.

## 6. 오류 신고 (`/admin/reports`)

**목적:** 사용자가 특정 학교의 상세정보(학급수·급식·시간표 등)가 실제와 다르다고 제보한 것 처리. 출처 `info_reports`.

- **목록**(미처리 우선 → 최신순): 접수시각 · 학교 · 분류 · 내용 · 상태(미처리/처리됨) + 액션(학교 화면 보기↗ · 처리완료).
- 처리완료 API `POST /admin/reports/:id/resolve`. 개인정보 미수집.

---

## 7. 베타 의견 (`/admin/feedback`)

**목적:** 학교와 무관한 서비스 전반 의견/버그/제안 처리. 출처 `beta_feedback`.

- **목록**(미처리 우선 → 최신순): 접수시각 · 분류(불편·버그/기능제안/칭찬/기타) · 내용 · 상태 + 처리완료.
- 처리완료 API `POST /admin/feedback/:id/resolve`. 개인정보 미수집.

## 부록 A. 데이터 모델 요약 (페이지 ↔ 테이블)

| 페이지 | 읽는 테이블 | 쓰는 테이블 |
|---|---|---|
| 모니터링 | schools, school_details, academic_schedules, meals, timetables, etl_runs, etl_error_log | — |
| 유료 회원 | children, schools, users, payments, notif_settings, free_trials, community_posts | children(수정·삭제), children.trial_expires_at(연장) |
| 결제 관리 | payments, users, children | payments(수정·환불·삭제) |
| 데이터 보정 | schools, meals, academic_schedules, admin_edit_log | meals, academic_schedules, admin_edit_log |
| 배너 관리 | banners | banners |
| 오류 신고 | info_reports, schools | info_reports.status |
| 베타 의견 | beta_feedback | beta_feedback.status |

**핵심 키:** `owner_token`(부모=회원 식별자, 로그인 없이 브라우저 쿠키). `users`가 소셜계정↔owner_token 연결. `children`/`payments`/`notif_settings`/`free_trials`가 전부 owner_token으로 묶임 → **회원 상세는 owner_token 하나로 자녀·결제·알림·체험을 모두 조인**.

**개인정보 원칙:** 이름·전화·이메일 미수집. 소셜 로그인은 고유식별번호+닉네임만. 결제자 이름(payer_name)만 PG 연동 시 저장.
