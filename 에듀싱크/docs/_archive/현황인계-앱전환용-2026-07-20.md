# 1. 현재 기술 스택

| | |

| 배포 | wrangler CLI |
| 인증 | 소셜 OAuth(카카오·구글·네이버) + `owner_token` 쿠키 |

## ⚠️ 앱 전환의 핵심 문제
**화면과 데이터가 분리돼 있지 않습니다.** 핸들러가 DB를 조회해 **HTML 문자열을 바로 반환**합니다. JSON API가 거의 없습니다.

```js
// 지금 구조 (예: 학교 상세)
async function handleSchool(...) {
  const school = await db.prepare("...").first();
  const meals  = await db.prepare("...").all();
  return html(schoolDetailPage({ school, meals, ... }));  // ← HTML 문자열
}
```

→ **앱을 붙이려면 이 전부를 JSON API로 다시 만들어야 합니다.** 파일 몇 개 수정이 아니라 전 계층 재설계입니다. 이게 이번 설계의 가장 큰 덩어리입니다.

**현재 JSON을 반환하는 것**: `/api/push/*`, `/api/school-warm`, `/records/upload`, `/records/delete`, `/activities/save|delete`, `/timetable/edit`, `/admin/school-search` — **이게 전부**입니다.

## 🔴 회원 구조의 근본 문제
```
users        : id, provider, provider_uid, nickname, owner_token, created_at, last_login_at
children     : id, owner_token, school_id, grade, class_name, nickname, is_test,
               trial_expires_at, consent_at, consent_method, regranted_at, ...
```
- **회원의 실체가 `owner_token`(쿠키 UUID)입니다.** `users`는 소셜 로그인을 그 토큰에 *붙이는* 부속 테이블일 뿐입니다.
- **ID·비밀번호·이메일·휴대폰이 없습니다.**
- `children.owner_token`으로 소유를 판정합니다 — 즉 **쿠키를 잃으면 자녀가 사라집니다.**
- 이용권 만료일이 **`children.trial_expires_at`(자녀별)** 에 있습니다. 회원 단위 구독 개념이 없습니다.

→ **앱은 쿠키를 못 씁니다.** 회원 체계를 ID 기반으로 다시 세우고 토큰(JWT 등)으로 가야 합니다. **이게 앱 전환의 1순위 설계 항목입니다.**

## 결제 구조
```
payments : id, owner_token, child_count, months, amount, method,
           auto_renew, status, new_expiry, created_at, payer_name
```
- `PAYMENTS_DISABLED = true` — **서버에서 결제 자체를 차단** 중
- 가격: `PAY_PRICES = {1:3500, 3:9500, 6:16800, 12:29400}` (자녀 3명 포함 단일가)
- **주문·입금대기·확인 개념이 없습니다.** 무통장을 넣으려면 `orders` 계열이 새로 필요합니다.

6. 웹푸시 코드는 있으나 미사용(`push_subscriptions` 0행). **앱은 FCM으로 갈아야 함**

# 8. 전략 세션에 요청하는 것

**설계를 그려 주십시오.** 특히 이 순서가 중요합니다.

1. **회원 체계** — ID/비번, 부모 휴대폰(인증은 나중에 끼움), 앱 인증 토큰 방식, 기존 `owner_token` 사용자 이행 방안
2. **결제 구조** — 무통장(주문→입금대기→관리자확인→활성), 나중에 PG·인앱결제를 끼울 자리
3. **API 설계** — 앱이 부를 엔드포인트. 지금 HTML 렌더를 어떻게 쪼갤지
4. **앱 화면 구성** — 웹 화면 5종 + 학교정보를 앱에서 어떻게 배치할지
5. **웹의 운명** — 앱 전환 후 웹은 유지/축소/폐기 중 무엇인지 (SEO로 유입 중이라 판단 필요)
6. **일정** — 8/15 개발완료·8월 하순 배포 목표가 아직 유효한지
