### 말 규칙 (결정 4 상세) — 화면·푸시·버튼 전부 이 표를 따른다

| 개념 | 쓰는 말 | 쓰지 않는 말 |
|---|---|---|
| 별을 내고 보상을 얻는 행위 | **바꾸기** «★5로 바꾸기» | 구매 · 결제 · 사기 |
| 바꾼 보상 | **티켓** 🎟️ (지시서 §4③의 말) | 영수증 · 주문 |
| 아이가 티켓을 모아 보는 곳 | **내 티켓** | 구매 내역 |
| 부모가 실물로 해주는 행위 | **티켓 바꿔주기** → [바꿔줬어요] | 지급 · 처리 · fulfill |
| 아이 티켓 상태 | «기다리는 중» → «받았어요» | requested / fulfilled 노출 |

- 서버 코드(`reward_orders`·`fulfill`)는 **그대로 둔다** — 말 규칙은 화면의 일이다.
  API 이름을 따라 화면 말을 정하면 이번 같은 일이 또 생긴다
- ⚠ 진짜 돈이 오가는 **인앱결제 화면(이용권)에는 「구매·결제」를 그대로 쓴다.**
  거기까지 게임말로 하면 스토어 심사·소비자 안내에서 문제가 된다. 갈림선은 «실제 돈이냐»다

## 1. 재화 — 새로 만들지 않는다

`S.missionStars`(모은 도장)가 **이미 있고 이미 서버와 동기화된다**(`app.js:7936`·`8010`).
상점 결제는 서버 `star_ledger` 에 **음수로** 적히므로 앱은 응답의 `stars` 를 다시 받기만 하면 된다.

> ⛔ **앱에 잔액 변수를 새로 만들지 말 것.** 두 값이 생기는 순간 어긋나고,
> 그때부터 어느 쪽이 맞는지 알 수 없다(서버가 `balance` 컬럼을 안 둔 것과 같은 이유).

## 3. 입구 중복 금지 — 여기서 갈린다

이 앱이 반복해서 낸 사고가 «같은 것을 두 곳에서 그리기»다(dayPanel·알레르기·급식). 그래서:

- **부모 진열대는 드로어에만.** 홈에 또 놓지 않는다
- **승인과 티켓 바꿔주기는 미션 화면 한 곳에 모은다.** 따로 화면을 파면 부모가
  «확인할 게 두 군데»가 되고, 하나만 보고 끝냈다고 여긴다
- **아이 상점은 별의 길에서만.** 별을 보는 자리와 별을 쓰는 자리가 이어져야 한다

## 4. 한 바퀴 (이게 다 돌면 기능이 산 것이다)

```
부모  드로어 → 진열대 세팅 → 「유튜브 30분 · ★5 · 주 2회」 올림
아이  아이 모드 → 미션 완주 → ★ 충전 → 별의 길 → 상점 → ★5 로 바꾸기 → 🎟️ 티켓
부모  (푸시 «티켓으로 바꿨어요») → 미션 화면 «티켓 바꿔주기» → [바꿔줬어요]
아이  «내 티켓» 기다리는 중 → 받았어요
부모  미션 화면 «확인해 주세요» → 독서록 보고 [보너스 ★2]
아이  대형 스티커 팝업 + 축하 모션
```

## 5. 규칙 (서버가 이미 막고 있는 것 — 화면이 어기지 말 것)

- **잔액 부족·주간/월간 상한은 서버가 센다.** 화면은 «버튼을 가리는 것»으로 끝내지 말고
  서버가 돌려주는 `LIMIT_EXCEEDED` 를 사람 말로 보여준다 (가리기만 하면 우회된다)
- **2차 보너스는 한 번만.** 재승인은 `DUPLICATE`
- **티켓엔 보상 이름이 박혀 있다** — 진열대에서 지워도 티켓은 남는다
- **아이는 바꾸는 것만.** 진열대 편집·보너스 승인·칭찬 발송은 **부모만**
- **중복 판정은 KST** — `date(created_at,'+9 hours')`. 앱이 날짜를 따로 세지 않는다
