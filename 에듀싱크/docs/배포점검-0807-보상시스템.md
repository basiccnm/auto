```bash
npx wrangler d1 execute eduthink-db --remote --config workers/site-renderer/wrangler.toml ^
  --file scripts/migrate_pin_2026-08-07.sql
```

**검증 (문장 18개 · 오류 0 · 연쇄삭제 정상 — 격리 SQLite 로 실측 완료)**

| 만드는 것 | 개수 |
|---|---|
| 표 | `parent_mission_templates` · `store_items` · `reward_orders` · `child_mode_config` · `reactions` · `mission_verifications` |
| 인덱스 | 7개 |
| 기존 표 확장 | `orders.payment_channel`(기본 `'inapp'`) · `orders.child_limit`(기본 1) · `child_mode_config.fail_count` · `child_mode_config.locked_until` |

- **추가만 한다(add-only).** 기존 컬럼 의미를 바꾸지 않는다 — DB 절대규칙
- **자녀 삭제 시 연쇄삭제**가 붙어 있다(실측 확인). 아이를 지우면 상점·티켓·검증로그가 같이 사라진다
- ⚠ `children.trial_ends_at` 은 **일부러 뺐다.** `trial_expires_at` 이 이미 있고 코드 45곳이 쓴다.
  체험 만료일이 두 칸이 되면 어느 쪽이 진짜인지 아무도 모른다

## B. 워커 배포

```bash

```

🔴 **출력 마지막 줄이 `Uploaded eduthink-site-renderer` 인지 눈으로 확인.**
다른 이름이 나오면 라이브에 아무것도 안 올라간 것이다.

### 바뀐 파일
- `src/api_reward.js` — 보상 13개 + **PIN 3개 신규**

- `src/index.js` — 화이트리스트에 `/api/v1/child-mode/` 추가
  ⚠ 이게 빠지면 PIN 이 **에러 없이 조용히 HTML 404 로 샌다**(07-27 supplies 와 같은 함정)

### 배포 후 확인
```bash
curl -s https://<워커주소>/api/v1/child-mode/pin
```

→ `AUTH_REQUIRED` 가 나오면 **라우트가 살아 있는 것**(404 면 화이트리스트를 다시 볼 것).
