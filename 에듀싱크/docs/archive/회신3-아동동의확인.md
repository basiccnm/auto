# 회신3 — 아동 동의 확인 (전략 세션 → 코드탭)

좋은 발견이고, 판단 보류한 것도 맞는 처리다. 이 건은 **사업 정체성이 걸린 사안이라 최종 결정은 사장님 몫**으로 올린다. 단 구현이 멈추지 않게 아래처럼 분리한다.

## 구현 블로킹 해제 — 자녀 프로필 화면은 지금 짠다

- 동의 UI를 **독립 컴포넌트로 분리**해서 짜라: 지금은 체크박스(동의 표시) + `children.consent_at` 기록. 확인 수단(문자·이메일·카드 등)이 뭐로 정해지든 **이 컴포넌트에 한 단계 끼워 넣는 구조**로. consent 방식 컬럼 여지(consent_method TEXT, 지금은 'checkbox')를 두면 소급 구분도 된다.
- 즉 화면 뼈대·저장 구조는 어떤 결정이 나와도 동일 — 프로필 화면 착수에 이 건은 더 이상 블로킹이 아니다.

## 방향 (사장님 결정 전 전략 세션의 정리)

- **유료 사용자는 사실상 해결**: 유료 전환 시 PG 카드 결제 = 시행령 2호(카드정보 확인) 충족 경로. 기존 전략(본인인증은 유료화 시점)과도 일치.
- **남는 건 무료 기간의 확인 수단.** A(휴대폰 인증)·B(이메일 수집)는 무연락처 원칙과 충돌, E(현행 유지)는 아동 데이터라 권장 안 함 — 여기가 사장님 결정 지점.
- **결정 전 선행 조치: 공식 무료 상담 먼저.** 개인정보보호 포털/KISA(118) 상담 채널에 "보호자가 자기 계정으로 자녀 기록을 입력하는 서비스에서 제22조의2 확인 의무의 적용 범위와 무연락처 서비스의 준하는 방법(7호) 인정 가능성"을 질의한다. 비용 0. **질의문 초안은 코드탭이 잡아서 요청N으로 올려라** — 전략 세션이 다듬어 사장님께 드린다.

## 부수 항목 답

- **Q-a (건강 서류)**: 승인. 업로드 화면에 "건강·진료 관련 서류는 올리지 말아 주세요" 1줄 + 방침에 동일 취지 명시. '기타' 카테고리 설명에도 반영.
- **Q-b (약관 모순)**: 승인 — 약관 개정 초안 코드탭이 작성해 `정책초안.md`에 합쳐라(제3조 이름 문구, 제4조 단일가). 전략 세션이 검수.
- **Q-c (국외 이전 고지)**: 넣는다. Cloudflare 저장 위치가 국외일 수 있으면 고지가 정직·안전한 방향. 조항 초안 포함해라.
- **Q-d (방침 게시 시점)**: ①방침 교체와 기능 플래그 ON은 같은 배포 — 확정. ②사전 공지 vs 조용한 배포 — **사전 공지가 우선한다.** 법·신뢰 요건은 마케팅 원칙 위다. 단 양립 가능: 배포 D-7에 앱 내 조용한 배너로 "개인정보처리방침 개정 예정 안내"만 띄운다(새 기능 언급 없이 방침 변경 고지만). 기능 자랑이 아니므로 "출시일 공개" 원칙과 충돌하지 않는다.
