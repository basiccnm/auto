## 🔴 결정 요청 — 무료 개방 기간에 콘텐츠가 7일 뒤 잠깁니다

### 상황
지시서 v3 1-3에 이렇게 돼 있습니다.
> "**무료 개방 기간: 배포일~유료 전환일.** 유료 전환일 = 학사일정 데이터 중 가장 빠른 2학기 개학일"
> "한도 로직은 다 만들되, 전환일 전에는 **전원 이용권 활성 취급**하는 플래그."

그런데 기존 코드 실사 결과, **그 플래그(`BETA_FREE_ALL`)가 자녀 수 한도만 관장하고 콘텐츠 잠금은 관장하지 않습니다.**

콘텐츠 잠금(급식·시간표·학사일정)은 자녀별 `trial_expires_at`(1주일 체험 만료일)만 봅니다.

### 그래서 지금 이렇게 동작합니다
1. 사용자가 자녀 등록 → 7일 이용권 부여 → 전체 열림
2. **7일 뒤 → 다시 잠김** (무료 개방 기간인데도)

→ **"개학 전까지 무료"가 실제로는 "가입 후 1주일만 무료"입니다.**
로드맵 v3 1절의 마케팅 문구("개학 전까지 무료가 마케팅 문구가 됨")가 성립하지 않는 상태입니다.

### 코드탭 제안
플래그가 **①자녀 수 한도 ②콘텐츠 게이팅 ③기록 20건 한도(신규)** 셋을 모두 관장하게 통일.
전환일에 플래그 하나만 내리면 세 가지가 동시에 정상화됩니다.

이름도 `BETA_FREE_ALL` → **`FREE_OPEN_UNTIL`(날짜 설정값)**로 변경 제안.
지시서 v3 1-3의 "코드에 하드코딩 금지, 설정값으로"에 부합합니다. 상수라 add-only 원칙과 무관합니다.

### ❓ 전략 세션에 묻는 것

**Q1. 무료 개방 기간에는 1주일 체험과 무관하게 전원 열어두는 게 맞습니까?**
- (A) 맞다 — 개방 기간엔 체험 만료 무시하고 전부 열기 *(코드탭 제안)*
- (B) 아니다 — 개방 기간에도 1주일 체험 규칙은 그대로 두기
- (C) 다른 안

**Q2. (A)라면, 전환일에 기존 사용자는 어떻게 됩니까?**
개방 기간에 가입해서 체험 7일이 이미 지난 사용자는, 전환일이 오는 순간 **즉시 잠깁니다.**
- (A-1) 그대로 즉시 잠금 (결제 유도)
- (A-2) 전환일에 전원 체험 7일 재부여 (연착륙)
- (A-3) 다른 안

> 참고: 이건 "개학 첫 주에 급식·시간표가 갑자기 잠기는" 시점이라, 이탈이 가장 크게 갈릴 지점으로 보입니다.

## 📎 참고 — 실사로 확정된 것들 (결정 완료, 회신 불필요)

전략 세션의 로드맵 정본에 이미 반영돼 있으면 무시하셔도 됩니다.

| 항목 | 결과 |
|---|---|
| **이용권 구조** | `passes` 신설 **취소**. 만료일은 기존 `children.trial_expires_at`, 결제는 기존 `payments`, 연장 이어붙이기 로직 **이미 구현돼 있음** |
| **가격표** | `PAY_MATRIX`가 이미 존재하고 **1개월 1명이 이미 3,500원**. 자녀 수 차원만 제거해 단일가화 (1개월 3,500 / 3개월 9,500 / 6개월 16,800 / 12개월 29,400) |
| **자녀 상한** | **3명 확정** (문서 5명 ↔ 코드 3명 충돌 → 코드가 맞음). 헤더 2×2 그리드가 3명 기준으로 이미 구현됨 |
| **인원별 추가과금** | 자녀2 +500원 · 자녀3 +1,000원 **폐지**. 단일 기간권에 3명 포함 → 문구 전면 교체 "이용권 하나로 자녀 3명까지" |
| **PG** | 미부착 확인. `/pay`는 더미(DB 기록만) |
| **NEIS 홈페이지 필드** | `HMPG_ADRES` **이미 적재 중**. 12,563개교 중 **12,504개(99.5%)** 보유 → 추가 수집 불필요 |
| **학교 서식 기능** | 내림(기능 플래그 오프, 코드 보존). 학교마다 양식이 달라 오사용 리스크 → "학교 홈페이지 바로가기" 카드로 교체 |
