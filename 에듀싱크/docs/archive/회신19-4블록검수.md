## 0. 총평
4블록 로컬 완료 + `index.js` 충돌 0 + 스모크 전부 200. 그리고 **원칙6이 실제로 값을 냈다** — 짓는 도중 `/about` 500, KST/UTC 하루 밀림, 알레르기 데이터 유실을 잡아냈다. 이게 "1회 진행 후 1회 검수"의 목적 그대로다. 잘했다.

## 1. 진행 중 고친 것 — 전부 승인
- **① `/about` 500(단일가화 잔재):** 승인. 사용자에게 보이던 페이지가 죽어 있었으니 바로 고친 게 맞다. 네 작업 밖 버그라도 노출 페이지면 고치는 게 옳다.
- **② KST/UTC 하루 밀림:** **강한 승인.** 학교 데이터는 전부 한국 날짜 기준 — 새벽에 급식·시간표가 전날로 뜨면 신뢰가 깨진다(조회수에 직접 타격). 실측까지 좋다. `todayYmd()`와 규칙 통일도 맞다.
- **③ 급식 알레르기 `dishes` 객체 배열 개정:** **승인(계약 확정).** 정본 원칙2 정확한 적용 — 있는 데이터(`allergens`)를 버리면 나중 "알레르기 하이라이트" 만들 때 API를 다시 고치고 앱 버전 호환까지 깨진다. `[{name, allergens}]` 유지. 이름만 쓰는 화면은 `d.name`. 되돌리지 말 것.
- **④ `dev-seed` → accounts 연결:** 승인. QA 도구가 계정 체계와 붙어야 이행 테스트가 진짜가 된다.

## 2. 🔴 통합 처리 — 순서 승인
1. **삭제 연쇄 단일화 — GO, 최우선.** 두 벌은 안전 사고 지점이다. 한 곳 놓치면 **R2에 아이 사진이 영구히 남는다** = 정본 §4.5·보안 원칙 정면 위반. `data_children.js` 공용 모듈로 승격해 **단일 진입점 복원**. `r2KeysOf`·`R2_DERIVED_SUFFIXES`도 같이. 이게 먼저다.
2. **블록5 임시 인증 → 블록1 교체.** `resolveOwner→resolveAuth`, `isSubscriber→orders 기반`, 그리고 **`requireReauth`를 즉시 잠글 것**(지금 무조건 통과 = 계약 §3.4 "삭제·수정 재인증"이 안 걸린 상태). 한 줄로 5개 잠긴다니 바로.
3. **`AUTH_SECRET`:** 로컬은 상수로 돌아도, **배포 전 `wrangler secret put AUTH_SECRET` 필수** — 배포 체크리스트에 못박아 둔다(대표님 승인 시).

## 3. 확인 요청 5건 — 확정
1. **급식 `dishes` 객체 배열:** **승인**(§1-③).
2. **시간표 `timetable_overrides` 병합:** **승인.** 웹·앱이 다른 과목을 보여주면 안 된다. 반 단위 크라우드소싱 수정본은 이 서비스 자산(로드맵)이라 앱도 똑같이 덮어써야 한다. 8줄이면 하라.
3. **`total` 의미:** "현재 페이지 건수"는 오해 소지라 지양. **`total`은 값싸게 셀 수 있을 때만 실제 전체값, 아니면 `null`.** 학교(12,563행)처럼 스캔 비용 큰 목록은 `null` + **cursor로 페이징**(봉투 §5.1이 그걸 위한 것). 앱은 total 없으면 "더 보기"로 처리.
4. **기록 정렬 `id DESC` + 앱이 `period`로 그룹핑:** **승인.** 서버는 안정 커서 스트림, 학년·학기 묶기는 앱이 `period` 객체로. `period`를 응답에 넣어둔 이유가 이거다.
5. **가격 할인율:** **대표님 확정(2026-07-23).** 자녀 1명당 1개월 1만 / 3개월 2.7만 / 6개월 5.1만 / 12개월 9.6만. 작업 기준값 → 확정값으로 승격.
