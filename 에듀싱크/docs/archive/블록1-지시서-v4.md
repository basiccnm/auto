## 1. 확정 결정 (기존 코드 실사 질문에 대한 답 포함)

1. **유료 모델 = "기간권" 단건 결제. 자동결제(빌링) 아님.** 1개월 3,500원(가격은 상수로). 기존 이용권(D-N 남은 일수) 구조를 그대로 재사용. **PG 연동은 이번 블록 범위 밖의 별도 트랙** — 이번에는 한도 로직·이용권 안내·구매 화면(PG 미연동 상태는 숨김 플래그)까지만. PG 후보는 토스페이먼츠/포트원 계열, 심사 기간 감안해 유료 전환일 전 부착 목표.
2. **무료/유료 경계:** 기존 기능(급식·시간표·일정·커뮤니티)의 이용권 정책은 현행 유지. **자녀기록은 이용권 없이 자녀 1명 + 기록 20건까지 무료.** 초과 시 **신규 업로드만 잠금**(열람·검색·삭제는 항상 가능 — 쌓은 걸 볼모로 잡지 않는다). 이용권 활성 시 자녀 3명·기록 1,000건/자녀(어뷰징 상한 — 자녀 등록=학교 열람 해제이므로 3명으로 묶음. 4명 이상 실제 다자녀 가정은 고객센터 수동 예외). 자녀 추가 과금 없음 — 기존 코드의 "자녀2 +500원·자녀3 +1,000원" 인원별 과금은 폐지. 방과후·활동 페이지는 무료.
3. **무료 개방 기간 처리 (2026-07-19 확정):** 플래그는 `FREE_OPEN_UNTIL`(날짜 설정값, 구 BETA_FREE_ALL 대체)로 통일하고 **①자녀 수 한도 ②콘텐츠 게이팅 ③기록 20건 한도 셋을 모두 관장.** 개방 기간(배포~전환일)에는 1주일 체험 만료를 무시하고 전원 전체 개방(Q1=A). **전환일 도래 시 전원에게 체험 7일 일괄 재부여(Q2=A-2, 연착륙)** — 개학 첫 주(가치 최고 체감기)를 쓰게 한 뒤 잠금이 오도록. free_trials의 계정당 1회 차단은 이 일괄 재부여에 한해 무시. 이후 신규 가입자는 기존 규칙(등록 시 7일 체험) 그대로.
4. **자녀기록은 소셜 로그인 필수.** 업로드 데이터는 기기 바뀌어도 유지돼야 하므로. 기존 기능은 기존 정책 유지.
5. **A-1 승인:** 기존 children 테이블 확장(INTEGER id 유지). birth_year(선택)·consent_at 컬럼 추가만. add-only.
6. **A-2/A-3 승인:** 신규 테이블명 `activity_schedules`. 기존 personal_schedule(교시 개인일정, 최대 4행)은 **건드리지 않고 유지**, 신규 페이지가 학원·활동 데이터의 정본. 기존 데이터 이전은 안 함(표시만 유지).
7. **A-4 승인:** R2 버킷 신설(비공개). 생성은 배포 계정 작업이므로 실행 시점에 사장님 확인.
8. **A-5 결정:** FEATURE_MYPAGE 켜기. **마이페이지 = 자녀기록의 집** (아래 2절).
9. **A-6 승인:** 신규 테이블 전부 sync_to_d1 재적재 제외 등록.
10. **B-7 승인:** 브라우저(canvas) 리사이즈(긴 변 2000px, JPEG ~85) + 서버 측 4MB/장 상한.
11. **B-9 승인:** 기존 nickname은 목록·커뮤니티용 유지. 실명(name)은 identifiers에만, 기록 화면 표시 시에만 조인.
12. **B-10 확정:** school_year = 정수 코드 (초1=1 … 초6=6, 중1=7 … 중3=9, 고1=10 … 고3=12, 유치원 0 예약). semester = 1|2.
13. **B-11 승인:** 자녀 삭제 시 identifiers·records·activity_schedules + R2 원본 + 기존 personal_schedule·personal_events·schedule_settings까지 전부 파기.

## 2. 화면 위치·레이아웃 (목업은 이 스펙대로)

### ① 마이페이지 (신규 활성화) — 자녀기록의 집
위에서 아래로:
1. 자녀 스위처 — 기존 헤더 자녀 배지 패턴 재사용
2. 자녀 카드 — 이름·학교·학년반·이용권 상태(D-N)·[이용권 연장] 버튼
3. 기록 타임라인 (아래 ②)
4. 방과후·활동 바로가기 카드
5. 설정 — "내 아이 데이터, 이렇게 보호합니다" / 개인정보처리방침 / 자녀·데이터 전체 삭제
- **업로드 버튼 = 우하단 플로팅 버튼(FAB).** 기존 공유 FAB 패턴 재사용, 마이페이지에서만 노출.

### ② 기록 타임라인
- 상단 고정: 종류 필터 칩 6종(상장/통지표/성적표/자격증/활동/기타) + 검색창
- 본문: "3학년 1학기" 식 학년·학기 섹션 헤더 + **3열 썸네일 그리드**, 최신이 위
- 업로드 플로우: 사진 선택(다중 가능) → 종류 탭 1번 → 저장. 제목·시기는 자동값("3학년 1학기 상장"), 수정은 선택. **다중 업로드 시 시기 일괄 지정 바** (백필용)
- 무료 20건 초과 시: FAB에 자물쇠 + 탭하면 이용권 안내 바텀시트

### ③ 방과후·활동 페이지 (신규 별도 페이지)
- 진입점 2곳: 마이페이지 카드 + 시간표 탭 하단 요약줄
- 상단 자녀 스위처 공유
- **주간 뷰: 월~일 가로 열 × 세로 시간축(14~22시).** 일정 블록 탭하면 수정
- [+ 등록]: 이름 / 유형(학원·방과후·활동) / 요일(복수) / 시작·종료 시각 / 유효기간(시작~종료일, 기본값 오늘~학기말)
- **시간표 탭 하단에 읽기 전용 한 줄**: "오늘의 방과후: 수학학원 16:00~18:00" → 탭하면 이 페이지로

### ④ 자녀 프로필 등록/수정
- 이름 / 출생연도(선택) / 학교·학년·반(기존 구조) / **보호자 동의 체크(필수)**: "본인은 보호자이며 자녀 기록의 등록·보관에 동의합니다"
- 소셜 로그인 안 된 상태에서 기록 기능 진입 시 → 기존 로그인 화면으로 유도

### ⑤ 광고(애드센스) 배치 규칙
- **허용 위치: 공개 정보 화면만** — 학교정보·급식·일정 탭 콘텐츠 하단
- **금지 위치: 자녀기록·방과후 페이지·마이페이지·결제 화면 전부** (아이 데이터 화면은 광고 청정 구역 — 신뢰+정책 리스크)
- 이용권 활성 사용자는 광고 전체 제거
- 자사(즈마장 등) 링크는 광고 슬롯이 아니라 "서비스 소개" 메뉴에 별도 배치
- 애드센스 스크립트가 개인 데이터 API 응답·DOM에 접근할 수 없는 구조 확인

## 3. DB (v2 스키마 + 실사 반영)

- `children` — **기존 테이블에 추가만**: birth_year(선택), consent_at
- `identifiers` — 신설: child_id(FK, unique), name, created_at. **분리 규칙: 이름은 이 테이블에만. records·activity_schedules·children·로그·분석 어디에도 이름 저장 금지. 화면 표시 시점에만 조인. 광고/분석 코드는 접근 경로 자체가 없어야 함. name은 전용 접근 계층(단일 모듈/함수)을 통해서만 읽고 쓴다 — 일반 쿼리에서 identifiers 직접 조인 금지, 이름 검색용 인덱스 만들지 않음(인덱스는 child_id만).**
- `records` — 신설: record_id, child_id, category(6종 enum), school_year(정수 코드), semester(1|2), title, note, image_ref, created_at, updated_at
- `activity_schedules` — 신설: schedule_id, child_id, type(academy|afterschool|activity), name, days_of_week(복수), start_time, end_time, start_date, end_date, created_at, updated_at
- 예약(주석만): grades(record_id FK로 원본 연결), knowledge_base, chat_state
- **신규 테이블 전부 sync_to_d1 재적재 제외**

## 4. 시기 자동 추정 (v2 유지)

업로드 시점: 3~8월 → 해당 연도 1학기, 9~12월 → 2학기, 1~2월 → 직전 학년도 2학기. 학년은 자녀 프로필 기준. 다중 업로드 시 일괄 지정 가능.

## 5. 보안·비용 가드레일 (v2 유지 + 보강)

1. 이미지: 브라우저 리사이즈(2000px/85) + 서버 4MB 상한, R2 비공개 버킷, 공개 URL 금지, 인증/서명 접근만
2. 상한: 무료 자녀 1·기록 20 / 이용권 자녀 3·기록 1,000 (전부 상수). 헤더 자녀 스위처는 기존 2×2 그리드(최대 3명) 그대로 유지 — 재작업 불필요
3. at-rest 암호화 + HTTPS
4. 광고/분석 코드는 records·activity_schedules·identifiers 접근 불가
5. 모든 조회 owner_token→child_id 검증 (+ 소셜 로그인 계정 검증)
6. 업로드 이미지에 성명·학교명 인쇄되어 있음을 전제로 취급

## 6. 정책·고지 (배포와 동시)

- **개인정보처리방침 개정:** 자녀 이름·출생연도(선택) 수집 추가, "업로드 이미지에 성명 등 포함될 수 있음" 명시, 보호자 동의 근거, 삭제 시 원본 포함 즉시 파기. **기존 사용자에게 변경 고지 배너 1회 노출.**
- **"내 아이 데이터, 이렇게 보호합니다" 페이지:** ①이름은 기록과 분리 보관 ②자녀별 데이터 격리 ③저장·전송 암호화 ④광고는 자녀 데이터 접근 불가 ⑤언제든 전부 삭제 가능
- **푸터 사업자 표시 채우기:** 대표자·주소·고객센터(값은 사장님이 제공), 통신판매업 신고번호 자리 마련 — 유료 전환일 전 필수
- **문구 통일:** 체험 관련 문구를 전 화면에서 1종으로 — "자녀 등록하면 1주일 무료 체험"
- **기존 인원별 과금 문구 전면 제거:** 등록 폼·구독 안내의 "자녀2 +500원/월 · 자녀3 +1,000원/월" → "이용권 하나로 자녀 3명까지" (단일 기간권 3,500원)

## 7. 함께 처리할 정비·버그 (블록1 범위)

- 비로그인 상태에서 QA계정 자녀 배지가 헤더에 노출되는 문제 확인·수정
- admin 테스트 자녀 등록 직후 이용 상태가 '만료'로 표시되는 불일치 확인
- 학교 상세 연락처 카드에 **학교 홈페이지 주소** 추가 — NEIS 학교기본정보 HMPG_ADRES 필드 (적재 여부 확인 후 없으면 적재 추가)
- **학교 서식 기능 내리기(삭제 아님, 기능 플래그 오프)** — 학교마다 양식이 달라 오사용 리스크. 그 자리에 "서식·가정통신문은 학교 홈페이지에서 — [홈페이지 바로가기]" 카드로 교체. 코드는 보존(수요 확인 시 학교별 검증 붙여 부활 가능)
