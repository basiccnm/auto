## Q1. 🔴 자녀 "이름" vs "별명" — 목업과 스키마 원칙이 충돌합니다

**충돌 지점**
- **목업 ④(자녀 프로필)**: 입력란이 **이름 하나**뿐입니다.
- **지시서 v4 3절 / 로드맵 절대규칙 ①**: 실명은 **`identifiers` 테이블에만**. `children`·`records`·로그·분석 어디에도 저장 금지.
- **그런데 `children.nickname`은 헤더 자녀 스위처(2×2 칩)에 그대로 찍힙니다.** 커뮤니티 표시명과도 연결됩니다.

→ 목업대로 이름 하나만 받아 그걸 `nickname`에 넣으면 **식별자 분리 원칙이 정면으로 깨집니다.** 실명이 헤더·커뮤니티에 노출됩니다.

**선택지**
| 안 | 내용 | 대가 |
|---|---|---|
| **A** | 이름·별명 **둘 다 받되 별명은 자동 채움**("첫째/둘째/셋째"), 이름은 `identifiers`에만 | 입력 1칸 늘어남(목업과 다름) |
| B | 이름만 받고 별명은 이름 첫 글자 등으로 자동 생성("김○○") | 여전히 실명 일부가 `children`에 남음 |
| C | 별명만 받고 실명은 안 받음 | 블록2·3 발달 AI가 이름을 못 씀(로드맵 전제 훼손) |

> **코드탭 의견: (A).** 목업 우선 원칙과 스키마 원칙이 부딪히는 **유일한 지점**이라 임의 결정하지 않았습니다. 다만 식별자 분리는 **로드맵 4.1의 "절대 규칙"**이고 정책 문서에도 "이름은 기록과 분리 보관"으로 이미 학부모에게 약속할 문구를 써둔 상태라, 이쪽을 깨는 건 위험하다고 봅니다. 별명을 자동 채우면 사용자 입력 부담은 실질적으로 안 늘어납니다.

## Q2. `purgeAllPage`가 없는 기능을 안내하고 있습니다

전체 삭제 화면(이미 구현)에 이렇게 써 있습니다:
> "기록을 남기고 싶으시면 **먼저 이미지를 내려받아** 주세요."

**그런데 내려받을 수단이 없습니다.** 지시서 v4 Non-goals에 "공유·내보내기 기능 없음"이 명시돼 있습니다.

- **(A) 그 문장을 지운다** — 없는 기능을 안내하지 않음
- (B) 개별 이미지 다운로드만 만든다 — 원본 1장씩 저장(내보내기 기능 아님으로 해석)
- (C) 일괄 다운로드(zip) — 지시서 Non-goals 위반, 범위 확장

> **코드탭 의견: (A).** 제가 목업 ⑥을 옮기면서 넣은 문장인데, 지시서 범위를 확인 안 하고 쓴 제 실수입니다. 다만 "원본까지 영구 삭제"를 경고하면서 백업 수단이 전무한 게 사용자에게 가혹한지는 판단이 필요합니다.

## Q3. 목업 ④의 "1주일 무료 체험" 문구

목업 ④ 하단에 "등록하면 **1주일 무료 체험**이 시작돼요"가 있습니다.
그런데 작업로그 6절에서 **개방 기간 중 이 문구는 사실과 달라 제거**하기로 확정했고, 등록 완료 화면에서는 이미 뺐습니다.

- **(A) 조건 분기** — 개방 중이면 "우리 아이 학교 개학 전까지 무료", 개방 끝나면 "1주일 무료 체험"
- (B) 항상 개방 문구 — 전환 후엔 틀린 말이 됨
- (C) 문구 제거

> **코드탭 의견: (A).** 목업 v1이 개방 기간 결정 **이전**에 만들어진 캡션이라, 목업 우선 원칙의 예외로 봅니다. 확인만 부탁드립니다.

## 참고 — 설계에서 미리 막아둔 것 (회신 불필요, 보고용)

**① 이미지 서빙 URL을 일부러 연번(`records.id`)으로 잡았습니다.**
UUID를 URL에 넣으면 "URL을 아는 사람 = 권한자"라는 잘못된 보안 모델이 생깁니다. 소유권은 `owner_token → child_id → record`를 SQL 한 줄로 매 요청 검증하고, 실패는 **403이 아닌 404**로 응답합니다(존재 여부 자체를 숨김).

**② 썸네일이 삭제 약속을 깰 수 있습니다.**
타임라인이 3열 그리드라 2000px 원본 20장을 그대로 뿌리면 첫 화면이 6~8MB입니다. 썸네일이 필요한데, `deleteChildCascade()`는 지금 `image_key` **하나만** 지웁니다. 파생 키를 함께 지우게 고치지 않으면 **"언제든 원본까지 전부 삭제" 약속이 조용히 깨집니다.**
→ 배포 직전 잡았던 `env` 미전달 사고와 같은 계열(조용히 실패하는 삭제)이라, 업로드 구현 시 최우선으로 처리하겠습니다.

**③ 함수명 충돌 회피** — `schoolYearOf()`가 이미 있고 뜻이 다릅니다(NEIS 학년도 문자열 "2026"). 신규 학년 정수코드 함수는 `gradeCodeOf`로 명명합니다.

**④ FAB 좌표 충돌** — `shareFab()`이 `layout()`에서 전 페이지에 주입되며 목업의 업로드 FAB와 정확히 같은 자리입니다. 마이페이지에서는 공유 FAB를 숨기거나 위로 밀어야 합니다.
