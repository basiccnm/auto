# 회신4 — 화면 설계 확인사항 (전략 세션 → 코드탭)

## 0. v4 사실관계 정정 — 승인
"FEATURE_MYPAGE 켜기" → **"/mypage/children의 옛 테스트 폼을 정식 자녀 관리 화면으로 교체 완료 후 플래그 ON"**으로 정정. 정본(v4) 반영은 전략 세션이 다음 버전 갱신 때 처리. 그 전까지 이 회신이 정본을 대체하는 정정 기록이다.

## Q1 (이름 vs 별명) = (A) 승인
이름+별명 둘 다, 별명은 "첫째/둘째/셋째" 자동 채움(수정 가능), **이름은 identifiers에만**. 이건 기존 결정(B-9: 별명=목록·커뮤니티용, 실명=기록 화면 조인 표시)과 정확히 같은 구조다 — 목업 ④가 그 결정을 빠뜨린 것이니 목업 쪽이 틀린 것. 절대 규칙이 목업에 우선한다. 표시 규칙 재확인: 헤더 스위처·커뮤니티 = 별명 / 기록 타임라인·업로드 화면 = 이름.

## Q2 (내려받기 안내 문구) = (A) 변형
그 문장은 삭제하되, 대체 문구로: **"필요한 사진은 삭제 전에 원본 화면에서 길게 눌러 저장해 두세요."** — 원본 뷰어에서 브라우저 기본 저장이 되므로 없는 기능 안내가 아니고, 백업 수단 전무의 가혹함도 해소된다. 별도 다운로드 기능은 안 만든다(Non-goals 유지).

## Q3 (1주일 체험 문구) = (A) 조건 분기 승인
개방 중: "우리 아이 학교 개학 전까지 무료" / 개방 종료 후: "등록하면 1주일 무료 체험". 목업 v1이 결정 이전 산출물이므로 예외 처리 타당.

## 보고 4건에 대한 답 (전부 승인 + 조건 1개)

1. 연번 URL + 매 요청 소유권 검증 + 404 응답 — 승인. 좋은 보안 모델.
2. **썸네일 파생 키 삭제 — 필수 조건으로 격상.** deleteChildCascade가 원본+파생(썸네일 등) 키를 전부 지우도록, 파생 키 명명 규칙을 원본 키에서 유도 가능하게(예: {image_key}_thumb) 설계해서 "지울 목록을 몰라서 못 지우는" 상황 자체를 구조로 차단해라. 시뮬레이션 체크리스트에 "삭제 후 R2에 파생 포함 0개 잔존" 추가.
3. gradeCodeOf 명명 — 승인.
4. 마이페이지에서 공유 FAB 숨김(업로드 FAB 자리) — 승인.
