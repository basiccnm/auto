# 블록1 "자녀기록" — Claude Code 작업 지시서

작성: 2026-07-19 | 대상: 배포 중인 "우리아이학교정보(에듀싱크)" 앱
성격: 기존 앱 위에 얹는 업데이트. **새 앱 아님. 기존 급식·시간표·학사일정 기능과 owner_token(쿠키) 구조는 그대로 유지.**

## 0. 목표와 일정

- 자녀의 상장·통지표·성적표·자격증·활동 기록을 사진으로 업로드하고, 자녀별 타임라인으로 정리·열람하는 기능 + 학원·활동 스케줄 등록.
- **이번 블록에 AI 없음.** 저장·정리·열람만. 단, 여기서 만드는 저장 형식이 미래 AI(리포트·대화)의 입력 형식이므로 스키마는 아래 정의를 정확히 따를 것.
- 일정: **8월 15일 전후 개발 완료 → 8월 중하순 조용한 배포**(심사 버퍼 포함) → 9월 초 새학기 공지. 범위를 늘리지 말고 이 일정을 지키는 쪽으로 판단할 것.

## 1. 기능 범위 (딱 이만큼만 — 추가 구현 금지)

1. **자녀 프로필** — 이름 + 출생연도(선택) + 기존 앱의 학교·학년·반 설정 연결. 자녀 여러 명 지원. 등록 직전 **보호자 동의 체크(필수) 1회**: "본인은 보호자이며 자녀 기록의 등록·보관에 동의합니다." 이름은 입력값 그대로 사용(본인인증·검증 없음).
2. **기록 업로드** — 사진/이미지 파일 업로드 → 종류를 사용자가 직접 선택(상장/통지표/성적표/자격증/활동/기타) → 시기(학년·학기)는 자동 추정값을 기본으로 깔고 사용자가 수정 가능 → 저장.
3. **타임라인 열람·검색** — 자녀별 → 학년·학기로 그룹핑된 타임라인. 종류 필터 + 제목 검색.
4. **학원·활동 스케줄** — 이름, 유형(학원/방과후/활동), 요일(복수), 시작·종료 시각, **유효기간(시작일~종료일)**. 등록하면 기존 시간표 화면에 학교 시간표와 함께 표시. 격주·복잡 반복은 만들지 않음.
5. **개인정보처리방침 갱신 + "내 아이 데이터, 이렇게 보호합니다" 안내 페이지** — 아래 6절.

### Non-goals (하지 말 것)

- OCR 없음 — 자동 분류도, 성적 숫자 추출도 전부 fast-follow. 이번엔 안 붙임.
- 본인인증 없음 — 이름은 검증 없이 입력값 그대로. 연락처·주민번호·정확한 생년월일 등 추가 식별정보 수집 없음(출생"연도"까지만, 선택).
- **이름을 records/schedules 등 기록 테이블·로그·분석에 저장하지 말 것** — 아래 identifiers 분리 구조 필수.
- 로그인/회원가입 없음. 기존 owner_token 방식 유지.
- 공유·내보내기 기능 없음.

## 2. DB 스키마

기존 DB에 테이블 추가. 명명은 기존 코드베이스 컨벤션에 맞추되 구조는 아래대로.

### children

- child_id (uuid, PK)
- owner_token 연결 (기존 방식대로)
- birth_year (출생연도, 선택 — 블록2 발달 AI용 자리)
- consent_at (보호자 동의 시각)
- 학교·학년·반 — 기존 앱의 학교 설정 데이터와 연결(기존 구조 재사용)
- created_at

### identifiers (식별자 분리 테이블 — 보안 핵심, 반드시 별도 테이블)

- child_id (FK, unique)
- name (자녀 이름)
- created_at

**분리 규칙:** 이름은 이 테이블에만 존재. records·schedules·children·로그·분석 이벤트 어디에도 이름 저장 금지. 화면 표시 시점에만 조인. 목적: DB의 다른 테이블이 유출돼도 "누구의 기록인지"가 안 이어지게. 가능하면 접근 계층/권한도 분리(광고·분석 코드는 이 테이블 접근 경로 자체가 없어야 함).

### records

- record_id (uuid, PK)
- child_id (FK)
- category (enum: award | report_card | grade_sheet | certificate | activity | other)
- school_year (학년: 초1~고3에 해당하는 값. 유치원 확장 여지 남길 것)
- semester (1 | 2)
- title (기본값 자동 생성: "{학년} {학기} {종류}", 수정 가능)
- note (텍스트, 선택)
- image_ref (스토리지 참조. 원본 이미지)
- created_at, updated_at

수정이력 관련: 별도 이력 테이블은 만들지 않음. 원본 = 이미지 자체(불변), 확정 = 메타데이터(수정 가능)로 충분.

### schedules

- schedule_id (uuid, PK)
- child_id (FK)
- type (enum: academy | afterschool | activity)
- name
- days_of_week (복수)
- start_time, end_time
- start_date, end_date (유효기간 — 방학 특강과 학기 정규 학원을 같은 구조로 담는 핵심)
- created_at, updated_at

### 예약 자리 (테이블은 만들지 말고, 스키마 문서/마이그레이션 주석으로만 예약)

- grades — records 파생, 과목·점수/등급 (fast-follow: OCR 구조화 시)
- knowledge_base — 공용 발달 콘텐츠 (블록2)
- chat_state — 자녀별 대화 상태 (블록4)

## 3. 시기 자동 추정 규칙

- 업로드 시점 기준: 3~8월 → 해당 연도 1학기, 9~12월 → 2학기, 1~2월 → 직전 학년도 2학기.
- 학년은 자녀 프로필의 현재 학년에서 계산.
- 백필 지원이 핵심: **다중 업로드 시 시기를 일괄 지정**할 수 있게 할 것(작년 상장 몰아 올리기 시나리오).

## 4. UX 요구 — 입력은 극단적으로 가볍게

- 업로드 플로우: 사진 선택 → 종류 탭 1번 → 저장. 끝. (제목·시기는 자동값, 수정은 선택사항)
- 다중 선택 업로드 지원.
- 타임라인: 자녀 선택 → 학년·학기 섹션으로 그룹핑, 최신 위. 썸네일 그리드 + 탭하면 원본.
- 스케줄 등록 화면은 "한 번 등록하면 반복"이 체감되게 — 등록 직후 시간표 화면에 바로 반영.

## 5. 보안·비용 가드레일 (부가기능 아님 — 필수)

1. 이미지는 업로드 시 리사이즈(긴 변 2000px, JPEG 품질 ~85) 후 저장. 원본 그대로 쌓지 말 것(용량 폭증 방지).
2. 상한: 자녀 5명/토큰, 기록 1,000건/자녀. 초과 시 안내 메시지(추후 정책으로 조정 가능하게 상수로).
3. 저장 시 암호화(스토리지 at-rest 암호화 설정 확인) + 전 구간 HTTPS.
4. 기록·스케줄 데이터는 child_id로만 연결. **광고/분석(애드센스·GA 등) 코드가 records/schedules 데이터에 접근하는 경로가 없어야 함.**
5. 자녀별 데이터 격리: 모든 조회 쿼리는 owner_token → child_id 검증을 거칠 것(다른 토큰의 자녀 데이터 접근 불가).
6. **업로드 이미지에는 성명·학교명 등이 인쇄되어 있음** — 이미지 스토리지는 비공개 버킷/경로로, 공개 URL 금지. 인증된 요청(또는 만료되는 서명 URL)으로만 접근.

## 6. 개인정보처리방침 갱신 + 데이터 보호 안내 페이지 (배포와 동시 공개 필수)

**개인정보처리방침:**

- 수집 항목 추가: 자녀 이름, 출생연도(선택), 학교·학년·반, 업로드한 기록 이미지, 학원·활동 스케줄.
- **업로드 이미지에 성명·학교명 등 개인정보가 포함될 수 있음을 명시**하고, 해당 이미지도 동일한 보호(암호화·비공개 저장) 적용을 명시.
- 수집 근거: 법정대리인(보호자)이 직접 입력·동의(등록 시 동의 체크). 아동의 직접 가입 없음 명시.
- 이용 목적: 이용자 본인의 자녀 기록 보관·열람 서비스 제공. 제3자 제공 없음.
- 보관·파기: 이용자가 삭제 시 원본 이미지 포함 즉시 파기. 삭제 기능(기록 단건 + 자녀 전체) 구현 포함.

**"내 아이 데이터, 이렇게 보호합니다" 안내 페이지 (설정·공지에서 접근, 9월 공지에 링크할 마케팅 자산):**

1. 이름은 기록과 분리 보관합니다 (식별자 분리)
2. 자녀별로 데이터가 격리됩니다
3. 저장·전송 모두 암호화합니다
4. 광고는 자녀 데이터에 접근할 수 없습니다
5. 언제든 전부 삭제할 수 있습니다 (원본 포함 즉시 파기)

## 7. 완료 기준 체크리스트

- 보호자 동의 체크 없이는 자녀 등록 불가
- 자녀 2명 등록(이름 표시 확인) → 각각 기록 업로드 → 타임라인이 자녀별로 분리되어 보임
- 이름이 identifiers 테이블에만 존재 — records/schedules/children 테이블·API 로그·분석 이벤트에 이름 미포함 확인
- 업로드 이미지가 인증 없는 공개 URL로 접근 불가 확인
- 3장 다중 업로드 + 시기 일괄 지정(백필) 동작
- 시기 자동 추정이 7월 업로드 기준 "1학기"로 잡히고 수정 가능
- 학원 등록(월·수 16:00~18:00, 7/21~8/22) → 시간표 화면에 표시, 종료일 지나면 미표시
- 다른 owner_token으로 접근 시 남의 자녀 데이터 조회 불가 확인
- 기록 삭제 시 스토리지 원본도 삭제 확인
- 이미지 리사이즈 동작(업로드 후 파일 크기 확인)
- 개인정보처리방침 페이지 갱신 반영
- 기존 기능(급식·시간표·학사일정) 회귀 없음
