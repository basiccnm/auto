## [상시 지시 — 병렬 트랙 보고] ※ 이전 전달분이 파일 이동과 엇갈려 유실됐을 수 있어 재전달

1. 작업로그.md **맨 위에 "진행 중 트랙" 표**를 두고 항상 최신 유지: 트랙명 / 만지는 파일 범위 / 상태 / **예상 완료 시각(ETA)**. 전략 세션이 15~30분 주기로 이 표를 감사한다.
2. 각 트랙을 시작하거나 끝낼 때 이 회신.md를 다시 읽어라 — 여기 중단·범위 축소 지시가 있으면 그게 우선.
3. 두 트랙이 같은 파일·같은 테이블을 만지게 되면 병렬을 풀고 순차로 전환 후 로그에 기록.
4. 지시서 범위 밖 작업은 시작 전에 요청.md로 물을 것 — 임의 확장 금지.
5. 우체통 파일 정리 시점 규칙(꼬임 방지): 회신.md를 읽고 archive로 옮기는 주체는 코드탭 하나로 통일. 전략 세션은 회신.md를 덮어쓰기만 하고 이동하지 않는다.
