# 블록1 지시서 v5 — 통합 (플랫폼 구조 + 회원가입 + 배포기조)

작성: 2026-07-19 저녁 (v4 대체) | 큰 변경 3가지 — ①플랫폼 구조(PC/모바일 별도) ②회원가입 대전환 ③배포 기조. v4 기능결정 대부분 유지. 이 문서가 최신 정본.

## 1. 플랫폼 구조 — HTS/MTS 모델 (오늘의 가장 큰 변경)
결정: PC 화면과 모바일 화면을 별도로 설계·개발. 반응형 하나로 커버 안 함.
- 데이터·기능·DB = 하나 공유 / 화면(겉) = 모바일용·PC용 둘로 분리
- 근거: 증권사 HTS(PC 분석)/MTS(모바일 간편)처럼, 기능 깊은 서비스는 기기별 사용방식이 근본적으로 달라 반응형으론 안 나옴.

### ⚠️ 화면 손질 아니라 "껍데기(앱 프레임) 재구축"이다
현재 앱은 한 페이지에 스크롤로 다 나열하는 웹사이트 껍데기. 모바일 원칙("한 화면씩 크게, 눌러 들어가고 뒤로 나오기")하려면 껍데기(레이아웃 래퍼·내비게이션·화면 전환)를 뜯어 새로 짜야 함. CSS 손질 수준 아님.
- 살리는 것: 데이터·기능·API·DB (속은 그대로)
- 뜯는 것: 껍데기 — 내비 프레임, 화면 전환(라우팅/스택), layout() 계열 래퍼
- 착수 전: 코드탭이 현 껍데기(layout·라우팅·공통 프레임) 실사 → 뜯는/살리는 범위를 요청으로 먼저 정리.

모바일 원칙(MTS): 한 화면=한 가지, 큰 글씨·큰 버튼, 눌러 들어가고 뒤로 나오는 앱형 전환, 하단 탭바/화면 스택 내비.
PC 원칙(HTS): 넓게 펼쳐 여러개 한눈에(성적 비교·궤적 그래프·리포트). 중고 진학분석에서 값어치.
앱: 웹이 본체. 나중에 모바일 화면을 하이브리드 껍데기로 감싸 앱스토어(푸시·카메라). 웹 자산 안 버림.
순서: 모바일 먼저 완성 → PC → 앱 껍데기. (PC 본격·네이티브앱은 중고기능·유료화 시점)

## 2. 회원가입 대전환
소셜 로그인 유지(비번은 소셜 위임) + 부모 정보 회원가입 폼.
- 필수: 부모 이름·휴대폰(문자인증)·주소. 자녀 연락처 안 받음.
- 자녀: 이름(identifiers 분리)·출생연도(선택)·학교학년반.
- 인증: 무료=문자 인증번호(저비용 자체) / 유료전환=대행사 본인인증 승격.
- 법근거: 시행령 제17조의2 제1호(동의+문자통지) 명문. KISA 질의 안 함(사장님 결정).
- 목적고지: 약관·방침에 "본인확인·서비스제공·이벤트/사은품 발송" 명시(주소 근거).
- 가족검증(등본): 블록1.5 도입, 지금은 children에 가족검증_상태 칸만 예약. 방법=정부24 등본/대행사 부가서비스. 마이데이터 아님(금융위 허가 대상, 우리 급 아님).
- 기존 사용자: 강제 마이그레이션 안 함. 자녀추가·유료전환 등 필요시점에 자연스럽게 부모정보 받기.
- 부분배포 불가: 통짜 완성 후 플래그 ON.

## 3. DB 추가
- guardians(부모) 신설: owner_token 연결, 이름, 휴대폰(+인증여부), 주소, 인증방식, verified_at. 자녀데이터와 분리.
- children에 가족검증_상태 예약.
- identifiers·records·activity_schedules 유지. 공통규칙(add-only·삭제연쇄·검증) 로드맵 그대로.

## 4. 배포·운영 기조
- 웹 배포 = 사장님 "배포해" 전까지 전면 중단. 라이브 동결. 회신·시뮬레이션 통과는 승인 아님.
- 블록1 전체 기능 플래그 OFF. 라이브에 코드 있어도 사용자에게 진입점 안 보임. 로컬만 ON.
- 앞으로 모든 신규기능 = 플래그 OFF로 올리고 로컬 검증 → 사장님 배포+ON 지시 때만 공개.
- 오전 개인정보 버그수정은 유지(되돌리지 않음).
- 최종 오픈 조건: 블록1+회원가입+PC화면+사업자등록(통신판매업) 다 갖춰지면 한 번에.

## 5. 유지되는 v4 결정 (변경 없음)
기록 6종 수동분류 / OCR 제외(1.5) / 시기 자동추정 / 방과후 유효기간 / 이름 identifiers 분리 / deleteChildCascade / 상한(자녀3·기록1000, 무료 자녀1·기록20) / 단일가 3500원 / 자녀별 개학일 전환 / 광고 청정구역 / 게이팅 통합 / 리사이즈+EXIF제거+연번URL+404.
※ 껍데기가 앱형으로 바뀌므로 기능들의 표시 위치·진입 경로는 새 껍데기에 맞게 재배치(기능 자체는 유지).

## 6. 우선순위
1. 데모데이터 세션 심기 수정 → 전략세션 채워진 타임라인·360px 검수(현 껍데기 마지막 확인)
2. 껍데기 재구축 범위 실사 — 코드탭이 layout·라우팅 보고 뜯는/살리는 범위 요청으로 정리
3. 모바일 앱형 껍데기 신규 제작 — 스택 내비, 그 위에 현 5화면 콘텐츠 얹기
4. 디자인 의뢰(클로드 디자인) — 모바일 껍데기·구조 확정 후 1회 (지금 아님)
5. 회원가입 통짜 구현(guardians DB+문자인증+폼+약관/방침)
6. PC 화면(HTS) 설계·제작
7. 앱 껍데기(하이브리드) — 나중

## 7. 사장님 대기 항목
웹배포 최종승인(전체 완성 후) / 사업자정보 기입 / 민감정보 질의 제출여부(저긴급).
