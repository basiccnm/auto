# 에듀싱크 — 전체 로드맵 & DB 마스터 설계

작성: 2026-07-19 | 성격: 12년 서비스의 뼈대 문서. 기능은 블록 단위로 얹되, **데이터 설계는 이 문서가 단일 기준.**
관계: 전략은 우리아이-뒷바라지AI-전략.md, 블록1 구현은 블록1-자녀기록-ClaudeCode-지시서.md. 이 문서는 그 사이의 "전체 지도".

## 0. 4대 원칙 (모든 블록에 적용)

1. **설계는 전체를 미리, 구현은 블록으로.** DB 스키마·형식은 지금 확정, 테이블 생성은 각 블록 시점에.
2. **저장 형식 = 미래 AI 입력 형식.** 블록1이 저장하는 모양 그대로 블록3 리포트·블록4 AI가 읽는다.
3. **각 블록은 출시하는 날 처음 공개.** 미리 보여주면 앵커링(유료화 반발) + 모방 시간 벌어줌.
4. **검증 후 확장.** 블록마다 검증 지표를 정해두고, 반응 확인 후 다음 블록 착수.

## 2. 블록별 정확한 분류

각 블록: **포함 / 제외(어느 블록으로 미뤘나) / 쓰는 데이터 / 선행 조건 / 검증 지표**

### 블록 1 — 자녀기록 (지금 제작)

- **포함:** 자녀 프로필(이름·출생연도(선택)·보호자 동의), 기록 업로드(6종 수동 분류: 상장/통지표/성적표/자격증/활동/기타), 시기 자동추정+수정, 자녀별 타임라인·검색, 학원·활동 스케줄(요일반복+유효기간→시간표 표시), 개인정보처리방침 갱신, "내 아이 데이터 보호" 안내 페이지
- **제외:** OCR 전부(→1.5), 알림·공유·내보내기(→미정), AI 일체(→2·4)
- **데이터:** 개인 DB — children / identifiers / records / schedules
- **선행 조건:** 없음 (블록0 위에 바로)
- **검증 지표:** 자녀 등록률(기존 사용자 중), 업로드 발생률, 스케줄 등록률, 2주 재방문

### 블록 1.5 — 성적 구조화 (fast-follow)

- **포함:** 업로드 시 OCR 자동분류(수동 선택→추천으로 완화), 성적표에서 과목·점수 추출 → grades 테이블
- **제외:** 성적 해석·비교(→3·4)
- **데이터:** grades 생성 (records 파생 — 모든 성적 숫자는 원본 이미지가 근거로 연결됨)
- **선행 조건:** 블록1에서 업로드가 실제로 일어남 + OCR API 원가가 사용자 수 대비 감당 가능
- **검증 지표:** 자동분류 정확도, 성적표 업로드 비중

### 블록 2 — 공용 발달 AI (온램프)

- **포함:** 초등 육아·발달·습관 코치 챗. 공용 지식 DB만 사용, **개인 데이터 접근 없음(격벽)**. AI 행동규율 5개 적용
- **제외:** 개인 기록 기반 답변(→4)
- **데이터:** 공용 지식 DB — knowledge_base 생성
- **선행 조건:** 지식 DB 소스 확정(의학·발달심리 근거 — 다음 액션), 사용량 제한 설계(무료 원가 방어)
- **검증 지표:** 대화 사용률, 재사용률(습관 형성 여부), 세션당 원가

### 블록 3 — 1년 돌아보기 리포트

- **포함:** 1년치 기록·성적·스케줄 기반 연 1회 정산 리포트(궤적 시각화). 정기 생성이라 원가 예측 가능
- **제외:** 수시 대화형 질의(→4)
- **데이터:** reports 생성 (records·grades·schedules 읽음)
- **선행 조건:** 1년치 쌓인 코호트 존재, 유료 실험 시 부모 본인인증·결제 인프라
- **검증 지표:** 리포트 열람률, **유료 실험 시 결제 전환율** ← 이 숫자가 블록4 가격 설계의 근거

### 블록 4 — 개인 대화 AI + 기억 (해자·프리미엄)

- **포함:** 자녀별 전용 AI(해당 child_id 데이터만), 관찰·대화 기억 축적(memories), 연령별 페르소나, 리셋 기능
- **데이터:** memories · chat_state 생성 (개인 DB 전체 읽음)
- **선행 조건:** 데이터 성숙(최소 1~2년치), 부모 본인인증, 구독 결제
- **검증 지표:** 구독 전환·유지율, 주간 대화 빈도

### 블록 5+ — 진학 분석 심화 (미정)

- 중등 이후 궤적 분석·고입/대입 관점. 블록4 성과 보고 설계.

### 상시 트랙 (블록 아님 — 모든 블록에 병행)

- **보안·개인정보:** 방침 갱신, 동의 관리, 접근 통제 점검
- **마케팅:** 각 블록 출시 공지(공개 범위는 전략 문서 12번), 블로그(보유 채널)
- **검증:** 블록별 지표 측정 → 다음 블록 착수 판단

## 3. 유료화 사다리 매핑

- **무료 유지:** 블록0(밑동) · 블록1(수집 시작이 목적) · 블록2(온램프, 사용량 제한으로 원가 방어)
- **첫 유료 실험:** 블록3 리포트 *(후보 — 미결 5-1 참조)*
- **프리미엄 구독:** 블록4 개인 AI (수익화 골든타임 = 중1 학부모)
- **최고 단가:** 블록5+ 진학 분석

## 4. DB 마스터 설계 (12년 전체 — 지금 확정, 생성은 블록별)

### 4.1 두 창고와 절대 규칙

- **자녀별 개인 DB** (child_id 기준) / **공용 지식 DB** (개인정보 없음)
- 절대 규칙 4개 — 어느 블록에서도 위반 금지:
  1. 이름은 identifiers 테이블에만 (기록·로그·분석에 이름 금지)
  2. 공용 AI(블록2)는 개인 DB 접근 불가
  3. 개인 AI(블록4)는 해당 child_id 데이터만 (자녀 간 격벽·집적 불가)
  4. 광고/분석 코드는 개인 DB 전체 접근 불가

### 4.2 테이블 전체 목록 (생성 시점 명시)

**■ 블록1에서 생성 (확정 — 상세는 지시서)**

- children — child_id, owner_token, birth_year(선택), consent_at, 학교·학년·반 연결, created_at
- identifiers — child_id, name (분리 테이블, 여기에만 이름)
- records — record_id, child_id, category(6종), school_year, semester, title, note, image_ref, created_at, updated_at
- schedules — schedule_id, child_id, type, name, days_of_week, start_time/end_time, start_date/end_date

**■ 블록1.5에서 생성 (설계 확정)**

- grades — grade_id, record_id(FK: 원본 근거), child_id, subject, score_type(점수|등급|성취도), value, school_year, semester → 모든 성적 숫자는 원본 이미지에 연결 = AI가 근거 없는 숫자를 말할 수 없는 구조(환각 방지·신뢰의 바닥)

**■ 블록2에서 생성 (설계 확정)**

- knowledge_base — kb_id, age_band(연령대), topic(습관|정서|학습|건강|또래), content, source(근거 출처 필수), created_at
- 공용 AI 대화는 개인 저장 최소화: 세션 단위·익명, 영구 저장 안 함

**■ 블록3에서 생성 (설계 확정)**

- reports — report_id, child_id, period(학년도), content_ref, generated_at

**■ 블록4에서 생성 (설계 확정, 세부는 그때)**

- memories — memory_id, child_id, kind(관찰|대화요약), content, source_ref, created_at — AI가 대화에 끌어쓰는 2겹째 데이터
- chat_state — child_id, 대화 컨텍스트, updated_at — **리셋 시 삭제 대상은 기본적으로 이 테이블만** (records·memories 보존. 기억 포함 리셋 옵션은 미결 5-3)

**■ 유료화 시점에 생성 (설계 확정)**

- guardians — owner_token 연결, 본인인증 결과(최소 정보만), verified_at
- subscriptions — plan, status, 기간, 결제 참조

### 4.3 공통 설계 규칙 (전 테이블)

1. 개인 DB 모든 테이블은 child_id 포함. 모든 조회는 owner_token→child_id 검증 통과 필수.
2. **시기 축 통일:** school_year(초1~고3, 유치원 확장 여지) + semester(1|2). 전 테이블 동일 형식 — 리포트·AI가 12년 궤적을 읽는 공통 축.
3. 삭제 연쇄: 자녀 삭제 = 그 child_id의 전 테이블 + 스토리지 원본까지 즉시 파기.
4. 마이그레이션은 추가만(add-only) 지향. 기존 컬럼의 의미 변경 금지 — 12년 데이터가 깨지지 않는 조건.

3. 블록4 리셋 범위 — 대화만 vs 기억 포함 옵션
4. 블록3 리포트 유료/무료 실험 설계 (가격·대상)
