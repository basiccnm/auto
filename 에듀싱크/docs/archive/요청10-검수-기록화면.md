## 봐줬으면 하는 포인트

### 1. 업로드 흐름 (목업 ②b)
우하단 **＋기록** FAB → 사진 선택(다중 가능) → 시트에서 종류 탭 1번 → 저장.
- 시기는 자동으로 채워집니다(자녀 학년 → 초3, 현재 7월 → 1학기)
- **제목 미리보기**가 종류·시기 바꿀 때마다 갱신되는지
- **실제 폰 사진**으로 해보시면 좋겠습니다 — 아이폰 세로 사진이 눕지 않는지(`imageOrientation:'from-image'` 적용)

### 2. 이미지 품질·용량
- 원본은 긴 변 2000px / JPEG 0.85, 썸네일은 480px / 0.7로 **브라우저에서 리사이즈**한 뒤 올립니다
- 타임라인 3열 그리드에서 썸네일이 충분히 선명한지
- 큰 사진(5MB+) 올렸을 때 리사이즈 후 통과하는지 (서버 상한 4MB)

### 3. 타임라인 (목업 ②)
- 학년·학기 섹션 묶음이 자연스러운지
- 필터 칩 7개가 **360px에서 가로 스크롤**되는지, 칩+검색 줄이 **스크롤 시 상단 고정**되는지
- 썸네일 탭 → 원본이 새 탭에서 열리는지

### 4. 문구
- "종류가 다른 사진은 나눠서 올려주세요"
- 빈 상태: "아직 기록이 없어요 / 상장·통지표·활동 사진을 올려두면 학년별로 정리해 드려요"
- 한도 초과 시(무료 20건): FAB 자물쇠 + "이미 올린 기록은 언제든 보고 지울 수 있어요"

## 이미 검증한 것 (재확인 불필요)

| 항목 | 결과 |
|---|---|
| 업로드 2장 → D1 + R2 저장 | `{"ok":true,"saved":2}` |
| 원본·썸네일 서빙 | 둘 다 200 |
| **타 계정이 남의 기록 조회** | **404** (403 아님 — 존재 자체를 숨김) |
| **타 계정이 남의 기록 삭제** | `not_found` |
| **타 계정이 남의 자녀에 업로드** | `forbidden` |
| 미로그인 접근 | 302 → `/login` |
| 필터(종류별) | 정상 |
| 단건 삭제 → 원본+썸네일 동시 제거 | 삭제 후 404 |
| 공유 FAB 미노출 | 확인 (업로드 FAB와 자리 겹침 방지) |

## 설계 결정 (검수 시 참고)

**이미지 URL이 연번(`/records/2/img`)인 이유** — UUID를 URL에 넣으면 "URL을 아는 사람 = 권한자"라는 잘못된 보안 모델이 생깁니다. 실제 방어는 매 요청 SQL(`owner_token → child_id → record`)이고, `image_key`의 UUID는 R2 경로 추측 방지용일 뿐입니다. 권한 없음은 **404**로 응답해 존재 여부까지 숨깁니다.

**EXIF가 사라집니다** — canvas를 거치며 위치정보가 통째로 제거됩니다. 부작용이 아니라 기능이며, 방침 문서에 명시할 항목입니다(`정책초안.md` 반영 필요).

**쓰기 순서 R2 → D1** — 반대로 하면 타임라인에 영영 안 지워지는 깨진 칸이 남습니다. D1 실패 시 방금 올린 R2 객체를 즉시 보상 삭제합니다.

**다중 업로드는 장별 독립** — 3장 중 2번째가 실패해도 1·3은 저장합니다. 전부 롤백하면 사용자가 사진을 처음부터 다시 골라야 합니다.

## 알려진 미완

- **동의 확인 UI 최종 결선**은 비워둔 상태입니다(사장님 KISA 답 대기). 현재는 체크박스 + `consent_method='checkbox'` 기록까지.

- 기록 메타(제목·시기) 수정 화면 없음 — v4 범위에 있는지 확인 필요.
