## 요약

정책 문구 초안을 쓰다 발견했습니다.
**지시서 v4의 "보호자 동의 체크박스 1개" 설계가 개인정보보호법 요건을 충족하지 못할 가능성이 큽니다.**
그리고 이걸 충족하려면 **"연락처를 일절 받지 않는다"는 서비스 핵심 원칙을 포기해야 하는 구조적 충돌**입니다.

---

## 1. 법 조문 (원문 확보 완료)

**법 제22조의2제1항**
> "개인정보처리자는 만 14세 미만 아동의 개인정보를 처리하기 위하여 이 법에 따른 동의를 받아야 할 때에는 그 법정대리인의 동의를 받아야 하며, **법정대리인이 동의하였는지를 확인하여야 한다.**"

→ **동의를 받는 것**과 **동의했는지 확인하는 것**이 별개 의무입니다.

**시행령 제17조의2제1항 — 확인 방법 7가지 한정 열거**
| # | 방법 | 전제 |
|---|---|---|
| 1 | 사이트에서 동의 표시 + **휴대전화 문자**로 확인 통지 | 전화번호 |
| 2 | 동의 표시 + **신용/직불카드 정보** 제공받기 | 결제수단 |
| 3 | 동의 표시 + **휴대전화 본인인증** | 전화번호 |
| 4 | **서면** 발급·우편·팩스 후 서명날인 제출 | 주소/팩스 |
| 5 | 동의 내용 **전자우편** 발송 → 회신 수신 | 이메일 |
| 6 | **전화**로 고지 후 재차 전화로 동의 | 전화번호 |
| 7 | 1~6에 **준하는 방법** | — |

## 2. 우리 현황

- **지시서 v4 2절 ④ 설계**: 자녀 등록 폼의 **체크박스 1개** — "본인은 보호자이며 자녀 기록의 등록·보관에 동의합니다"
- **서비스 원칙**: 이메일·전화번호를 **일절 수집하지 않음**(방침 제1조, `loginPage` 주석에도 명시). 소셜 로그인도 이름·이메일 미수집.

**충돌**: 체크박스는 *동의 표시*일 뿐 *확인 수단*이 아닙니다. 그런데 시행령의 확인 수단 1~6번이 **전부 연락처 또는 결제수단을 전제**합니다. 7번 "준하는 방법"도 무연락처 상태에서 뭘 쓸 수 있을지 불분명합니다.

**"보호자가 자기 계정으로 입력하니 괜찮지 않나"에 대해**: 아동이 직접 가입하지 않더라도 **처리 대상이 만 14세 미만 아동의 개인정보**인 이상 제22조의2 적용을 벗어난다고 단정하기 어렵습니다. 게다가 이 서비스는 **아동의 이름 + 성적·상장 이미지 원본**을 다룹니다.

## 3. 선택지 (결정 필요)

| 안 | 내용 | 대가 |
|---|---|---|
| **A** | 자녀기록 이용 시에만 **휴대전화 본인인증** 1회(시행령 3호) | 가입 마찰 大 · 인증 비용 발생 |
| **B** | 소셜 로그인에서 **이메일 수집 동의 범위 확대** → 확인 메일 발송(5호/1호 준용) | 무연락처 원칙 포기 · 카카오/네이버 동의항목 추가 |
| **C** | **유료 결제 시 카드정보 확인**(2호) 활용 | 무료 이용자를 못 덮음 |
| **D** | 만 14세 미만 자녀기록 기능을 **본인인증 완료 계정에만** 개방 | 사실상 A |
| **E** | 현행 유지 + 리스크 감수 | **권장하지 않음** — 아동 데이터 + 이미지 원본이라 사고 시 파급이 큼 |

> **코드탭 의견: 판단하지 않겠습니다.** 이건 기술 선택이 아니라 **사업 정체성(무연락처 원칙) vs 법적 리스크**의 문제이고, 제가 조문만 읽고 결론 낼 영역이 아닙니다.
> 다만 사실관계로 두 가지만 덧붙입니다.
> ① **B가 구현 부담이 가장 작습니다** — 소셜 로그인이 이미 붙어 있어 동의항목만 넓히면 됩니다. A는 인증 SDK를 새로 붙여야 합니다.
> ② **지금이 가장 싼 시점입니다.** 자녀 프로필 화면이 아직 0줄이라, 지금 정하면 처음부터 그 구조로 짭니다. 나중에 바꾸면 이미 쌓인 사용자 데이터의 소급 동의 문제가 생깁니다.
>
> **법률 자문이 필요한 항목이라고 봅니다.** 변호사 검토 없이 E로 가는 건 말리겠습니다.

## 4. 함께 결정할 부수 항목 (같은 회신에 묶어주세요)

**Q-a. '기타' 종류로 건강 서류가 올라올 수 있습니다.**
기록 종류 6종에 '기타'가 있어 진단서·보건 서류가 들어오면 **법 제23조 진짜 민감정보(건강)** 가 서버에 들어옵니다. 기술적 차단은 불가능합니다.
→ 제안: 업로드 화면에 "건강·진료 관련 서류는 올리지 말아 주세요" 1줄 + 방침에 동일 취지 명시.

**Q-b. 이용약관이 개정 방침과 정면 모순됩니다.**
- 약관 제3조 "**이름 등 불필요한 개인정보는 수집하지 않습니다**" ← 자녀 이름 수집과 정면 충돌
- 약관 제4조 "유료 이용권은 **자녀 수·기간별로** 판매되며" ← 단일가화(3,500원·자녀3명)로 이미 변경됨
→ 약관도 함께 개정해야 합니다. 개정문을 제가 초안 잡을까요?

**Q-c. 국외 이전 고지를 넣을까요?**
Cloudflare 저장 위치가 국외일 수 있습니다. 이전받는 자·국가·일시·방법·항목·목적·보유기간 고지 항목 추가 여부.

**Q-d. 방침 게시 시점.**
기능보다 방침이 먼저 나가면 **허위 기재**, 나중에 나가면 **무고지 수집**입니다.
→ 제안: 배포 체크리스트에 "방침 교체와 기능 플래그 ON은 같은 배포에" 명시. 다만 통상 중요 변경은 **시행 7일 전 사전 공지**가 권장되는데, 이건 "조용한 배포" 방침과 충돌합니다. 어느 쪽을 우선할까요?
