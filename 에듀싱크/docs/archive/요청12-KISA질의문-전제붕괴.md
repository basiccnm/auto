# 요청12 — 🔴 KISA 질의문의 전제가 무너졌습니다 (긴급)

회신 파일: **`docs/회신12-KISA질의문-정정.md`**
긴급도: **높음** — 사장님이 회신9의 질의문을 **그대로 제출하면 틀린 답을 받습니다.**

---

## 문제

같은 시각에 받은 두 회신이 정면으로 충돌합니다.

**회신9 (KISA 질의문 최종본, 사장님 제출용)**
> "**이메일·전화번호를 일절 수집하지 않으며**, 소셜 로그인을 이용하되 이름·이메일 등 제공 항목에 대한 동의를 받지 않는 최소 수집 방식을 취하고 있습니다."
>
> "(2) … 당사는 이용자 부담 경감을 위해 **연락처를 일절 수집하지 않는 설계를 유지**하고 있습니다. 이 경우 제7호의 '준하는 방법'으로 …"

**회신10-검수 (전략 변경 예고)**
> "사장님이 방향을 틀었다: **연락처 일절 안 받는 원칙 → 회원가입 도입 + 부모 연락처(휴대폰) 수집.**"

→ **질의문의 핵심 전제가 이미 폐기된 정책입니다.**

---

## 왜 급한가

### 1. 사장님이 제출하면 쓸모없는 답이 옵니다
질의 (2)와 (3)은 통째로 **"연락처가 없을 때"**를 묻습니다. 부모 휴대폰을 받기로 했다면 이 질문 자체가 성립하지 않습니다. 관공서 서면 회신은 **몇 주** 걸리는데, 그 답이 도착해도 쓸 수 없습니다.

### 2. 애초에 질의가 거의 불필요해집니다
부모 휴대폰을 수집하면 시행령 제17조의2의 확인 방법이 **바로 열립니다**:

| 호 | 방법 | 휴대폰 수집 시 |
|---|---|---|
| 제1호 | 동의 표시 + **휴대전화 문자로 확인 통지** | ✅ 즉시 가능 |
| 제3호 | 동의 표시 + **휴대전화 본인인증** | ✅ 인증 붙이면 가능 |

즉 **요청3에서 제기한 "무연락처 원칙 vs 법정 확인 의무" 충돌이 사라집니다.** 제1호는 인증 대행사 없이도 문자 발송만으로 충족될 여지가 있어 비용도 낮습니다.

### 3. 지금 구현이 그 전제로 짜여 있습니다
자녀 등록 화면에 **"이름은 받지 않아요"**, 로그인 화면에 **"이름·이메일·전화번호는 받지 않아요"**가 박혀 있습니다. 이미 자녀 이름은 받고 있어 **첫 번째 문구는 지금도 거짓**입니다(회신4 Q1으로 이름 수집이 확정됐는데 이 문구를 못 고쳤습니다 — 제 누락입니다).

## Q1. KISA 질의를 어떻게 할까요?

- **(A) 새 전제로 다시 쓴다** — "부모 휴대폰을 수집하는 구조에서 제1호(문자 통지)로 확인 의무를 충족할 수 있는지" 중심. 질문이 훨씬 좁아지고 답도 명확해집니다
- **(B) 아예 접는다** — 제1호·제3호가 시행령에 명문으로 있어 질의 없이도 근거가 됩니다. 대신 (4) 민감정보 질문만 남겨 별건으로
- **(C) 회신9 그대로 제출** — 무연락처 안이 되살아날 가능성에 대비
- (D) 다른 안

> **코드탭 의견: (A).** 다만 (B)도 진지하게 봐야 합니다. 시행령 제1호가 "동의 표시 + 문자 통지"를 **명문으로** 인정하므로, 부모 휴대폰만 있으면 해석 질의 없이 바로 구현 가능합니다. 질의는 오히려 **(4) 학업 이미지의 민감정보 해당 여부**가 더 실익이 큽니다 — 이건 조문만으론 안 풀립니다.
>
> ⚠️ 제가 판단할 수 없는 지점: 사장님 방향 전환이 **확정**인지 **검토 중**인지 모릅니다. 검토 중이면 (C)로 양쪽 답을 받아두는 게 나을 수도 있습니다.

## Q2. 지금 코드의 거짓 문구를 먼저 고칠까요?

정식 개정 지시 전이라도 **사실과 다른 문구**는 지금 고쳐야 한다고 봅니다.

| 위치 | 현재 문구 | 문제 |
|---|---|---|
| 자녀 등록 화면 | "**이름은 받지 않아요**" | 🔴 **지금도 거짓** — 이름 입력칸이 바로 아래 있습니다 |
| 로그인 화면 | "이름·이메일·전화번호는 받지 않아요" | 방향 전환 시 거짓이 됨 |

- **(A) 자녀 등록 문구만 지금 수정** — 명백한 거짓이라 개정과 무관. 로그인 화면은 정식 지시 대기
- (B) 둘 다 정식 지시까지 대기
- (C) 둘 다 지금 수정

> **코드탭 의견: (A).** 첫 번째는 개정 방향과 무관하게 **이미 틀린 말**입니다. 사용자가 이름을 입력하는 화면에서 "이름은 받지 않아요"라고 쓰여 있으면 신뢰가 깨집니다. 두 번째는 방향이 확정되면 한 번에 고치는 게 낫습니다.

## Q3. 정책초안 검수는 어떻게 됩니까?

`정책초안.md`는 **무연락처 전제**로 썼습니다. 방향이 바뀌면 수집 항목·동의 근거·처리 위탁이 전부 달라집니다.
→ 지금 검수하면 헛일이 될 수 있으니, **개정 방향 확정 후로 미루는 게** 맞는지 확인 부탁드립니다.
