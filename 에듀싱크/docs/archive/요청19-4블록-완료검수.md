# 2. 🔴 진행 중 발견해 고친 것 3건

## ① `/about`이 500이었습니다 — 사용자에게 보이는 페이지가 죽어 있었음

`templates.js:2216`이 `PAY_PRICE[m][1]`로 **자녀 수별 배열처럼** 읽는데, 7/19 단일가화 때 `PAY_PRICE`를 숫자로 바꾸면서 이 표를 안 따라갔습니다.

```js
PAY_PRICE = { 1: 3500, … }     // 숫자
PAY_PRICE[m][1]                // → undefined.toLocaleString() → 500
```

가격표를 단일가 1열로 고쳤습니다. **제 작업과 무관한 기존 버그**지만 사용자에게 노출되는 페이지라 바로 처리했습니다.

## ② 날짜가 하루 어긋나 있었습니다 (KST/UTC)

`api_core.ymdToday()`가 UTC 기준이라 **한국 새벽 0~9시에 날짜가 하루 전**으로 나왔습니다.

```
실측: UTC 2026-07-23 22:36  =  KST 2026-07-24 07:36
```

학교 데이터는 전부 한국 날짜 기준이라 급식·시간표가 하루씩 밀립니다. KST(+9h) 기준으로 고쳤고, `index.js`의 `todayYmd()`와 같은 규칙이 됐습니다.

## ③ 급식 알레르기 정보를 버리고 있었습니다 — **계약 §4.2 개정**

`meals.dishes_parsed`에 알레르기 번호가 **이미 들어 있는데** API가 이름만 내보내고 있었습니다.

```json
// DB 실제 값
[{"name":"근대된장국","allergens":[5,6,18]}, {"name":"아몬드멸치볶음","allergens":[13]}]
```

계약 예시가 문자열 배열이라 그대로 만든 건데, 이대로면 **"자녀 알레르기 하이라이트"를 만들 때 API를 다시 고쳐야** 하고 앱 배포 후엔 버전 호환 문제까지 생깁니다.

> 정본 원칙2 — *"저장 형식 = 미래 입력 형식. 오늘 화면에 맞춰 대충 뽑으면 그 실수를 API 층에서 반복한다."*

**있는 데이터를 버리지 않는 쪽으로 계약을 고쳤습니다.** `dishes`를 `[{name, allergens}]` 객체 배열로. 이름만 필요한 화면은 `d.name`만 읽으면 됩니다.
→ **계약 변경이라 승인이 필요합니다.** 아니라면 되돌리겠습니다.

## ④ `dev-seed`가 `accounts`를 안 만들어 `/me`가 401이었습니다
QA 도구가 `users`만 만들던 시절 코드라 계정 체계와 끊겨 있었습니다. `linkSocialAccount`를 연결해 실제 로그인과 같은 상태가 되게 했습니다.

## 블록1 회원 (13항목 통과)

| 확인 | 결과 |
|---|---|
| 가입 → 토큰 발급 | 201 |
| 로그인 · `/me` · 재인증 | ✅ |
| **refresh 회전** — 쓴 토큰 재사용 | **차단** |
| 인증없음 / 위조토큰 | `AUTH_REQUIRED` / `AUTH_INVALID` |
| 검증실패 항목별 사유 | 7개 필드 |
| 아이디 중복 | `DUPLICATE` |
| 기존 데이터 | users·children **무손실** |

**보안에서 신경 쓴 것**
- **계정 열거 방어** — 없는 아이디로 로그인해도 비번 검증을 그대로 돌립니다. 응답 시간이 달라지면 "그 아이디가 있다"가 샙니다. 실제로 틀린 비번과 없는 아이디가 **같은 응답**입니다.
- **refresh 회전** — 한 번 쓴 refresh는 즉시 폐기. 탈취돼도 무한 재사용이 안 됩니다.
- PBKDF2 10만 회. 해시 문자열에 반복수를 박아둬서 나중에 올려도 옛 비번이 계속 검증됩니다.

# 4. 🔴 통합 시 반드시 처리할 것

## ① 삭제 연쇄가 두 벌이 됐습니다 — 가장 위험

블록5가 순환 import 때문에 `deleteChildCascade`를 **복제**했습니다. `index.js` 원문이 *"삭제 경로는 이 함수 하나만 쓴다"*고 못박은 바로 그 지점입니다.

**자녀에 딸린 테이블이 추가되면 두 곳 모두 고쳐야 합니다.** 한 곳을 빠뜨리면 R2에 아이 사진이 영구히 남습니다.
→ 공용 모듈(`data_children.js`)로 승격해 **단일 진입점을 복원**해야 합니다. `r2KeysOf`·`R2_DERIVED_SUFFIXES`도 같은 문제입니다.

## ② 블록5의 임시 인증을 블록1로 교체
블록5가 병렬로 돌 때 블록1이 아직 없어서 쿠키 폴백으로 만들었습니다. 이제 `auth_core.resolveAuth`가 있으니 교체해야 합니다.

| 대상 | 현재 | 교체 |
|---|---|---|
| `resolveOwner` | 쿠키 폴백 | `resolveAuth` |
| `requireReauth` | **`return null`(통과)** | `apiErr("REAUTH_REQUIRED")` |
| `isSubscriber` | 쿠키 판정 | `orders` 기반 |

**`requireReauth`가 지금 무조건 통과합니다.** 계약 §3.4의 "삭제·수정은 재인증"이 아직 안 걸려 있습니다. 한 줄이면 5개 엔드포인트가 한꺼번에 잠깁니다.

## ③ `AUTH_SECRET` 미설정
지금은 개발용 상수로 떨어지고 콘솔에 경고를 찍습니다. **배포 전 `wrangler secret put AUTH_SECRET` 필수.**

# 5. 확인 요청 5건

1. **급식 `dishes` 객체 배열 개정**(§2-③) — 계약 변경이라 승인 필요
2. **시간표 `timetable_overrides` 병합** — 웹은 반 단위 공개 수정본을 덮어씌우는데 계약 §4.3에 그 얘기가 없어 안 했습니다. **지금 웹과 앱이 다른 과목을 보여줍니다.** 병합할지(코드 8줄)
3. **`total`의 의미** — 블록3+4가 "현재 페이지 건수"로 냈습니다. 계약 §1.2 예시(128 = 전체)와 다릅니다. 전체 COUNT는 12,563행 스캔이 한 번 더 돌아서 그렇게 뒀습니다
4. **기록 정렬** — 커서가 성립하려면 `id DESC`여야 해서 웹 타임라인의 복합 정렬을 못 씁니다. 학년·학기 그룹핑은 앱이 `period`로 하면 됩니다
5. **가격 할인율** — 1개월 1만원은 확정. 3/6/12개월(2.7만·5.1만·9.6만 = 10·15·20% 할인)은 제 작업 기준값입니다
