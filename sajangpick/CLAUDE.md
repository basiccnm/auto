## 역할 3고정 (회신03)
- **웹 Claude = 두뇌.** 판단, 전략, 제품 선정, 대본·기획서 작성
- **코드탭 = 실행.** 구현, 렌더, 자동화, 인프라. 판단이 필요하면 요청NN으로 웹에 묻는다
- **사용자 = 링크 전달 + 최종 승인.** 그 외에는 요청하지 않는다

사용자에게 설정·설치·폴더 정리·토큰 발급·파일 저장을 요청하는 것은 원칙 위배.
필요하다고 판단되면 먼저 요청NN으로 웹에 올려 우회 방법을 논의한다.
(단, "판단 라우팅"의 안전 예외 — 외부 통신·PC 상시 설정·삭제·결제 — 는 유지)

## 협업 구조
- Claude 웹: 제품 선정, 대본, 제목/설명 작성 → inbox/에 기획서 JSON 저장됨
- Claude Code(너): inbox 기획서를 읽고 영상(mp4) + 업로드용 텍스트 산출 → outbox/
- 사용자: 산출물을 유튜브 쇼츠/인스타 릴스/틱톡/네이버 클립에 업로드
- 사용자는 코딩을 직접 하지 않음. 설명은 문법이 아니라 "왜 필요한지" 중심으로.

## 최우선 원칙 — 사용자 개입 최소화
사용자가 하는 일은 **셋뿐**이다.
1. 쿠팡 파트너스 링크를 따서 Claude 웹에 전달
2. 완성된 mp4를 각 플랫폼에 업로드
3. 성과 데이터 전달

그 외 전 과정(이미지 확보·음성·편집·렌더·업로드 텍스트)은 자동화한다.
**사용자에게 파일 저장·폴더 정리·수동 매칭을 요구하는 설계는 채택 금지.**
그 방법밖에 없다고 판단되면 채택 전에 요청NN.md로 웹에 올린다.

## 통신 — PROTOCOL v5 (정본: 드라이브의 `PROTOCOL-v5.md`)
v1~v4와 ANSWER.md 방식은 전부 폐기됐다(`archive/`에 있음). 다시 꺼내 쓰지 말 것.

프로젝트 폴더는 바탕화면에 있고 드라이브 동기화 대상이 아니다.
`G:\내 드라이브\sajangpick\`를 우편함으로 쓴다. **파일마다 쓰는 쪽이 하나뿐이다.**

### 3주체
| 주체 | 살아있는 시간 | 하는 일 |
|---|---|---|
| watcher.mjs | 상시(백그라운드) | 폴더 감시, 알림, 정형 작업 자동 실행. **판단하지 않음** |
| 코드탭 | 호출될 때만 | 판단이 필요한 구현·렌더·디버깅 |
| 웹 Claude | 사용자가 부를 때만 | 전략 판단, 기획서 작성, 회신 |

### 파일명 — 완전 고정. 슬러그 금지
```
요청00.md ~ 요청09.md    코드탭 → 웹
회신00.md ~ 회신09.md    웹 → 코드탭
```
- **주제는 파일 안 첫 줄에 쓴다. 파일명에 절대 넣지 않는다**
- 요청NN의 답은 반드시 회신NN. 번호는 00~09 순환, 활성 최대 20개
- 같은 번호 재사용 전에 이전 쌍을 `archive/`로 (`요청04_20260722.md`)
- 이 형식 외의 파일명은 통신으로 인정하지 않는다

### 쓰기 권한 (서로 상대 파일에 쓰지 않는다. UTF-8 고정)
| 파일 | 쓰는 쪽 | 용도 |
|---|---|---|
| WAKE.md / PENDING.md / WATCHER_HEARTBEAT.md | **watcher** | 깨움 신호·대기 목록·생존 표시 |
| INDEX.md / STATE.md / WORKLOG.md / COMMLOG.md / 요청NN | **코드탭** | 통신 현황·상태·작업기록·통신기록 |
| 회신NN.md | **웹** | 지시·답변 |
| DATA.md | 사용자/코드탭 | 업로드 성과 |

- 코드탭이 드라이브로 올리는 건 `node scripts/sync-drive.mjs` (렌더 시 자동 실행)
- **회신NN.md를 절대 덮어쓰지 말 것** — 드라이브가 사본 `회신00 (1).md`를 만들어 갈라진다

### 재개 절차 (코드탭이 다시 켜졌을 때)
1. `node watcher.mjs --once` → PENDING.md 확인
2. 밀린 회신을 순서대로 처리
3. 처리한 회신마다 `node watcher.mjs --handled 00`
4. INDEX.md · COMMLOG.md · STATE.md 갱신

### watcher 운영
- 상시 실행: `run-watcher.vbs` (창 없이 뜸, 이미 돌고 있으면 중복 실행 안 함)
- 점검: `node watcher.mjs --once` / 생존 확인: `WATCHER_HEARTBEAT.md`
- **watcher가 자동 실행하는 것은 `AUTO_RENDER: 001` 한 가지뿐.**
  회신 안의 자유 문장은 실행하지 않는다 — 해석이 불가능하고, 확인 없이 파일 내용을
  실행하는 구조는 위험하다. 자유 문장 지시는 코드탭에서 사람이 보고 처리한다

그 외 기술 선택·대본 수정·규격 변경·우선순위는 요청NN으로 웹에 보낸다.

**단, 아래는 위 규칙과 무관하게 항상 사용자에게 직접 확인한다** — 되돌리기 어렵거나

- 외부로 나가는 통신(텔레그램 전송, 외부 API 호출, 업로드·게시)
- PC 상시 설정 변경(작업 스케줄러·시작프로그램 등록, 시스템 설정)

## 자율 진행 규칙
- 대본이 규격(20~30초) 초과 → 장면 수를 줄여 자동 축약하고 WORKLOG에 기록
- 제품 이미지 없음 → 텍스트·색배경 렌더 (#F97316 / #1A1A1A / 흰 배경)
- 렌더 실패 → 3회 재시도, 계속 실패하면 다음 기획서로 넘어감
- inbox 비면 → 대기 전환, STATE.md 갱신 후 정지
- 라이브러리·경로·빌드 등 순수 기술 이슈 → 직접 해결. 질문하지 않는다
- 회신이 20분 내 안 오면 → 자율 판단해 진행. 멈추지 않는다

### 작업 규칙

- 처리한 기획서는 inbox/ → done/ 으로 이동
- git은 로컬 커밋만 유지 (원격 push 없음)

## 기술 스택
- Remotion (React 기반 프로그래매틱 영상 렌더링)
- TTS: edge-tts (무료 한국어 보이스) — 추후 교체 가능하게 모듈 분리
- 이미지: 기획서의 coupang_url 상세페이지 이미지를 image_hint에 맞게 사용
- BGM/효과음: 저작권 프리 소스만

## 출력 규격
- 1080x1920 세로(9:16), 30fps, h264 mp4, 20~30초
- 영상 1개당 함께 출력: {video_id}_upload.txt (제목 + 설명 + 해시태그)
- 설명에 반드시 포함: "이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 수수료를 제공받습니다."

## 영상 구조 원칙
1. 첫 3초: 5컷 이상 전환 + 후킹 자막 대형 표시
2. 자막: 흰 배경에 진한 글자(#1A1A1A) + 주황 형광펜.
   화면 하단 20%(384px)는 세이프존이라 자막 금지
3. 구조: 후킹(3초) → 공감(5초) → 제품 시연(10~15초) → CTA
4. TTS 음성 길이에 자막 타이밍 자동 동기화
5. 브랜드 컬러: 주황 `#F97316` / 텍스트 `#1A1A1A` / 흰 배경
6. 대본 길이 기준: 후킹+나레이션+CTA 합계 150자 이내(권장 130자), 장면 5개.
